## 폼 제출과 검증 오류 표시: @ModelAttribute, @Valid, BindingResult (2026-11-23 보강, MockMvc로 확인함)

**참고**: 원본 자료와 출처, 확인 범위는 [부록 92](92_선별근거_원본연결.md)의 이 장 항목을 본다.

**흐름**: 브라우저가 폼을 `POST`로 보내면 Spring이 폼 값을 객체에 채우고(`@ModelAttribute`), 검증 규칙(`@Valid`)을 적용한다. 실패한 항목은 `BindingResult`에 모인다. 컨트롤러는 이 결과를 보고 다시 폼을 보여 주거나 저장한다.

```java
public static class SignupForm {
    @NotBlank(message = "이름을 입력하세요")
    private String name;
    @Min(value = 0, message = "나이는 0 이상이어야 합니다")
    private int age;
    // getter, setter 생략
}

@PostMapping("/signup")
@ResponseBody
public String signup(@Valid @ModelAttribute("form") SignupForm form, BindingResult result, Model model) {
    if (result.hasErrors()) {
        return "invalid: " + result.getFieldErrors().stream()
                .map(e -> e.getField() + "=" + e.getDefaultMessage())
                .sorted()
                .collect(Collectors.joining(", "));
    }
    return "ok: " + form.getName() + " " + form.getAge();
}
```

**실행 결과 (확인함)**

```
bad   -> 200 invalid: age=0 이상이어야 합니다, name=이름을 입력하세요
good  -> 200 ok: kim 30
```

- `name=` 빈 값과 `age=-1`을 보냈더니 두 항목의 메시지가 모두 돌아왔다. 검증 실패 시 `BindingResult`가 항목별 오류를 가졌다.
- 정상 값은 `ok`로 처리됐다.

**설명 시 주의**: 이 예제는 Spring Boot 전체가 아니라 MockMvc standalone 설정으로 확인했다. 검증 엔진(Hibernate Validator)은 EL(표현 언어) 구현이 필요한데, 이 PC에는 EL jar가 없어서 `ParameterMessageInterpolator`로 바꿔 연결했다. Spring Boot 프로젝트에서는 `spring-boot-starter-validation`이 이 설정을 자동으로 맞춘다. 실제 프로젝트에서는 이 연결 코드를 쓰지 않는다.

**흔한 실수**
- `BindingResult`를 `@Valid` 바로 뒤에 두지 않는다: `@Valid` 객체 바로 다음 인자여야 오류가 `BindingResult`에 담긴다. 사이에 다른 인자가 있으면 검증 실패가 예외로 나간다.
- 검증 메시지를 템플릿에서 출력하지 않는다: Thymeleaf에서는 `th:errors`나 `th:field`로 항목별 오류를 화면에 보여 준다(24장).

**면접 기준**: "폼 값은 `@ModelAttribute` 객체에 바인딩되고, `@Valid`로 규칙을 확인합니다. 실패한 항목은 `BindingResult`에 모여서 화면에 다시 보여 줍니다."

### 실제 서버 실행: Maven 빌드와 Spring Boot 4.1.1 (2026-11-24, 확인함)

> 추가 근거: 9_Spring_boot_Basic `04 spring form #2`의 컨트롤러와 템플릿을 Spring Boot 4.1.1 프로젝트로 옮겨 **Maven으로 빌드하고 실제 서버를 띄운 뒤 curl과 PowerShell로 요청했다.** 이전 MockMvc 확인과 달리 내장 Tomcat이 실제로 응답한다. 강의 화면의 브라우저 조작은 하지 않았다.

- **빌드**: `pom.xml`의 부모는 `spring-boot-starter-parent 4.1.1`이고, 의존성은 `starter-webmvc`, `starter-thymeleaf`, `starter-validation`, Lombok이다. Lombok은 `annotationProcessorPaths`에 따로 지정해야 어노테이션 처리가 된다. `mvn package`가 성공하고 `target/form2app-0.0.1-SNAPSHOT.jar`가 생겼다(Maven 3.9.9).
- **실행**: `java -jar target/form2app-0.0.1-SNAPSHOT.jar`로 8088 포트에서 `Started Form2App`까지 확인했다.

**실행 환경 메모 (이 PC에서 필요했던 우회):**
- Windows의 Java에서 내장 Tomcat 기본 NIO 커넥터를 올리면 `Unable to establish loopback connection`으로 시작이 실패했다. JDK의 셀렉터가 루프백 연결을 만들지 못하는 문제로 보인다. 같은 이유로 Gradle도 실패했다. 우회로 Tomcat의 프로토콜을 `Http11Nio2Protocol`로 바꾸는 설정 빈을 넣었다(`factory.setProtocol(...)`). 일반 프로젝트에는 필요 없다.
- WSL에서 실행한 서버는 같은 문제 없이 떴다. 다만 WSL에서 Windows의 `127.0.0.1`로 접속할 수는 없었다.
- Windows `curl`로 한글을 POST하면 서버가 `MalformedInputException`으로 400을 냈다. PowerShell에서 UTF-8 바이트로 보낸 요청은 정상이었다. 요청 본문의 인코딩을 확인하는 것이 먼저다.

**Maven 빌드와 서버 실행은 확인했다. Gradle 빌드는 여전히 미실행이다**([22-3의 Gradle 절](22-3_빌드_Lombok_Gradle.md)).

### 폼 바인딩, 리다이렉트, 검증 오류: 9_ form1·form3 기준 (MockMvc로 확인함, 2026-11-24)

> 추가 근거: 9_Spring_boot_Basic `03 spring form #1`, `05 spring form validation`의 컨트롤러와 `StudentEdit` 모델을 읽고, 같은 코드를 **MockMvc standalone(Spring 7.0.9)**으로 실행했다. 실제 서버에서의 요청 결과는 앞의 "실제 서버 실행" 절에 있다. Thymeleaf 화면 렌더링은 뒤의 "폼 템플릿 렌더링" 단락에서 따로 확인했다.

```java
@GetMapping("edit")
public String edit(Model model) {
    StudentEdit studentEdit = new StudentEdit();
    studentEdit.setName("홍길동");
    model.addAttribute("studentEdit", studentEdit);
    return "student/edit";
}

@PostMapping("edit")
public String edit(Model model, @Valid StudentEdit studentEdit, BindingResult bindingResult) {
    try {
        if (bindingResult.hasErrors()) throw new Exception("저장할 수 없습니다");
        return "redirect:list";
    } catch (Exception ex) {
        bindingResult.reject("", null, ex.getMessage());
        return "student/edit";
    }
}
```

| 요청 | 결과 (확인함) |
|---|---|
| `GET /student/edit` | 200, 뷰 `student/edit`, 모델에 `studentEdit`(이름 `홍길동`)이 들어 있다 |
| `POST` 잘못된 값 (학번 `123`, 이름 빈칸, 학과 0, 성별 `기타`, 학년 0) | 200, 뷰 `student/edit` 그대로, 오류 **8건** (필드 7건 + 전체 1건) |
| `POST` 올바른 값 (학번 9자리, 이름 `홍길동`, 학과 1, 성별 `남자`, 학년 4) | **302**, 리다이렉트 위치 `list` |

**확인한 규칙:**
- 모델 속성 이름은 클래스 이름에서 첫 글자만 소문자로 만든 `studentEdit`다. 검증 결과는 `org.springframework.validation.BindingResult.studentEdit` 키로 모델에 들어간다. 변수 이름 `student`는 상관없다(강의 설명과 같음).
- 빈 이름 하나에 `@NotEmpty`와 `@NotBlank`가 함께 붙어 있어서 오류가 **두 개** 나온다(`비어 있을 수 없습니다`, `공백일 수 없습니다`). 두 애노테이션의 역할이 다르다는 점을 확인한다.
- `@Pattern(regexp = "남자|여자")`에 맞지 않는 `기타`는 `"남자|여자"와 일치해야 합니다`로 막혔다. 메시지를 `message`로 바꾸면 그 문구가 나온다.
- `bindingResult.reject(...)`로 추가한 전체 오류는 필드 오류와 같은 목록에 들어간다.
- `redirect:list`는 MockMvc standalone에서 `list`로 나왔다. 실제 서버에서는 현재 주소(`/student/…`) 기준으로 `/student/list`가 된다. 2026-11-24에 `form2app` 서버(8088)에서 확인했다: `POST /student/edit`(학번·이름 입력)은 302이고 `Location: http://127.0.0.1:8088/student/list`였다(확인함).
- 학번을 빼고 보내면 같은 주소에서 200으로 `학번을 입력하세요` 오류가 나왔다(확인함).

**Student 객체 바인딩 (확인함)**: 요청 파라미터 `studentNo`, `name`은 `setStudentNo`, `setName`으로 채워진다. 객체는 `model`에 자동으로 `student`라는 이름으로 추가된다. 서버 실행에서 `POST` 값이 `Student` 객체에 들어가 `SAVED` 처리되는 흐름을 위 302·200 결과로 확인했다. 입력값을 콘솔에서 직접 본 것은 아니다.

**폼 템플릿 렌더링 (Thymeleaf 3.1.5 + MockMvc, 확인함):** 9_ 04 강의의 `student/edit.html`(`th:object`, `th:field`)을 `ThymeleafViewResolver`로 렌더링했다. 모델 값은 학번 `201914099`, 이름 `홍길동`, 학과 `1`, 성별 `남자`, 휴학 `true`, 학년 `4`다. 결과 HTML의 핵심 부분:

```html
<input type="text" id="studentNo" name="studentNo" value="201914099" />
<option value="1" selected="selected">소프트웨어공학과</option>
<label><input type="radio" value="남자" id="gender1" name="gender" checked="checked" />남자</label>
<label><input type="checkbox" id="absense1" name="absense" value="true" checked="checked" /><input type="hidden" name="_absense" value="on"/>휴학</label>
<input type="number" id="year" name="year" value="4" />
```

강의 화면의 예상 HTML과 값(`selected`, `checked`, `value`)은 같다. 차이는 Spring이 추가하는 `id` 속성과 체크박스의 `_absense` 숨김 필드다. 이 숨김 필드는 체크하지 않은 체크박스를 서버에서 구분하려고 붙는다.

**면접 기준:** "폼 POST는 `@ModelAttribute`처럼 객체에 바인딩하고, `@Valid`와 `BindingResult`로 검증한다. 실패하면 같은 화면을 다시 보여 주고, 성공하면 리다이렉트로 POST 중복 제출을 막는다."

### 폼 검증 애노테이션: null과 빈 문자열은 다르게 처리된다 (9_ 자료 05 기준, Bean Validation 실행 확인)

> 추가 근거: 9_SpringBoot_Basic `05 spring form validation` 강의 자료(17쪽)의 `StudentEdit` 모델을 읽고 보강했다. 아래는 **Hibernate Validator 9.1.3을 직접 실행한 결과**다(2026-11-24). 스프링 웹 폼 화면 전체 흐름은 이 절 위의 MockMvc 예와 별개로 **미실행**이다.

```java
public static class StudentEdit {
    @NotEmpty @NotBlank @Size(min = 8, max = 12) public String studentNo;
    @NotEmpty @NotBlank @Pattern(regexp = "010-[0-9]{3,4}-[0-9]{4}",
                                 message = "휴대폰 번호를 입력하세요 예:010-000-0000") public String phone;
    @NotEmpty @Email public String email;
    @NotEmpty @NotBlank @Pattern(regexp = "남|여", message = "남, 여 중 하나를 입력하세요.") public String sex;
    @Min(value = 1, message = "학과를 선택하세요.") public int departmentId;
}
```

| 입력 | 나온 오류 (확인함) |
|---|---|
| 정상 값 (학번 9자리, 휴대폰 `010-2090-1421`, 메일, 성별 `여`, 학과 1) | 0건 |
| 잘못된 값 (학번 `123`, 이름 공백, 휴대폰 `0101234`, 메일 `not-an-email`, 성별 `기타`, 학과 `0`) | 7건: 학번 크기, 이름 공백, 이름 크기, 휴대폰 형식, 메일 형식, 성별 형식, 학과 최소값 |
| 모든 필드가 `null` (빈 객체) | 10건: `@NotEmpty`·`@NotBlank` 오류와 `@Min` 오류. `@Pattern`·`@Email`·`@Size` 오류는 **없다** |

**핵심 규칙 (확인함):** `@Pattern`, `@Email`, `@Size`는 값이 `null`이면 **통과**한다. 그래서 `null`을 막으려면 `@NotNull`·`@NotBlank`·`@NotEmpty`를 함께 붙인다. 강의 자료가 `@NotEmpty @NotBlank`를 같이 쓰는 이유가 이것이다. 빈 문자열 `""`은 `@NotEmpty`가 막고, 공백 `" "`은 `@NotBlank`가 막는다.

**메시지:** `message`를 생략하면 기본 메시지가 나온다. 한국어 기본 메시지는 설정 언어에 따라 바뀐다(위 실행에서 `공백일 수 없습니다`처럼 나옴).

**주의 (확인함):** Hibernate Validator는 EL 구현이 없으면 기본 메시지 보간에서 실패할 수 있다. 실행에서는 `ParameterMessageInterpolator`를 썼다. 스프링 부트 웹 앱에서는 의존성과 설정으로 자동 처리되므로 이 설정은 독립 실행에서만 필요하다.

**면접 기준:** "검증 애노테이션은 `null`을 통과시키는 것이 많다. 필수 값은 `@NotNull`, `@NotBlank`, `@NotEmpty` 중 하나로 명시하고, 형식은 `@Pattern`·`@Email`로 검사한다."
