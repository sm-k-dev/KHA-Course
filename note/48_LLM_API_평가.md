## 1. LLM API를 쓸 때 알아야 할 것

**정의** — LLM API는 텍스트를 보내면 모델이 텍스트를 돌려주는 서비스다. 응답은 확률로 만들어지므로 같은 입력에도 다른 답이 나올 수 있다.

**핵심 개념**
- **토큰:** 모델이 처리하는 텍스트 단위. 입력과 출력 모두 토큰으로 계산되고, 비용과 속도가 토큰 수에 비례한다.
- **컨텍스트 길이:** 한 번에 넣을 수 있는 토큰의 상한. 넘으면 앞부분을 잘라야 하므로 중요한 내용을 잃을 수 있다.
- **온도(temperature):** 응답의 무작위성. 낮으면 일관되고, 높으면 다양하다. 분류나 추출에는 낮게 둔다.
- **환각(hallucination):** 그럴듯하지만 사실이 아닌 답. 근거를 함께 요구하고 검증해야 한다.

**흔한 오해:** "모델이 말했으니 맞다"는 틀리다. 응답을 검증 가능한 형태로 받고, 평가 데이터로 측정해야 한다.

## 2. 구조화 출력: 응답을 검증하고 거부하기

**정의** — 모델 응답을 자유 텍스트 대신 정해진 모양(JSON 등)으로 받게 하고, 받은 뒤에 그 모양이 맞는지 검사하는 방식이다.

**왜 필요한가** — 백엔드는 응답을 코드로 처리한다. 필드가 빠지거나, 타입이 틀리거나, 범위를 벗어난 값이 오면 시스템이 오동작한다.

**구현 (검증 완료)**

```java
static Optional<String> parseLabel(String json) {
    try {
        JsonNode n = new ObjectMapper().readTree(json);
        if (!n.hasNonNull("label") || !n.get("label").isTextual()) return Optional.empty();
        if (!n.hasNonNull("confidence") || !n.get("confidence").isNumber()) return Optional.empty();
        double c = n.get("confidence").asDouble();
        if (c < 0 || c > 1) return Optional.empty();                  // 범위 검사
        return Optional.of(n.get("label").asText());
    } catch (Exception e) { return Optional.empty(); }                 // 깨진 JSON도 거부
}
```

- **확인:** 올바른 JSON은 통과한다. 필드가 빠진 것, 신뢰도가 1.7인 것, JSON이 깨진 것은 모두 거부된다.
- **원칙:** 검증에 실패하면 재시도하거나 사람에게 넘긴다. 실패한 응답을 그대로 쓰지 않는다.

## 3. 분류 평가: 정밀도, 재현율, F1

**혼동 행렬**

|  | 실제 양성 | 실제 음성 |
|---|---|---|
| 예측 양성 | TP (맞춤) | FP (잘못 잡음) |
| 예측 음성 | FN (놓침) | TN (맞게 통과) |

- **정밀도 (Precision):** 양성이라고 예측한 것 중 진짜 양성 비율 = TP / (TP + FP)
- **재현율 (Recall):** 진짜 양성 중 찾아낸 비율 = TP / (TP + FN)
- **F1:** 정밀도와 재현율의 조화 평균 = 2PR / (P + R). 둘 중 하나가 낮으면 낮게 나온다.

**예 (검증 완료):** TP=8, FP=2, FN=4, TN=6이면 정밀도 0.80, 재현율 0.667, F1 0.727이다.

**언제 무엇을 보나**
- 놓치면 안 되는 경우(사기 탐지, 보안 위협): 재현율을 본다.
- 잘못 잡으면 안 되는 경우(정상 고객 차단): 정밀도를 본다.
- 둘을 함께 보고 싶을 때: F1을 본다.

**흔한 실수:** 정확도(맞힌 비율)만 보면 안 된다. 양성이 1%뿐이면 전부 음성이라고 해도 정확도는 99%가 된다.

## 4. 신뢰구간: 표본이 작으면 불확실하다

**정의** — 측정한 비율이 실제 값 주변 어디에 있을지 범위로 나타낸 것이다. 표본이 작을수록 범위가 넓다.

**예 (검증 완료):** 20개 중 14개를 맞혔다(정확도 0.7). Wilson 95% 신뢰구간은 약 0.481 ~ 0.855다. 범위가 0.3 이상이라서 "70%"라는 숫자만으로 성능이 좋다고 말하기 어렵다.

**실무 규칙:** 평가 데이터가 수십 개뿐이면 개선을 주장하기 전에 표본을 늘린다. 두 버전을 비교할 때 구간이 많이 겹치면 차이가 있다고 말하지 않는다.

**면접 기준:** "정확도 하나보다 정밀도와 재현율을 함께 보고, 표본 크기에 따른 신뢰구간을 같이 제시합니다."

## 6. 기술 통계 기초

- **평균:** 값을 모두 더해 개수로 나눈다. 극단적인 값에 민감하다.
- **중앙값:** 크기순으로 나열했을 때 가운데 값. 짝수 개면 가운데 두 값의 평균. 극단값에 덜 민감하다.
- **분산과 표준편차:** 평균에서 얼마나 흩어져 있는지. 분산은 편차 제곱의 평균, 표준편차는 그 제곱근이다. 표준편차는 원래 단위로 돌아온다.
- **검증 완료:** `{2, 4, 4, 4, 5, 5, 7, 9}`는 평균 5, 모분산 4, 표준편차 2, 중앙값 4.5다.
- **실무:** 응답 시간을 평균만 보면 느린 요청을 놓친다. 중앙값과 p95(상위 5%의 경계)를 함께 본다(43장 메트릭).
- **면접 기준:** "평균은 극단값에 흔들리므로 중앙값과 분산을 함께 보고, 응답 시간은 p95로 봅니다."

## 7. 경사 하강법 (직관)

- **정의:** 함수의 값을 줄이는 방향으로 조금씩 움직여 최솟값을 찾는 방법. 기울기(미분값)의 반대 방향으로 한 걸음씩 간다.
- **식:** `x = x - 학습률 × 기울기`. 학습률이 너무 크면 튀고, 너무 작으면 느리다.
- **검증 완료:** `f(x) = (x-3)²`에서 학습률 0.1로 100번 반복하면 x가 3에 가까워진다(3.0000).
- **연결:** 모델 학습은 손실 함수의 최솟값을 이런 방식으로 찾는다. 세부 수식은 STEM 학습에서 천천히 본다.
