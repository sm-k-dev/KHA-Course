## 1. RAG란

**정의** — RAG(Retrieval-Augmented Generation)는 질문과 관련된 문서를 먼저 검색하고, 그 문서를 근거로 LLM이 답하게 하는 구조다.

**왜 필요한가**
- 모델이 학습하지 않은 최신 정보나 회사 내부 문서를 답할 수 있다.
- 답에 근거 문서를 붙일 수 있다. 환각을 줄이는 데 도움이 된다.
- 모델을 다시 학습하지 않고 문서를 바꾸는 것만으로 답이 바뀐다.

**흐름**
1. 문서를 잘게 나눈다(청킹).
2. 각 조각을 임베딩(숫자 벡터)으로 바꿔 벡터 저장소에 넣는다.
3. 질문을 같은 방식으로 임베딩한다.
4. 질문 벡터와 가까운 문서 조각 k개를 찾는다(검색).
5. 찾은 조각을 프롬프트에 넣어 LLM이 답하게 한다.

---

## 2. 임베딩과 코사인 유사도

**정의** — 임베딩은 텍스트의 의미를 숫자 벡터로 표현한 것이다. 의미가 비슷한 텍스트는 벡터 방향이 비슷하다.

**코사인 유사도** — 두 벡터가 이루는 각도의 코사인 값이다. 방향이 같으면 1, 직각이면 0이다. 벡터 길이가 아니라 방향을 비교하므로 문서 길이에 덜 영향을 받는다.

**구현 (검증 완료)**

```java
static double cosine(double[] a, double[] b) {
    double dot = 0, na = 0, nb = 0;
    for (int i = 0; i < a.length; i++) { dot += a[i] * b[i]; na += a[i] * a[i]; nb += b[i] * b[i]; }
    return dot / (Math.sqrt(na) * Math.sqrt(nb));
}
```

- **확인:** `{2, 0}`과 `{5, 0}`은 방향이 같아서 1이다. `{1, 0}`과 `{0, 1}`은 직각이라서 0이다.

## 3. 권한 필터는 검색 전에

**문제** — 검색은 의미가 가까운 문서를 찾는다. 권한 없는 문서가 가장 가까워도 검색 결과에 들어가면 안 된다.

**원칙** — 권한 필터를 **검색 전에** 적용한다. 점수를 매긴 뒤에 걸러내면, 나중에 빼도 이미 결과 계산에 권한 없는 내용이 쓰였을 수 있다. 프롬프트에 들어간 문서는 사용자에게 노출될 수 있다는 점도 기억한다.

**구현 (검증 완료)**

```java
static List<String> search(List<Doc> docs, double[] q, String userAcl, int k) {
    return docs.stream()
        .filter(d -> d.acl().equals(userAcl))                              // 권한 필터: 검색 대상을 먼저 좁힌다
        .sorted((x, y) -> Double.compare(cosine(q, y.vec()), cosine(q, x.vec())))
        .limit(k).map(Doc::id).toList();
}
```

- **확인:** 권한 없는 문서 S가 질문과 가장 가까워도, 공개 사용자의 결과에는 나오지 않는다.

---

## 4. 검색 품질 평가: recall@k

**정의** — 상위 k개 결과 안에 정답 문서가 얼마나 들어 있는지 비율이다.

**예 (검증 완료):** 정답 문서가 A, B이고 상위 2개가 A, B이면 recall@2는 1.0이다.

**검색과 답변을 나눠서 평가한다** — 답이 틀렸을 때 원인이 검색(정답 문서를 못 찾음)인지 생성(찾았는데 잘못 답함)인지 구분해야 고칠 곳이 보인다.

**흔한 실패 원인**
- 청크가 너무 커서 관련 없는 내용이 섞임, 너무 작아서 문맥이 잘림
- 질문과 문서의 표현이 달라서 임베딩이 가까워지지 않음 (용어 사전이나 하이브리드 검색으로 보완)
- 권한 필터를 빠뜨려서 결과가 줄어듦, 또는 반대로 노출됨

**면접 기준:** "RAG는 검색으로 근거를 찾고 LLM이 그 근거로 답하게 하는 구조입니다. 권한 필터는 검색 전에 걸고, 검색 품질은 recall@k로 따로 평가합니다."

## 5. 실습 과제 (임베딩 API가 있을 때)

1. 사내 문서 10개를 청크로 나누고 임베딩해서 저장한다.
2. 질문 5개에 대해 recall@3을 측정하고, 실패한 질문의 원인을 적는다.
3. 권한이 다른 두 사용자로 같은 질문을 던져 결과가 다른지 확인한다.
