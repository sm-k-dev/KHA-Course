## 학습 전 필수 관문 — undefined · null · 값 · 비동기

> **학습 순서:** 아래 정의를 읽고 → 굵은 용어를 자기 말로 풀고 → 틀린 문장을 반박하고 → 예제를 설명한 다음 → 답안을 가리고 면접처럼 말한다. 비유만 이해한 상태에서는 다음으로 넘어가지 않는다.

### 1. 정확한 정의

`undefined`는 값이 지정되지 않은 상태에 흔히 쓰이는 JavaScript 값이고, `null`은 개발자가 명시적으로 비어 있음을 나타낼 때 쓰는 값이다. 둘 다 `0`이나 빈 배열과 다르다.

### 2. 용어를 구분해야 하는 이유

`async` 함수가 즉시 최종 값을 반환한다는 말은 틀리다. `async` 함수는 Promise를 반환하며 `await`는 해당 비동기 결과를 기다려 이후 실행을 이어간다.

### 3. 새로운 상황에 적용

`async function f(){return 3}`의 `f()` 결과는 숫자 3이 아니라 Promise다. `await f()`의 평가 결과는 3이다.

### 4. 면접 질문과 답변 기준

**질문:** undefined · null · 값 · 비동기의 차이를 정의와 동작을 포함해 설명해 보세요.

**답변 기준:** JavaScript에서 비동기 작업은 Promise로 결과나 실패를 표현할 수 있고, async/await는 이를 순차적인 코드 형태로 다루는 문법입니다.

2. 위의 **틀린 주장**이 왜 틀렸는지 반례를 든다.

4. 답변 기준을 보지 않고 **정의 1문장 → 차이 1문장 → 예시 1문장**으로 말한다.

## 1. 값·참조·스코프

**정의** — 원시 값은 값 자체로 다뤄지고 객체는 참조를 통해 접근한다. 스코프는 식별자를 참조할 수 있는 코드 영역이다.

**목적과 책임** — 데이터 변경의 전파와 변수 가시성을 이해한다.

**구별해야 할 개념 / 흔한 오해** — const는 바인딩 재할당을 금지하지만 객체 내부 변경까지 막지는 않는다.

**실행·처리 흐름** — 선언 → 스코프 결정 → 평가 → 객체 속성 접근·변경

**직접 구현·검증** — 객체를 공유하는 변수 두 개로 변경 결과 확인. 실행 결과를 캡처하거나 테스트 로그로 남기고, 예상과 실제 결과가 다르면 이유를 기록한다.

**면접 질문** — let·const·var와 객체 참조의 차이는?

**30초 답변 연습** — 위 정의를 첫 문장으로 말하고, 목적·구별점·실제 예시 순서로 3~4문장으로 설명한다.

### 깊이 이해하기 — 개념의 경계와 설계 판단

JavaScript 변수는 값을 보유하며 객체를 변수에 대입하면 객체에 대한 참조값이 복사된다. 함수 호출도 값 전달이며 객체 참조값이 전달될 수 있다. `let`·`const`는 블록 스코프를 갖고 `const`는 바인딩 재할당을 막지 객체 내부 변경을 막지는 않는다.

### 직접 읽고 구현하는 독립 예제

```js
const a={count:1}; const b=a; b.count=2;
console.log(a.count); // 2
let x=1; {let x=3; console.log(x)} console.log(x);
```

**코드 읽기 순서:** 입력·전제조건을 확인하고, 어느 객체/계층이 무엇을 담당하는지 표시한 다음, 정상 경로와 실패 경로를 각각 따라간다. 코드 조각은 문맥상 필요한 클래스·import·설정이 생략될 수 있으며, 실행 전 직접 보완한다.

### 실행 검증 체크포인트

출력 순서를 예측하고 참조 공유와 블록 스코프를 구분한다.

### 스스로 작성할 변형 실습

얕은 복사 `{...a}`와 중첩 객체 공유를 비교한다.

### 면접 답변의 기준 문장

> 객체 변수는 참조값을 가질 수 있고 스코프는 이름이 접근 가능한 코드 영역입니다.

**구술 확인:** 위 문장을 외우기보다, 정의와 책임을 구분해 말하고 실제 코드에서 해당 역할을 수행하는 줄을 가리켜 설명한다.


### 정의를 읽고 넘어가지 않기 — 능동 확인

**1차: 정확한 문장 완성.** 다음 문장을 보지 않고 스스로 말한다. *“원시 값은 값 자체로 다뤄지고 객체는 참조를 통해 접근한다. 스코프는 식별자를 참조할 수 있는 코드 영역이다.”* 문장 속 주요 용어를 각각 설명하지 못하면 정의를 외운 것이 아니라 읽은 것이다.

**2차: 경계 구분.** 다음 설명이 어떤 오해를 막는지 자기 말로 설명한다. *“const는 바인딩 재할당을 금지하지만 객체 내부 변경까지 막지는 않는다.”* 반례를 하나 만들어 본다.

**3차: 면접 재현.** *“let·const·var와 객체 참조의 차이는?”*에 대해 **정의 → 왜 필요한가 → 무엇과 다른가 → 코드·상황 하나** 순서로 30~60초 말한다. 답을 읽지 않고 말한 뒤 원문과 대조한다.

## 2. DOM 이벤트·위임

**정의** — DOM 이벤트는 문서에서 발생한 상호작용을 전달하는 메커니즘이며 이벤트 위임은 조상 요소에 리스너를 두어 자식의 이벤트를 처리하는 패턴이다.

**목적과 책임** — 동적으로 추가된 요소의 이벤트도 효율적으로 처리한다.

**구별해야 할 개념 / 흔한 오해** — 이벤트 버블링과 캡처링은 단계가 다르며 모든 이벤트가 같은 방식으로 버블링하지는 않는다.

**실행·처리 흐름** — 이벤트 발생 → 캡처 → 타깃 → 버블링(해당 시) → 리스너

**직접 구현·검증** — 동적으로 추가한 목록 항목을 상위 ul의 클릭 리스너로 삭제. 실행 결과를 캡처하거나 테스트 로그로 남기고, 예상과 실제 결과가 다르면 이유를 기록한다.

## 3. Promise·async/await

**정의** — Promise는 비동기 작업의 최종 완료·실패를 나타내는 객체이고 async/await는 Promise 기반 코드를 동기식 흐름처럼 표현하는 문법이다.

**목적과 책임** — 비동기 결과와 실패를 일관되게 다룬다.

**구별해야 할 개념 / 흔한 오해** — await가 JavaScript 전체 실행을 멈추는 것은 아니다.

**실행·처리 흐름** — 비동기 작업 시작 → Promise 상태 변화 → 마이크로태스크 처리 → 결과 사용

**직접 구현·검증** — fetch 실패·HTTP 404를 각각 처리하고 차이 확인. 실행 결과를 캡처하거나 테스트 로그로 남기고, 예상과 실제 결과가 다르면 이유를 기록한다.

# 핵심 개념을 오해 없이 이해하기 위한 기초 연결

## 필수 기초 연결: undefined, null, 빈 배열, 비동기 결과

`undefined`는 값을 할당하지 않은 변수나 없는 프로퍼티 등에서 나타나고, `null`은 개발자가 의도적으로 비어 있음을 나타낼 때 쓰는 값이다. `[]`는 요소가 0개인 **배열 객체**다. 이 셋은 같지 않다. 또한 `fetch()`의 반환값은 HTTP 응답 객체 자체가 아니라 **Promise**이며, `await`는 Promise가 이행될 때까지 해당 비동기 함수의 진행을 기다린다.

```javascript
const absent = null;
const list = [];
console.log(list.length);            // 0
console.log(absent === null);        // true
console.log(list === null);          // false
async function loadUser(id) {
  const response = await fetch(`/api/users/${id}`);
  if (response.status === 404) return null; // 애플리케이션에서 선택한 계약
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  return await response.json();
}
```

**검증:** `404` 응답과 네트워크 실패를 구별한다. `fetch`는 HTTP 404/500만으로 Promise를 reject하지 않는다. 네트워크 오류 등은 reject될 수 있다. `response.json()`은 JSON 파싱 실패 시 별도로 예외가 발생한다.

### 경계 1. undefined / null / 0 / 빈 배열

**흔한 오해:** “값이 없으면 모두 falsy다”

**정확한 구분:** undefined는 할당되지 않은 값 등, null은 명시적 부재다. 0은 숫자, []는 빈 배열이며 JavaScript에서 []는 truthy다. nullish 병합 ??는 null/undefined에만 기본값을 적용한다.

**코드·명령 해석:**

```text
console.log(Boolean([])); // true
console.log(0 || 10); // 10
console.log(0 ?? 10); // 0
```

**확인 방법:** ||와 ??가 0, 빈 문자열, null에 대해 다른 결과를 내는지 확인한다.

**직접 구현:** 폼 입력의 유효한 숫자 0을 보존하는 기본값 코드를 작성하라.

**면접 점검:** “undefined / null / 0 / 빈 배열”의 각 용어를 각각 정의하고, 위 코드에서 어느 계층·시점·값에 해당하는지 60초 안에 설명해 보자.


### 경계 2. 동기 / 비동기 / Promise / await

**흔한 오해:** “await는 서버를 멈추는 명령이다”

**정확한 구분:** await는 async 함수의 후속 실행을 기다리도록 표현하지만 브라우저 전체 스레드를 동기적으로 막는다는 뜻은 아니다. Promise는 미래의 완료/실패를 나타내는 객체다.

**코드·명령 해석:**

```text
console.log("A");
Promise.resolve().then(() => console.log("C"));
console.log("B"); // A B C
```

**확인 방법:** 동기 로그와 마이크로태스크의 출력 순서를 설명한다.

**직접 구현:** async 함수에서 try/catch로 Promise 거부를 처리하라.

**면접 점검:** “동기 / 비동기 / Promise / await”의 각 용어를 각각 정의하고, 위 코드에서 어느 계층·시점·값에 해당하는지 60초 안에 설명해 보자.


### 경계 3. == / === / 타입 변환

**흔한 오해:** “==와 ===는 언제나 같은 비교다”

**정확한 구분:** ==는 특정 경우 타입 변환을 동반하고 ===는 타입 변환 없이 비교한다. 실무에서는 의도치 않은 변환을 피하기 위해 ===를 우선한다.

**코드·명령 해석:**

```text
console.log(0 == "0"); // true
console.log(0 === "0"); // false
```

**확인 방법:** 숫자 입력 문자열을 Number()로 명시적으로 변환한 뒤 비교한다.

**직접 구현:** NaN과 Number.isNaN의 차이를 실험하라.

**면접 점검:** “== / === / 타입 변환”의 각 용어를 각각 정의하고, 위 코드에서 어느 계층·시점·값에 해당하는지 60초 안에 설명해 보자.

### 정의를 읽고 넘어가지 않기 — 능동 확인

**1차: 정확한 문장 완성.** 다음 문장을 보지 않고 스스로 말한다. *“Promise는 비동기 작업의 최종 완료·실패를 나타내는 객체이고 async/await는 Promise 기반 코드를 동기식 흐름처럼 표현하는 문법이다.”* 문장 속 주요 용어를 각각 설명하지 못하면 정의를 외운 것이 아니라 읽은 것이다.

**2차: 경계 구분.** 다음 설명이 어떤 오해를 막는지 자기 말로 설명한다. *“await가 JavaScript 전체 실행을 멈추는 것은 아니다.”* 반례를 하나 만들어 본다.

**3차: 면접 재현.** *“네트워크 실패와 HTTP 오류를 fetch에서 어떻게 구분하는가?”*에 대해 **정의 → 왜 필요한가 → 무엇과 다른가 → 코드·상황 하나** 순서로 30~60초 말한다. 답을 읽지 않고 말한 뒤 원문과 대조한다.

**완료 기준:** 비유 없이 정의 가능 / 혼동되는 용어 구별 가능 / 처음 보는 예제에 적용 가능. 세 조건 중 하나라도 실패하면 해당 항목만 재학습한다.
