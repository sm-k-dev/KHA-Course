## 학습 전 필수 관문 — 빌드 · 실행 · 배포 · 환경 변수

> **학습 순서:** 아래 정의를 읽고 → 굵은 용어를 자기 말로 풀고 → 틀린 문장을 반박하고 → 예제를 설명한 다음 → 답안을 가리고 면접처럼 말한다. 비유만 이해한 상태에서는 다음으로 넘어가지 않는다.

### 1. 정확한 정의

빌드는 소스와 자원을 실행 가능한 산출물로 만드는 과정이고, 배포는 산출물을 대상 환경에 전달·적용하는 과정이다. 실행은 프로그램 프로세스를 시작하는 것이다.

### 2. 용어를 구분해야 하는 이유

로컬에서 정상 실행됐다는 사실만으로 운영 배포가 성공했다고 말할 수 없다. 환경 변수는 코드와 별도로 설정을 전달하는 한 방법이다.

### 3. 새로운 상황에 적용

로컬에서는 DB 연결이 되는데 서버에서는 안 될 때 DB 주소·자격 증명·네트워크 허용 규칙을 구분한다.

### 4. 면접 질문과 답변 기준

**질문:** 빌드 · 실행 · 배포 · 환경 변수의 차이를 정의와 동작을 포함해 설명해 보세요.

**답변 기준:** 빌드 성공, 실행 성공, 배포 성공은 서로 다른 검증 단계입니다. 환경별 설정과 네트워크 조건을 분리해 확인해야 합니다.

### 5. 정답을 가리고 설명하기

1. 위 정의에서 핵심 명사 세 개를 골라 각각 뜻을 설명한다.

## 1. 컴퓨팅·DB·네트워크

**정의** — 클라우드 컴퓨팅은 필요에 따라 네트워크로 컴퓨팅 자원을 제공받는 모델이다. 서버·DB·네트워크·스토리지 자원은 서로 다른 책임을 갖는다.

**목적과 책임** — 애플리케이션 실행과 데이터 지속성·접근 경로를 구성한다.

**구별해야 할 개념 / 흔한 오해** — 퍼블릭 IP가 있다고 서비스가 안전하게 공개된 것은 아니다.

**실행·처리 흐름** — DNS → 네트워크 규칙 → 서버 → 앱 → DB

**직접 구현·검증** — 서버·DB 연결을 그림으로 그리고 허용 포트 최소화. 실행 결과를 캡처하거나 테스트 로그로 남기고, 예상과 실제 결과가 다르면 이유를 기록한다.

**면접 질문** — 보안 그룹/방화벽은 무엇을 제어하는가?

**30초 답변 연습** — 위 정의를 첫 문장으로 말하고, 목적·구별점·실제 예시 순서로 3~4문장으로 설명한다.

### 깊이 이해하기 — 개념의 경계와 설계 판단

클라우드 컴퓨팅 자원은 애플리케이션 실행 환경, 관리형 DB는 데이터 저장·운영 기능, 네트워크는 서비스 간 통신 경로를 제공한다. 보안 그룹은 네트워크 접근 규칙을 제어하며 애플리케이션 인증을 대신하지 않는다.

### 직접 읽고 구현하는 독립 예제

```text
Browser --HTTPS--> Load Balancer/Server
                         |
                         +--> App --> DB (private network)
```

**코드 읽기 순서:** 입력·전제조건을 확인하고, 어느 객체/계층이 무엇을 담당하는지 표시한 다음, 정상 경로와 실패 경로를 각각 따라간다. 코드 조각은 문맥상 필요한 클래스·import·설정이 생략될 수 있으며, 실행 전 직접 보완한다.

### 실행 검증 체크포인트

서버와 DB의 인바운드 규칙을 구분하고 DB의 공용 접근 필요성을 검토한다.

### 스스로 작성할 변형 실습

서버에 접속되지 않을 때 DNS·포트·방화벽·애플리케이션 로그 순서로 점검한다.

### 면접 답변의 기준 문장

> 컴퓨팅은 실행, DB는 영속 저장, 네트워크는 연결을 담당하며 각 보안 경계가 다릅니다.

**구술 확인:** 위 문장을 외우기보다, 정의와 책임을 구분해 말하고 실제 코드에서 해당 역할을 수행하는 줄을 가리켜 설명한다.


### 정의를 읽고 넘어가지 않기 — 능동 확인

**1차: 정확한 문장 완성.** 다음 문장을 보지 않고 스스로 말한다. *“클라우드 컴퓨팅은 필요에 따라 네트워크로 컴퓨팅 자원을 제공받는 모델이다. 서버·DB·네트워크·스토리지 자원은 서로 다른 책임을 갖는다.”* 문장 속 주요 용어를 각각 설명하지 못하면 정의를 외운 것이 아니라 읽은 것이다.

**2차: 경계 구분.** 다음 설명이 어떤 오해를 막는지 자기 말로 설명한다. *“퍼블릭 IP가 있다고 서비스가 안전하게 공개된 것은 아니다.”* 반례를 하나 만들어 본다.

**3차: 면접 재현.** *“보안 그룹/방화벽은 무엇을 제어하는가?”*에 대해 **정의 → 왜 필요한가 → 무엇과 다른가 → 코드·상황 하나** 순서로 30~60초 말한다. 답을 읽지 않고 말한 뒤 원문과 대조한다.

**완료 기준:** 비유 없이 정의 가능 / 혼동되는 용어 구별 가능 / 처음 보는 예제에 적용 가능. 세 조건 중 하나라도 실패하면 해당 항목만 재학습한다.
## 2. 배포·모니터링·백업

# 핵심 개념을 오해 없이 이해하기 위한 기초 연결

## 필수 기초 연결: 개발 환경과 배포 환경의 경계

로컬에서 DB 접속이 성공했다는 사실은 배포 환경의 네트워크 경로, 보안 그룹, DB 사용자 권한, 환경 변수, TLS 구성이 정상이라는 증거가 아니다. EC2는 컴퓨팅 자원, RDS는 관리형 관계형 DB 서비스, 보안 그룹은 인바운드/아웃바운드 트래픽 규칙을 관리한다. **인증 정보가 맞음**과 **네트워크 접근 가능**은 서로 다른 조건이다.

**점검 순서:** (1) DNS 이름 해석 (2) 대상 호스트·포트 연결 (3) TLS 설정 (4) DB 인증 (5) 스키마·권한 (6) 애플리케이션 쿼리. 실패 로그를 구분하여 기록한다.

**실습:** 실제 클라우드 비용이 들지 않도록 로컬 Docker 또는 테스트 환경에서 DB 포트를 차단한 경우와 비밀번호가 틀린 경우의 오류 메시지를 비교한다. 운영 보안 그룹을 무분별하게 `0.0.0.0/0`으로 열지 않는다.

## 개념 경계 정밀 보강 — 실제 코드에서 헷갈리는 지점

> 이 절은 기존 핵심 설명에 추가한 필수 기초 연결 학습이다. 아래 예제는 설명용 최소 코드로, SQL은 예시 테이블이 필요하고 Java는 import/클래스·실행 환경이 필요할 수 있다.


### 경계 1. 서버 / EC2 / RDS / DB

**흔한 오해:** “EC2가 데이터베이스 그 자체다”

**정확한 구분:** EC2는 가상 서버 컴퓨팅 서비스, RDS는 관리형 관계형 DB 서비스다. EC2에 DB를 직접 설치할 수도 있지만 서비스 역할은 구분해야 한다.

**코드·명령 해석:**

```bash
브라우저 → EC2(Spring Boot) → RDS(MySQL)
```

**확인 방법:** 애플리케이션 포트와 DB 포트를 각각 어디서 열어야 하는지 구분한다.

**직접 구현:** DB를 인터넷 전체에 공개하지 않는 네트워크 구성을 그려라.

**면접 점검:** “서버 / EC2 / RDS / DB”의 각 용어를 각각 정의하고, 위 코드에서 어느 계층·시점·값에 해당하는지 60초 안에 설명해 보자.


### 경계 2. 배포 / 실행 / 운영

**흔한 오해:** “로컬에서 실행되면 배포가 완료된 것이다”

**정확한 구분:** 로컬 실행은 개발 환경 검증이다. 배포는 운영 환경에 산출물을 설치·설정·시작하는 과정이며 운영은 모니터링·백업·복구·보안 등을 포함한다.

**코드·명령 해석:**

```bash
java -jar app.jar --spring.profiles.active=prod
```

**확인 방법:** 환경 변수, 방화벽, DB 접근, 로그, 재시작 정책을 별도 점검한다.

**직접 구현:** 운영 배포 전후 체크리스트를 작성하라.

**면접 점검:** “배포 / 실행 / 운영”의 각 용어를 각각 정의하고, 위 코드에서 어느 계층·시점·값에 해당하는지 60초 안에 설명해 보자.


### 경계 3. 보안 그룹 / 방화벽 / HTTPS

**흔한 오해:** “HTTPS를 쓰면 DB 포트를 공개해도 안전하다”

**정확한 구분:** HTTPS는 전송 구간의 암호화/서버 인증에 기여한다. 보안 그룹은 네트워크 접근 규칙이다. DB 공개 범위와 계정 권한은 별도로 제한해야 한다.

**코드·명령 해석:**

```bash
인바운드: 443 → 웹 공개 / 3306 → 애플리케이션 서버에서만
```

**확인 방법:** 보안 그룹의 인바운드/아웃바운드 규칙을 구분한다.

**직접 구현:** 운영 DB 접속 허용 대상을 최소화하라.

**면접 점검:** “보안 그룹 / 방화벽 / HTTPS”의 각 용어를 각각 정의하고, 위 코드에서 어느 계층·시점·값에 해당하는지 60초 안에 설명해 보자.

**1차: 정확한 문장 완성.** 다음 문장을 보지 않고 스스로 말한다. *“배포는 빌드 결과를 실행 환경에 반영하는 과정이고 모니터링은 상태·성능·오류를 관찰하는 활동이다. 백업은 복구 가능한 데이터 사본을 보존한다.”* 문장 속 주요 용어를 각각 설명하지 못하면 정의를 외운 것이 아니라 읽은 것이다.

**2차: 경계 구분.** 다음 설명이 어떤 오해를 막는지 자기 말로 설명한다. *“서버가 기동했다는 사실만으로 정상 배포가 검증된 것은 아니다.”* 반례를 하나 만들어 본다.

**3차: 면접 재현.** *“운영 배포 후 반드시 검증할 항목은?”*에 대해 **정의 → 왜 필요한가 → 무엇과 다른가 → 코드·상황 하나** 순서로 30~60초 말한다. 답을 읽지 않고 말한 뒤 원문과 대조한다.

**완료 기준:** 비유 없이 정의 가능 / 혼동되는 용어 구별 가능 / 처음 보는 예제에 적용 가능. 세 조건 중 하나라도 실패하면 해당 항목만 재학습한다.
