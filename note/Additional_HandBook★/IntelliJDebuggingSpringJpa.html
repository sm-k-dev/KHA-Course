1. 준비물 & 프로젝트 열기

IntelliJ에서 cafe-debug 프로젝트를 열고 실행 준비를 합니다.

💡 왜 하나요? 디버깅은 "내 컴퓨터에서 직접 실행"할 때 쓰는 도구입니다.
그래서 먼저 프로젝트가 IntelliJ에서 돌아가야 합니다.

준비물 체크리스트

프로젝트 열기

  1. IntelliJ 첫 화면에서 Open을 누릅니다.
  2. cafe-debug 폴더(안에 build.gradle이 있는 폴더)를 고르고 OK.
  3. "Trust Project?" 창이 뜨면 Trust Project를 누릅니다.
  4. 오른쪽 아래 진행 막대(Gradle 동기화)가 끝날 때까지 기다립니다. 처음엔 1~3분 걸릴 수 있습니다.
  5. 왼쪽 Project 창에서 아래 구조가 보이는지 확인합니다.
프로젝트 구조
cafe-debug
├─ build.gradle              ← 빌드 설계도 (Spring Boot 4.0.1, JPA, H2)
├─ README.md                 ← 기대 동작(요구사항) 문서
└─ src/main/java/com/example/cafe
   ├─ CafeApplication.java   ← main() 시작점
   ├─ CafeRunner.java        ← 오늘의 주문 시나리오 실행
   ├─ OrderService.java      ← 주문·정산 로직 (버그 ②③)
   ├─ Product.java           ← 상품 엔티티 (버그 ①)
   ├─ CafeOrder.java         ← 주문 기록 엔티티
   ├─ ProductRepository.java
   └─ CafeOrderRepository.java
⚠️ 막히면: "Cannot find a Java installation… languageVersion=25" JDK 25가 없거나 IntelliJ가 못 찾는 경우입니다.
File → Project Structure → Project → SDK에서 25를 고르세요.
없으면 같은 목록의 Download JDK…로 버전 25를 받습니다.
그다음 Settings → Build Tools → Gradle → Gradle JVM도 25로 맞춥니다.
⚠️ 막히면: 콘솔 한글이 깨져 보일 때 (터미널에서 실행한 경우) IntelliJ 실행 창에서는 보통 정상입니다. PowerShell에서 직접 실행했다면 먼저 아래를 입력하세요. 
chcp 65001

2. 디버그 모드가 필요한 이유

버그 없는 코드는 없습니다. 중요한 건 빨리 찾는 방법입니다.

💡 println 디버깅 vs 디버그 모드 System.out.println을 곳곳에 넣고 콘솔을 뒤질 수도 있습니다.
하지만 넣고, 다시 실행하고, 지우는 일을 반복해야 합니다.
디버그 모드는 코드를 고치지 않고 원하는 줄에서 시간을 멈춥니다.
🎬 비유로 이해하기 디버그 모드 = 영상 편집기의 일시정지 + 한 프레임씩 넘기기입니다.
멈춘 장면에서 등장인물(변수)의 상태를 하나하나 들여다볼 수 있습니다.
println은 영상이 끝난 뒤 남은 메모 쪽지만 읽는 것과 같습니다.
println 디버깅디버그 모드
코드 수정필요 (넣고 지우기)불필요
보이는 정보내가 찍은 값만그 순간의 모든 변수
실행 흐름못 멈춤한 줄씩 진행·메서드 안으로 들어가기
값 바꿔 보기불가실행 중에 바로 가능

🧠 퀴즈 1

디버그 모드의 가장 큰 장점은 무엇일까요?

정답은 2번입니다. 디버거는 버그를 고쳐 주지 않습니다. 대신 "그 순간의 상태"를 보여 줘서 원인을 찾게 돕습니다. 오히려 실행은 조금 느려집니다.

3. 약간의 이론: 중단점과 단축키

약속합니다, 이론은 이 장이 전부입니다. 😄

💡 중단점(Breakpoint)이란? "여기서 멈춰!"라고 꽂아 두는 빨간 깃발입니다.
디버그 모드로 실행하면 그 줄을 실행하기 직전에 멈춥니다.

중단점 거는 법

  1. 코드 왼쪽의 줄 번호 칸을 마우스로 한 번 클릭합니다. 빨간 점 ●이 생깁니다.
  2. 또는 원하는 줄에 커서를 두고 Ctrl+F8을 누릅니다.
  3. 지울 때도 같은 동작을 한 번 더 하면 됩니다.

중단점 4종류

종류모양어디에 거나요?언제 멈추나요?
줄(Line)🔴 빨간 원코드 한 줄그 줄 실행 직전
메서드(Method)🔶 빨간 마름모메서드 선언 줄메서드에 들어갈 때·나올 때
필드 감시점(Field Watchpoint)👁 빨간 눈필드 선언 줄 (예: private int stock;)그 필드를 읽거나 바꿀 때
예외(Exception)⚡ 번개중단점 목록 창에서 추가지정한 예외가 던져지는 순간
⚠️ 메서드 중단점은 느립니다 메서드 중단점은 프로그램을 눈에 띄게 느리게 만들 수 있습니다. 가능하면 메서드 안 첫 줄에 줄 중단점을 거세요.

중단점 목록 보기 · 한꺼번에 끄기

  • Ctrl+Shift+F8 → Breakpoints 창 (모든 중단점 목록)
  • 디버그 창의 Mute Breakpoints(빨간 점에 사선 아이콘) → 전부 잠시 끄기

꼭 외울 단축키 (Windows 기준)

🧠 퀴즈 2

5. 버그 ① 예외 중단점으로 "터지기 직전"에 멈추기

예외가 던져지는 그 순간에 시간을 멈추고 변수를 봅니다.

💡 왜 예외 중단점인가요? 어디서 터질지 모를 때, 줄마다 중단점을 걸 수는 없습니다.
예외 중단점은 "이 예외가 나면 어디서든 멈춰!"라는 화재 감지기입니다.

5-1. 예외 중단점 추가

  1. Ctrl+Shift+F8로 Breakpoints 창을 엽니다.
  2. 왼쪽 위 + → Java Exception Breakpoints를 고릅니다.
  3. 검색칸에 아래 이름을 붙여넣고 목록에서 고른 뒤 OK. 
    IllegalStateException
  4. 오른쪽 설정에서 Class filters를 체크하고 아래를 입력합니다. (우리 코드에서 난 예외만 잡기) 
    com.example.cafe.*
  5. Done을 누릅니다.
⚠️ 막히면: 스프링 내부 코드(모르는 파일)에서 자꾸 멈춰요 스프링·하이버네이트도 내부에서 IllegalStateException을 던졌다가 스스로 처리합니다.

6. 버그 ② 재고가 DB에 저장되지 않아요 (JPA)

10잔 중 3잔을 팔았는데 재고가 그대로 10입니다. 한 줄씩 따라가 봅니다.

💡 이번에 배우는 기능 조건부 중단점, F8 한 줄씩 실행, Evaluate Expression(Alt+F8)으로 DB 값 직접 확인하기.
📒 용어 비유: 엔티티 · 영속성 컨텍스트 · 트랜잭션 엔티티(Product) = DB 표 한 줄을 옮겨 적은 메모지입니다.
영속성 컨텍스트 = 메모지를 관리하는 담당 직원입니다.
트랜잭션 = 직원의 근무 시간입니다. 퇴근(커밋) 때 메모지가 바뀌었으면 DB 장부에 옮겨 적습니다. 이것을 변경 감지(dirty checking)라고 합니다.
근무 시간이 이미 끝났다면? 메모지를 고쳐도 아무도 장부에 옮겨 주지 않습니다.

6-1. 조건부 중단점 걸기

카페라떼 6잔 주문(세 번째 주문)에서만 멈추게 하겠습니다.

  1. OrderService.java를 열고 int sold = product.sell(requested); 줄(22줄) 번호 칸을 클릭합니다.
  2. 생긴 빨간 점을 마우스 오른쪽 클릭합니다.
  3. Condition 칸에 아래를 붙여넣고 Done. 
    requested == 6
  4. Ctrl+Shift+F8에서 5장의 IllegalStateException 중단점은 체크를 꺼 둡니다.

package com.example.cafe;

import jakarta.persistence.Entity;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;

@Entity
public class Product {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    private String name;
    private int price;
    private int stock;

    protected Product() {
    }

    public Product(String name, int price, int stock) {
        this.name = name;
        this.price = price;
        this.stock = stock;
    }

    /**
     * 손님이 requested 개를 주문하면 재고를 줄입니다.
     * README 규칙 1: 재고가 모자라면 남은 재고만큼만 팝니다.
     *
     * @return 실제로 판매한 개수
     */
    public int sell(int requested) {
        int sold = requested;
        stock -= sold;
        if (stock < 0) {
            throw new IllegalStateException("[" + name + "] 재고는 음수가 될 수 없습니다. stock=" + stock);
        }
        return sold;
    }

    public Long getId() { return id; }
    public String getName() { return name; }
    public int getPrice() { return price; }
    public int getStock() { return stock; }
}

OrderService.java 
package com.example.cafe;

import java.util.List;

import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

@Service
public class OrderService {

    private final ProductRepository productRepository;
    private final CafeOrderRepository orderRepository;

    public OrderService(ProductRepository productRepository, CafeOrderRepository orderRepository) {
        this.productRepository = productRepository;
        this.orderRepository = orderRepository;
    }

    /** 주문을 받고, 판매한 만큼 재고를 줄이고, 주문 기록을 저장합니다. */
    public CafeOrder order(Long productId, int requested) {
        Product product = productRepository.findById(productId).orElseThrow();
        int sold = product.sell(requested);
        CafeOrder order = new CafeOrder(product.getName(), sold, sold * product.getPrice());
        return orderRepository.save(order);
    }

    /** 지금까지 저장된 모든 주문의 금액을 더합니다. */
    @Transactional(readOnly = true)
    public int totalSales() {
        List<CafeOrder> orders = orderRepository.findAll();
        int total = 0;
        for (int i = 1; i < orders.size(); i++) {
            total += orders.get(i).getAmount();
        }
        return total;
    }
}
