## 학습 전 필수 관문 — HTTP 요청 · 응답 · 상태 코드

> **학습 순서:** 아래 정의를 읽고 → 굵은 용어를 자기 말로 풀고 → 틀린 문장을 반박하고 → 예제를 설명한 다음 → 답안을 가리고 면접처럼 말한다. 비유만 이해한 상태에서는 다음으로 넘어가지 않는다.

### 1. 정확한 정의

HTTP 요청은 메서드·대상·헤더·본문 등을 통해 의도를 전달하고, 응답은 상태 코드·헤더·본문으로 결과를 표현한다. **상태 코드**와 **응답 본문에 적힌 비즈니스 코드**는 다르다.

### 2. 용어를 구분해야 하는 이유

HTTP 404는 자원이 없음을 나타내는 응답 정책이다. DB에서 0행이 나왔다고 자동으로 404가 전송되는 것은 아니다.

### 3. 새로운 상황에 적용

GET /users/99에서 조회 결과가 없다면 컨트롤러가 404를 선택할 수 있지만, 목록 GET /users는 보통 200과 빈 배열을 반환할 수 있다.

### 4. 면접 질문과 답변 기준

**질문:** HTTP 요청 · 응답 · 상태 코드의 차이를 정의와 동작을 포함해 설명해 보세요.

**답변 기준:** HTTP는 요청과 응답 메시지의 의미를 규정하는 프로토콜입니다. 서버는 처리 결과에 맞는 상태 코드와 표현 본문을 선택합니다.

### 5. 정답을 가리고 설명하기

1. 위 정의에서 핵심 명사 세 개를 골라 각각 뜻을 설명한다.
2. 위의 **틀린 주장**이 왜 틀렸는지 반례를 든다.
3. 위 상황의 **실행 결과·처리 주체·변경되는 값**을 분리해 설명한다.
4. 답변 기준을 보지 않고 **정의 1문장 → 차이 1문장 → 예시 1문장**으로 말한다.
5. 다음 날 같은 질문에 답하지 못하면 예제가 아니라 **정의**부터 다시 확인한다.

## 1. HTTP 요청·응답

**정의** — HTTP는 클라이언트와 서버가 요청·응답 메시지를 교환하기 위한 애플리케이션 계층 프로토콜이다.

**목적과 책임** — 메서드·경로·헤더·본문과 상태 코드로 통신 의미를 전달한다.

**구별해야 할 개념 / 흔한 오해** — HTTP가 무상태라는 말은 서버가 어떤 상태도 저장할 수 없다는 뜻이 아니다.

**실행·처리 흐름** — 브라우저 요청 → 서버 처리 → 상태 코드·헤더·본문 응답

**직접 구현·검증** — 브라우저 개발자 도구에서 요청 헤더·상태 코드·응답 확인. 실행 결과를 캡처하거나 테스트 로그로 남기고, 예상과 실제 결과가 다르면 이유를 기록한다.

**면접 질문** — GET과 POST의 의미, 멱등성은 어떻게 다른가?

**30초 답변 연습** — 위 정의를 첫 문장으로 말하고, 목적·구별점·실제 예시 순서로 3~4문장으로 설명한다.

### 깊이 이해하기 — 개념의 경계와 설계 판단

HTTP는 클라이언트와 서버가 메시지로 요청·응답을 교환하는 응용 계층 프로토콜이다. 메서드는 요청 의도를, 상태 코드는 처리 결과 범주를, 헤더는 메타데이터를 전달한다. HTTP 무상태성은 서버가 세션을 절대 유지할 수 없다는 뜻이 아니다.

### 직접 읽고 구현하는 독립 예제

```http
GET /api/books/7 HTTP/1.1
Host: example.test
Accept: application/json

HTTP/1.1 200 OK
Content-Type: application/json

{"id":7,"title":"Java"}
```

**코드 읽기 순서:** 입력·전제조건을 확인하고, 어느 객체/계층이 무엇을 담당하는지 표시한 다음, 정상 경로와 실패 경로를 각각 따라간다. 코드 조각은 문맥상 필요한 클래스·import·설정이 생략될 수 있으며, 실행 전 직접 보완한다.

### 실행 검증 체크포인트

개발자 도구 Network에서 메서드·상태·헤더·본문을 각각 식별한다.

### 스스로 작성할 변형 실습

GET과 POST의 의미 및 멱등성 차이를 설명한다.

### 면접 답변의 기준 문장

> HTTP는 요청·응답 메시지의 형식과 의미를 규정하는 프로토콜입니다.

**구술 확인:** 위 문장을 외우기보다, 정의와 책임을 구분해 말하고 실제 코드에서 해당 역할을 수행하는 줄을 가리켜 설명한다.


### 정의를 읽고 넘어가지 않기 — 능동 확인

**1차: 정확한 문장 완성.** 다음 문장을 보지 않고 스스로 말한다. *“HTTP는 클라이언트와 서버가 요청·응답 메시지를 교환하기 위한 애플리케이션 계층 프로토콜이다.”* 문장 속 주요 용어를 각각 설명하지 못하면 정의를 외운 것이 아니라 읽은 것이다.

**2차: 경계 구분.** 다음 설명이 어떤 오해를 막는지 자기 말로 설명한다. *“HTTP가 무상태라는 말은 서버가 어떤 상태도 저장할 수 없다는 뜻이 아니다.”* 반례를 하나 만들어 본다.

**3차: 면접 재현.** *“GET과 POST의 의미, 멱등성은 어떻게 다른가?”*에 대해 **정의 → 왜 필요한가 → 무엇과 다른가 → 코드·상황 하나** 순서로 30~60초 말한다. 답을 읽지 않고 말한 뒤 원문과 대조한다.

## 2. HTML·DOM

**정의** — HTML은 웹 문서의 구조와 의미를 기술하는 마크업 언어이고 DOM은 문서를 객체 트리로 표현하는 인터페이스다.

**목적과 책임** — HTML은 의미 구조를 표현하고 DOM은 스크립트가 문서를 탐색·변경하도록 한다.

**구별해야 할 개념 / 흔한 오해** — HTML 소스 문자열과 런타임 DOM 트리는 일치하지 않을 수 있다.

**실행·처리 흐름** — HTML 파싱 → DOM 구성 → 스타일 계산·레이아웃 → 렌더링

**직접 구현·검증** — 시맨틱 form과 label을 만들고 개발자 도구에서 DOM 확인. 실행 결과를 캡처하거나 테스트 로그로 남기고, 예상과 실제 결과가 다르면 이유를 기록한다.

# 핵심 개념을 오해 없이 이해하기 위한 기초 연결

## 필수 기초 연결: URL, 메서드, 상태 코드, 응답 본문

브라우저가 `/users/99`에 GET을 보내면 서버는 요청을 해석하고 처리 결과를 HTTP 응답으로 만든다. **HTTP 404**는 요청한 리소스를 찾지 못했음을 나타내는 응답 상태이고, **SQL 0행**은 DB 조회 결과의 형태다. 서버가 0행을 확인하고 404를 선택할 수 있지만, DB가 직접 404를 반환하는 것은 아니다. 목록 API `/users`는 결과가 없을 때 보통 `200 OK`와 `[]`를 반환한다.

```http
GET /users/99 HTTP/1.1
Host: example.test

HTTP/1.1 404 Not Found
Content-Type: application/json

{"code":"USER_NOT_FOUND"}
```

**검증:** 단건 조회 실패와 목록 조회 0건을 구분해 각각 상태 코드와 응답 JSON을 설계한다. `404`와 `500`의 의미를 바꿔 사용하지 않는다. HTML의 `<form method="get">`과 `<form method="post">`가 URL·본문·의도에 어떤 차이를 만드는지도 브라우저 개발자 도구에서 확인한다.

## 개념 경계 정밀 보강 — 실제 코드에서 헷갈리는 지점

> 이 절은 기존 핵심 설명에 추가한 필수 기초 연결 학습이다. 아래 예제는 설명용 최소 코드로, SQL은 예시 테이블이 필요하고 Java는 import/클래스·실행 환경이 필요할 수 있다.


### 경계 1. URL / URI / HTTP 메서드

**흔한 오해:** “URL과 GET은 같은 종류의 개념이다”

**정확한 구분:** URI는 자원을 식별하는 식별자 개념이고 URL은 위치를 나타내는 URI의 한 형태다. GET/POST는 HTTP 요청의 메서드로 자원 식별자와 역할이 다르다.

**코드·명령 해석:**

```text
GET /users/3 HTTP/1.1
Host: example.test
```

**확인 방법:** /users/3은 경로, GET은 메서드, Host는 헤더라는 점을 구분한다.

**직접 구현:** 같은 경로에 GET과 DELETE를 보내면 서버 동작을 어떻게 다르게 설계할지 적어라.

**면접 점검:** “URL / URI / HTTP 메서드”의 각 용어를 각각 정의하고, 위 코드에서 어느 계층·시점·값에 해당하는지 60초 안에 설명해 보자.


### 경계 2. HTML form / HTTP 요청 / 서버 처리

**흔한 오해:** “form 태그가 DB에 직접 저장한다”

**정확한 구분:** HTML form은 사용자 입력을 수집해 HTTP 요청을 구성한다. DB 변경은 서버의 컨트롤러·서비스·저장소가 처리한다.

**코드·명령 해석:**

```text
<form action="/users" method="post"><input name="name"><button>등록</button></form>
```

**확인 방법:** 브라우저 개발자 도구에서 요청 메서드, URL, form 필드가 전송되는지 확인한다.

**직접 구현:** 필드 이름 name을 username으로 바꾸면 서버 파라미터 매핑이 어떻게 바뀌는지 설명하라.

**면접 점검:** “HTML form / HTTP 요청 / 서버 처리”의 각 용어를 각각 정의하고, 위 코드에서 어느 계층·시점·값에 해당하는지 60초 안에 설명해 보자.


### 경계 3. 상태 코드 / 응답 본문

**흔한 오해:** “HTTP 404는 DB가 자동으로 반환한다”

**정확한 구분:** 404는 서버가 요청 대상 리소스를 찾지 못했다는 HTTP 응답 의미다. DB 0행을 404로 변환할지는 웹 애플리케이션 정책이며, 200 빈 배열도 상황에 따라 타당하다.

**코드·명령 해석:**

```text
GET /users/999 → HTTP/1.1 404 Not Found
GET /users?name=x → HTTP/1.1 200 OK

[]
```

**확인 방법:** 단건 조회와 목록 조회에서 부재를 각각 어떻게 표현할지 설명한다.

**직접 구현:** POST 성공 시 200과 201 중 어떤 것이 적절한지 판단하라.

**면접 점검:** “상태 코드 / 응답 본문”의 각 용어를 각각 정의하고, 위 코드에서 어느 계층·시점·값에 해당하는지 60초 안에 설명해 보자.

### 정의를 읽고 넘어가지 않기 — 능동 확인

**1차: 정확한 문장 완성.** 다음 문장을 보지 않고 스스로 말한다. *“폼은 사용자의 입력을 이름-값 형태로 수집·제출하는 문서 구조이며 검증은 입력이 규칙에 맞는지 확인하는 과정이다.”* 문장 속 주요 용어를 각각 설명하지 못하면 정의를 외운 것이 아니라 읽은 것이다.

**2차: 경계 구분.** 다음 설명이 어떤 오해를 막는지 자기 말로 설명한다. *“클라이언트 검증만으로 서버 입력을 신뢰할 수 없다.”* 반례를 하나 만들어 본다.

**3차: 면접 재현.** *“서버에서도 입력 검증을 반드시 해야 하는 이유는?”*에 대해 **정의 → 왜 필요한가 → 무엇과 다른가 → 코드·상황 하나** 순서로 30~60초 말한다. 답을 읽지 않고 말한 뒤 원문과 대조한다.

**완료 기준:** 비유 없이 정의 가능 / 혼동되는 용어 구별 가능 / 처음 보는 예제에 적용 가능. 세 조건 중 하나라도 실패하면 해당 항목만 재학습한다.
