이 표는 **학습 완료 표시용**이며, 교재가 읽혔다는 이유로 자동 통과하지 않는다.

| 점검 항목 | 통과 기준 | 결과 |
|---|---|---|
| 정의 | 핵심 용어를 30초 안에 정확한 용어로 설명 | ☐ |
| 역할 | 담당하는 일과 담당하지 않는 일을 설명 | ☐ |
| 관계 | 인접 개념과 차이 1개 이상 설명 | ☐ |
| 흐름 | 요청·데이터·호출 흐름을 그림으로 재현 | ☐ |

| 검증 | 정상·예외 케이스와 실행 로그 제시 | ☐ |
| 응용 | 요구사항 하나를 바꿔 코드 개선 | ☐ |

## 답변 템플릿

> **정의:** X는 무엇이다. **목적:** Y 문제를 해결한다. **책임:** Z를 담당한다. **비교:** A와 달리 B는 ... **예:** 내가 작성한 코드에서는 ...

정의가 불명확할 때 예제부터 암기하지 않는다. 반대로 정의만 외우고 코드를 작성하지 않은 상태도 학습 완료로 표시하지 않는다.

## 기술면접에서 당황하기 쉬운 질문과 응용법 (2026-11-24 추가)

이 절의 질문은 정답 문장을 외우는 용도가 아닙니다. 면접관은 **정해진 답이 없는 상황에서 어떤 순서로 생각하는지**를 봅니다. 아래 답변 틀은 말하는 순서의 예시이고, 내용은 각 장에서 직접 확인한 범위만 근거로 씁니다. 근거 장에 적힌 "미실행" 표시도 그대로 따르세요. 실행하지 않은 것을 실행한 것처럼 말하면 그 자체가 면접 감점입니다.

**공통 답변 순서**: 재현 또는 상황 확인 → 원인 후보 분류 → 가설 하나씩 검증 → 수정 → 재발 방지. 이 순서를 지키면 모르는 질문에서도 말을 이어갈 수 있습니다.

---

**Q1. 리눅스에서 시스템을 실행했는데 오류가 났습니다. 어떻게 하시겠습니까?**
- **면접관이 보는 것**: 명령어 목록이 아니라 문제를 좁혀 가는 순서.
- **답변 틀**: 언제부터 어떤 요청에서 실패하는지 확인 → 로그의 **처음** 오류 줄 확인 → 프로세스와 포트 상태(`ps`, `ss -tlnp`) → 원인을 하나씩 검증 → 수정 후 같은 명령으로 재확인.
- **근거**: [43장 5절](43_Linux.md). 포트 충돌과 권한 오류는 이 PC의 WSL에서 재현해 해결까지 확인함.
- **함정**: 마지막 오류 줄만 보고 결론 내리기. 여러 설정을 한꺼번에 바꾸기.
- **연습**: 같은 질문에 60초로 답하고, 틀을 벗어난 부분을 표시한다.

**Q2. 운영 중인 서비스 응답이 갑자기 느려졌습니다. 어디부터 보시겠습니까?**
- **면접관이 보는 것**: 병목을 어떤 지표로 나눠 보는지.
- **답변 틀**: 최근 배포나 트래픽 변화 확인 → 느린 구간 나누기(웹 서버, 애플리케이션, DB 커넥션, 외부 호출) → 커넥션 풀 대기와 쿼리 수 확인 → 관측 도구(로그, 지표)로 재확인.
- **근거**: [07장 커넥션 풀 고갈 실험](07_RDBMS.md)(MySQL에서 확인함), [46장 관측성](46_관측성_CICD_데이터파이프라인.md), [38장 부하 테스트](38_부하_테스트.md).
- **함정**: "서버를 늘리면 된다"부터 말하기. 원인 확인 없이 확장하는 것은 답이 아닙니다.

**Q3. 같은 요청이 두 번 들어와서 결제가 두 번 됐습니다. 어떻게 막으시겠습니까?**
- **면접관이 보는 것**: 중복 요청과 동시성을 DB 수준에서 막을 수 있는지.
- **답변 틀**: 중복 요청의 원인 구분(사용자 재클릭, 재시도, 두 서버 동시 처리) → DB에서 막는 방법(유니크 제약, 조건부 UPDATE로 한 문장 처리) → 애플리케이션 방어(요청 식별자)는 보조로 말하기.
- **근거**: [33장 동시성](33_동시성_심화.md)(같은 조건에서 SELECT 후 UPDATE는 20건, 조건부 UPDATE는 10건 성공으로 확인함), [07장 유니크 제약](07_RDBMS.md).
- **함정**: 애플리케이션 `if`문으로만 막겠다고 말하기. 두 요청이 동시에 들어오면 그 검사는 둘 다 통과합니다.

**Q4. 쿼리가 느린데, 인덱스를 추가하면 되나요?**
- **면접관이 보는 것**: 인덱스를 무조건 추가하지 않고 실행 계획을 보는지.
- **답변 틀**: 느린 쿼리를 먼저 특정 → 실행 계획(`EXPLAIN`)으로 풀스캔 여부 확인 → 조건과 정렬에 맞는 인덱스 후보 → 추가 후 같은 계획과 시간 재확인 → 쓰기 비용 함께 고려.
- **근거**: [07장](07_RDBMS.md), [08장 SQL](08_SQL.md). `EXPLAIN` 결과 비교는 이 PC에서 실행하지 않았다면 미실행으로 말하세요.
- **함정**: 인덱스는 쓰기를 느리게 한다는 점을 빼먹기. 실행 계획을 본 적이 없으면 "본 적이 없다"고 말하고 확인 절차를 말하는 쪽이 낫습니다.

**Q5. JWT를 쓰면 로그아웃은 어떻게 하나요? 토큰이 그대로 살아 있지 않나요?**
- **면접관이 보는 것**: 토큰 기반 인증의 한계를 알고 있는지.
- **답변 틀**: JWT는 서명으로 위조는 막지만 서버가 쉽게 취소하지 못한다는 점을 먼저 인정 → 짧은 만료 시간 → 재발급(refresh) 방식 → 필요하면 폐기 목록이나 저장소로 상태 관리하는 비용을 설명.
- **근거**: [31장 3-1절](31_보안_프레임워크_RBAC.md)(JWT 서명 검증 실행 확인함), [32장](32_OAuth_소셜_로그인.md)(재발급 Node 확인함).
- **함정**: "JWT는 안전하니까 로그아웃만 하면 된다"고 말하기. 토큰 자체는 서버에서 지워지지 않습니다.

**Q6. 스프링 실행 중 "No qualifying bean"(빈을 찾을 수 없음) 오류가 납니다. 무엇을 보시겠습니까?**
- **면접관이 보는 것**: 컴포넌트 스캔 범위와 빈 등록 원리를 이해하는지.
- **답변 틀**: 오류 메시지에서 어떤 타입을 찾는지 확인 → 그 클래스에 스테레오타입(`@Service` 등)이 있는지 → 메인 클래스 패키지 아래에 있는지(스캔 범위) → 생성자 주입 대상 타입이 맞는지.
- **근거**: [19장 스캔 범위 오류](19_Spring_Core.md)(`NoSuchBeanDefinitionException`을 실행으로 확인함).
- **함정**: 빈 이름과 타입을 혼동하기. 같은 타입 빈이 여러 개면 다른 오류가 납니다.

**Q7. 목록 화면 하나에서 SQL이 수백 번 나갑니다. 원인과 해결은요?**
- **면접관이 보는 것**: N+1을 말로만 알지 않고 측정해 봤는지.
- **답변 틀**: 로그로 반복 쿼리 패턴 확인 → 연관 로딩 시점(LAZY) 확인 → fetch join, batch size, DTO 조회 중 목적에 맞는 방법 선택 → 쿼리 수로 개선 확인.
- **근거**: [25장 3절 N+1 비교](25_JPA.md)(6/2/1 SQL을 실행으로 확인함), [25장 4-5절](25_JPA.md)(학과 3개면 추가 3회).
- **함정**: fetch join을 모든 곳에 쓰기. 컬렉션을 페이징과 함께 쓰면 문제가 생길 수 있습니다.

**Q8. AI가 만든 코드를 어떻게 검증하시나요?**
- **면접관이 보는 것**: 생성물을 그대로 믿지 않는 검증 습관.
- **답변 틀**: 요구사항을 테스트로 먼저 쓰기 → 경계값과 예외 입력 실행 → 시간이나 외부 호출에 대한 방어 확인 → 결과를 DB나 원래 데이터와 대조.
- **근거**: [99장 AI 생성 코드 검증](99_AI_생성코드_검증.md)(결함 목록과 검증 코드 3종을 실행함).
- **함정**: "테스트가 통과했다"만 말하기. 테스트가 무엇을 검사하는지 말해야 합니다.

**Q9. 테스트가 가끔만 실패합니다. 어떻게 하시겠습니까?**
- **면접관이 보는 것**: 간헐적 실패(flaky)의 원인을 좁히는 방법.
- **답변 틀**: 실패 조건 기록(시간, 순서, 데이터) → 공유 상태와 실행 순서 의존 확인 → 시간이나 난수 고정 → 여러 번 반복 실행으로 재현.
- **근거**: [37장 테스트 심화](37_테스트_심화.md), [100장 디버깅](100_디버깅_기본.md).
- **함정**: "다시 돌리면 통과하니까 괜찮다"고 말하기.

**연습 방법**: 각 질문을 다음 순서로 소리 내서 말해 보세요. (1) 답을 가리고 60초로 말한다. (2) 근거 장을 열어 빠뜨린 부분을 확인한다. (3) 같은 질문을 실제 실행 결과로 한 문장 더 보강한다. 한 질문에 2~3회 반복하면 틀이 자연스러워집니다.
