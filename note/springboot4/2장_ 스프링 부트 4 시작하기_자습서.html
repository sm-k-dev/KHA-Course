1. 프레임워크와 라이브러리

라이브러리(Library)는 내가 필요한 기능을 골라 내가 불러서 쓰는 도구 모음입니다. 프레임워크(Framework)는 프로그램의 큰 틀을 먼저 정해 두고, 그 틀이 내 코드를 불러 주는 구조입니다. 이 차이를 "제어의 주도권"이라고 합니다.

🎬 애니메이션: 누가 누구를 부르는가

  1. 호출 방향만 기억하면 두 개념이 구분됩니다.
  2. 1단계: 라이브러리에서는 내 코드가 도구를 호출합니다.
  3. 2단계: 프레임워크에서는 틀이 내 코드를 호출합니다.
구분라이브러리프레임워크
주도권내 코드프레임워크
내가 할 일필요한 것을 골라 호출정해진 자리에 내 코드를 끼워 넣기
예날짜 계산 라이브러리스프링, 장고(Django)
📌 프레임워크를 쓰는 이유서버 프로그램에는 매번 똑같이 필요한 일이 많습니다. 요청 분배, 데이터 연결, 오류 처리 등입니다. 프레임워크는 이 공통 부분을 미리 만들어 두어 개발자가 핵심 업무에 집중하게 합니다.

Q. 프레임워크에서 주도권을 가진 쪽은 누구인가요?

A. 프레임워크(틀)입니다. 틀이 내 코드를 정해진 시점에 호출합니다.

2. 스프링 프레임워크

스프링(Spring Framework)은 자바로 서버 프로그램을 만들 때 가장 많이 쓰는 프레임워크입니다. 스프링의 핵심은 객체를 만들고 연결하는 일을 스프링 컨테이너(Container)라는 관리자에게 맡기는 것입니다.

🎬 애니메이션: 객체가 컨테이너를 거쳐 쓰이는 흐름

  1. 자바 객체를 직접 만들던 방식에서, 스프링이 대신 관리하는 방식으로 바뀝니다.
  2. 1단계: 개발자는 객체의 설계도(클래스)를 작성하고, 객체의 생성과 보관은 컨테이너에 맡깁니다.
  3. 2단계: 필요한 곳에서는 컨테이너가 보관 중인 객체를 꺼내 전달합니다.
스프링이 해 주는 일뜻
객체 관리객체를 만들고 필요한 기간 동안 보관
연결객체끼리 필요한 것을 서로 전달
공통 기능로그, 트랜잭션 같은 반복 기능을 한곳에서 처리
💡 핵심 한 줄스프링은 "객체를 누가 만들고, 누구에게 넘길지"를 대신 정해 주는 프레임워크입니다.
🧠 확인 퀴즈 2

Q. 스프링 컨테이너가 하는 일을 한 문장으로 말해 보세요.

A. 객체를 만들고 보관하며, 필요한 곳에 연결해 주는 일입니다.

3. 스프링 부트

스프링은 강력하지만, 예전에는 설정 파일을 수십 줄 써야 했습니다. 스프링 부트(Spring Boot)는 이 설정을 자동으로 맞추고, 서버(톰캣)까지 프로그램 안에 넣어 실행 한 번으로 서버가 뜨도록 만든 도구입니다.

🎬 애니메이션: 스프링 부트가 하는 세 가지 일

  1. 스프링 부트의 핵심은 세 단계로 줄어듭니다.
  2. 1단계: build.gradle에 starter 의존성을 한 줄 추가합니다.
  3. 2단계: 스프링 부트가 추가된 라이브러리를 보고 필요한 설정을 자동으로 맞춥니다.
  4. 3단계: 내장 톰캣이 함께 실행되어 바로 요청을 받을 수 있습니다.
구분스프링 (직접 설정)스프링 부트
서버 준비톰캣을 따로 설치하고 연결내장 톰캣이 자동 실행
설정설정 파일을 직접 많이 작성대부분 자동, 필요한 것만 수정
시작여러 단계 필요main 메서드 실행 한 번
📌 starter란?"웹을 만들 때 필요한 묶음"을 한 이름으로 가져오는 의존성입니다. 예: spring-boot-starter-web을 넣으면 웹 기능과 내장 톰캣이 함께 들어옵니다.
🧠 확인 퀴즈 3

Q. 스프링 부트가 설정을 줄여 주는 방식은 무엇이라고 부르나요?

A. 자동 설정(Auto Configuration)입니다. 추가된 라이브러리를 보고 설정을 알아서 맞춥니다.

4. IoC 제어의 역전

IoC(Inversion of Control, 제어의 역전)는 객체를 만들고 연결하는 권한을 내 코드에서 컨테이너로 넘기는 것입니다. "역전"이라는 말은 주도권이 내 코드에서 바깥으로 뒤집혔다는 뜻입니다.

🎬 애니메이션: 직접 만들기 → 맡기기

  1. 같은 기능을 두 가지 방식으로 만들어 봅니다.
  2. 1단계: 방식 A에서는 내 코드 안에서 new로 객체를 직접 만듭니다.
  3. 2단계: 방식 B에서는 객체 생성을 컨테이너에 맡기고, 내 코드는 받아서 씁니다.
  4. 3단계: 주도권이 바깥으로 넘어간 이 구조가 IoC입니다.

방식 A: 직접 만드는 코드

public class CoffeeShop { // CoffeeShop 객체가 만들어질 때 Grinder도 여기서 직접 만든다 private Grinder grinder = new Grinder(); public void makeCoffee() { // 직접 가진 grinder로 원두를 간다 grinder.grind(); } }

방식 B: 맡기는 코드

public class CoffeeShop { // Grinder는 밖에서 만들어 와 이 칸에 넣는다. 직접 new 하지 않는다 private final Grinder grinder; // 생성자: 밖에서 Grinder를 받아 칸에 저장한다 public CoffeeShop(Grinder grinder) { this.grinder = grinder; } public void makeCoffee() { grinder.grind(); } }
⚠️ 방식 A의 문제Grinder를 다른 것으로 바꾸거나 테스트용 가짜 객체로 바꾸려면 CoffeeShop 코드를 직접 고쳐야 합니다. 방식 B는 밖에서 넣기만 하면 되므로 고칠 곳이 줄어듭니다.
🧠 확인 퀴즈 4

Q. IoC에서 객체를 만드는 권한은 누구에게 넘어가나요?

A. 스프링 컨테이너입니다. 내 코드는 필요한 객체를 전달받아 사용합니다.

5. DI 의존성 주입

DI(Dependency Injection, 의존성 주입)는 어떤 객체가 필요로 하는 다른 객체를 밖에서 넣어 주는 것입니다. 주문을 처리하는 OrderService는 결제를 해 줄 PaymentGateway가 필요합니다. 스프링은 PaymentGateway를 미리 만들어 두었다가 OrderService를 만들 때 넘겨줍니다.

🎬 애니메이션: 결제 객체가 주문 객체에게 전달되는 순서

  1. 의존성 주입은 "필요한 것을 밖에서 넣어 준다"는 뜻입니다.
  2. 1단계: 스프링이 PaymentGateway 객체를 만들어 컨테이너에 보관합니다.
  3. 2단계: OrderService를 만들 때, 보관 중인 PaymentGateway를 생성자 매개변수로 넘깁니다.
  4. 3단계: 주문 요청이 오면 OrderService가 결제 객체의 메서드를 호출하고 결과를 돌려줍니다.

코드: 결제 객체

package com.example.demo; import org.springframework.stereotype.Component; // @Component를 쓰기 위해 가져온다 @Component // 스프링이 이 클래스의 객체를 만들어 관리하도록 표시한다 public class PaymentGateway { // 금액을 받아 결제를 시도하고, 성공이면 true, 실패면 false를 돌려준다 public boolean pay(int price) { return price > 0; // 금액이 0보다 크면 성공으로 보는 학습용 규칙이다 } // 결과 true 또는 false가 호출한 곳으로 돌아간다 }

코드: 주문 객체 (생성자로 결제 객체를 받음)

package com.example.demo; import org.springframework.stereotype.Service; // @Service를 쓰기 위해 가져온다 @Service // 스프링이 이 클래스의 객체를 만들어 관리하도록 표시한다 public class OrderService { private final PaymentGateway paymentGateway; // 결제 객체를 담아 둘 칸. final이라 한 번 정하면 바꾸지 않는다 // 생성자: 스프링이 OrderService를 만들 때 호출한다 // 스프링은 보관 중인 PaymentGateway 객체를 찾아 이 매개변수로 넘겨준다 public OrderService(PaymentGateway paymentGateway) { this.paymentGateway = paymentGateway; // 전달받은 객체를 필드 칸에 저장한다 } // 주문을 처리한다. 컨트롤러가 이 메서드를 호출한다 public String order(String item, int price) { boolean paid = paymentGateway.pay(price); // 결제 객체의 pay를 호출하고, 성공 여부를 받는다 if (!paid) { // 결제가 실패했다면 return "결제 실패: " + item; // 실패 문구를 호출한 곳으로 돌려준다 } return "주문 완료: " + item; // 결제가 성공했다면 완료 문구를 돌려준다 } }
📌 생성자가 하나면 @Autowired를 생략해도 됩니다스프링은 생성자가 하나뿐인 빈에 대해 필요한 객체를 자동으로 넣어 줍니다. 그래서 위 코드에는 @Autowired가 없습니다.
🧠 확인 퀴즈 5

Q. 생성자 매개변수로 PaymentGateway를 받는 방식을 무엇이라고 하나요?

A. 생성자 주입(의존성 주입의 한 방식)입니다.

6. 빈과 컴포넌트 스캔

빈(Bean)은 스프링 컨테이너가 만들고 관리하는 객체 하나를 말합니다. 스프링은 컴포넌트 스캔(Component Scan)으로 프로젝트 안을 훑어, 표시가 붙은 클래스를 빈으로 등록합니다.

🎬 애니메이션: 표시를 찾아 빈으로 등록하기

  1. 스프링은 표시가 붙은 클래스를 찾아 빈으로 만듭니다.
  2. 1단계: 스프링 부트 시작 시 프로젝트를 훑어 @Component 계열 표시를 찾습니다.
  3. 2단계: 찾은 클래스의 객체를 만들어 빈 저장소에 보관합니다.
  4. 3단계: 다른 빈이 필요로 하면 보관 중인 빈을 꺼내 넣어 줍니다.
표시(어노테이션)붙이는 곳의미
@Component일반 클래스가장 기본적인 빈
@Service업무 로직 클래스주문, 결제 같은 처리 담당
@Repository데이터 접근 클래스데이터베이스와 대화하는 담당
@Controller, @RestController요청을 받는 클래스웹 요청 입구 담당
⚠️ 스캔 범위@SpringBootApplication이 붙은 패키지와 그 하위 패키지만 스캔합니다. 다른 위치에 만든 클래스는 빈으로 등록되지 않아 "빈을 찾을 수 없다"는 오류가 날 수 있습니다.
🧠 확인 퀴즈 6

Q. 스프링이 표시를 보고 객체를 만들어 보관하는 저장소를 무엇이라고 부르나요?

A. 빈(Bean) 저장소, 즉 스프링 컨테이너입니다. 그 안의 객체 하나하나가 빈입니다.

7. AOP 관점 지향

AOP(Aspect-Oriented Programming, 관점 지향 프로그래밍)는 여러 곳에서 반복되는 공통 기능을 따로 빼 두고, 필요한 메서드 앞뒤에 자동으로 끼워 넣는 방식입니다. 대표적인 공통 기능은 로그 남기기, 실행 시간 재기, 권한 확인입니다.

🎬 애니메이션: 원래 메서드 앞뒤에 공통 기능이 끼어드는 순서

  1. 호출하는 곳에서는 원래 메서드만 부른 것처럼 보입니다.
  2. 1단계: 호출이 들어오면 공통 기능의 앞부분이 먼저 실행됩니다.
  3. 2단계: 공통 기능이 원래 메서드를 실행합니다.
  4. 3단계: 원래 메서드가 끝나면 공통 기능의 뒷부분이 실행되고 결과가 돌아갑니다.

코드: 실행 시간을 재는 공통 기능

package com.example.demo; import org.aspectj.lang.ProceedingJoinPoint; // 원래 메서드를 가리키는 객체 import org.aspectj.lang.annotation.Around; // 메서드 앞뒤를 감싸는 표시 import org.aspectj.lang.annotation.Aspect; // 공통 기능 클래스라는 표시 import org.springframework.stereotype.Component; // 스프링 빈으로 등록하는 표시 @Aspect // 이 클래스는 공통 기능을 담는다는 표시 @Component // 스프링이 이 클래스의 객체를 만들어 관리한다 public class TimeAspect { // OrderService의 모든 메서드를 이 공통 기능이 감싼다는 규칙 @Around("execution(* com.example.demo.OrderService.*(..))") public Object measure(ProceedingJoinPoint joinPoint) throws Throwable { long start = System.currentTimeMillis(); // 원래 메서드 실행 전 시각을 기록한다 Object result = joinPoint.proceed(); // 원래 메서드를 실행하고, 그 결과를 받는다 long end = System.currentTimeMillis(); // 원래 메서드가 끝난 시각을 기록한다 System.out.println(joinPoint.getSignature() + " 걸린 시간: " + (end - start) + "ms"); return result; // 원래 메서드의 결과를 호출한 곳으로 돌려준다 } }
📌 의존성 추가AOP를 쓰려면 build.gradle에 spring-boot-starter-aop를 추가해야 합니다.
🧠 확인 퀴즈 7

Q. AOP에서 여러 메서드에 반복되는 기능을 무엇이라고 부르나요?

A. 공통 기능(횡단 관심사)입니다. 로그, 시간 측정, 권한 확인 같은 기능이 여기에 해당합니다.

8. 첫 애플리케이션 구조

스프링 부트 프로젝트를 만들면 시작점이 되는 파일이 하나 생깁니다. 이 파일을 실행하면 빈 스캔과 서버 실행이 차례로 일어납니다.

🎬 애니메이션: main 메서드를 실행하면 생기는 일

  1. 실행 버튼 하나에 여러 일이 연결되어 있습니다.
  2. 1단계: main 메서드가 실행되고 스프링 부트가 컨테이너를 만들며 빈을 스캔합니다.
  3. 2단계: 빈 등록이 끝나면 내장 서버가 시작되어 요청을 기다립니다.

코드: 시작 파일

package com.example.demo; import org.springframework.boot.SpringApplication; // 스프링 부트를 실행하는 클래스 import org.springframework.boot.autoconfigure.SpringBootApplication; // 시작 표시 @SpringBootApplication // 이 패키지와 하위 패키지의 빈을 스캔하고 자동 설정을 켠다 public class DemoApplication { public static void main(String[] args) { // 자바 프로그램이 시작되는 지점 // 스프링 컨테이너를 만들고, 빈을 등록하고, 내장 서버를 실행한다 SpringApplication.run(DemoApplication.class, args); } // 서버가 실행되는 동안 이 줄에서 머문다 }
⚠️ 파일 위치이 파일은 src/main/java 아래의 가장 위 패키지(예: com.example.demo)에 두어야 합니다. 그래야 그 아래 모든 클래스를 스캔할 수 있습니다.
🧠 확인 퀴즈 8

Q. @SpringBootApplication은 어떤 범위의 빈을 스캔하나요?

A. 이 표시가 붙은 패키지와 그 하위 패키지입니다.

9. 실습: 첫 컨트롤러

이제 직접 실행해 봅니다. 요청 주소 /hello를 받으면 문자열을 돌려주는 컨트롤러를 만듭니다. 컨트롤러는 1장에서 본 요청의 입구 역할을 합니다.

🎬 애니메이션: /hello 요청 한 번

  1. 브라우저에서 /hello를 입력하면 이런 일이 생깁니다.
  2. 1단계: 요청이 HelloController의 hello 메서드로 전달됩니다.
  3. 2단계: 메서드가 돌려준 문자열이 응답 본문이 되어 화면에 보입니다.

코드: HelloController

package com.example.demo; import org.springframework.web.bind.annotation.GetMapping; // GET 요청을 메서드에 연결하는 표시 import org.springframework.web.bind.annotation.RestController; // 반환값을 응답 본문으로 보내는 컨트롤러 표시 @RestController // 이 클래스는 요청을 받아 응답 데이터를 돌려준다 public class HelloController { @GetMapping("/hello") // GET /hello 요청이 오면 아래 메서드가 실행된다 public String hello() { return "안녕하세요, 스프링 부트!"; // 이 문자열이 응답 본문으로 브라우저에 돌아간다 } }

실행 방법

  1. DemoApplication.java를 열고 main 메서드 옆의 실행(▶) 버튼을 누릅니다.
  2. 콘솔에 "Started DemoApplication"이 보이면 서버가 뜬 것입니다.
  3. 브라우저 주소창에 http://localhost:8080/hello를 입력합니다.
  4. "안녕하세요, 스프링 부트!"가 보이면 성공입니다.
🚫 자주 나는 오류포트 8080을 다른 프로그램이 쓰고 있으면 서버가 뜨지 않습니다. 1장에서 배운 포트 충돌을 떠올리고, 먼저 떠 있는 프로그램을 끄세요.
🧠 확인 퀴즈 9

Q. GET /hello 요청에 대해 응답 본문이 되는 값은 무엇인가요?

A. hello 메서드가 return한 문자열입니다.
