PART 1. Docker는 왜 등장했을까?

프로그래밍을 공부하다 보면 가장 당황스러운 순간 중 하나는 "내 컴퓨터에서는 잘 되는데, 다른 사람 컴퓨터나 서버에서는 왜 안 되지?"라는 문제를 마주할 때입니다.

👨‍💻 개발자 A의 컴퓨터

  • OS: Windows 11
  • Java: 21 버전
  • MySQL: 8.0 버전
  • Node.js: 22 버전
  • 결과: 프로젝트 정상 실행 ✅

👩‍💻 개발자 B의 컴퓨터

  • OS: Windows 10
  • Java: 17 버전
  • MySQL: 8.0 버전
  • Node.js: 20 버전
  • 결과: 버전 불일치 오류 발생 ❌

왜 이런 문제가 발생할까요?

운영체제 종류, 설치된 프로그램과 라이브러리의 버전, 환경설정, 포트 번호 등이 사람마다 조금씩 다르기 때문입니다. 개발 환경을 똑같이 맞추는 것은 수많은 시간이 소모되는 고통스러운 작업이었습니다. Docker는 바로 이 '개발 환경 불일치' 문제를 해결하기 위해 탄생했습니다!

PART 2. Docker란 무엇인가?

Docker(도커)는 애플리케이션을 실행하는 데 필요한 프로그램, 라이브러리, 설정 등 모든 실행 환경을 컨테이너(Container) 단위로 패키징하고 어디서든 동일하게 실행할 수 있도록 해주는 가상화 플랫폼입니다.

핵심 용어 정리

  • Docker Engine: 컨테이너를 생성하고 실행하는 도커의 핵심 엔진입니다.
  • Image (이미지): 프로그램을 실행하는 데 필요한 모든 파일과 설정이 담긴 읽기 전용 템플릿(붕어빵 틀)입니다.
  • Container (컨테이너): 이미지를 실행하여 독립된 공간에서 동작하는 프로세스(붕어빵)입니다.
  • Dockerfile: 이미지를 만들기 위한 설명서(레시피) 텍스트 파일입니다.
  • Docker Hub / Registry: 만든 이미지를 저장하고 공유하는 클라우드 저장소입니다.

PART 3. 가상머신(VirtualBox/WSL2)과 Docker의 차이

이미 앞에서 가상머신(VirtualBox)이나 WSL2를 학습하셨습니다. 그렇다면 Docker는 이들과 무엇이 다를까요?

🖥️ 일반 가상머신 (VirtualBox)

하드웨어 가상화를 통해 호스트 OS 위에 완전한 Guest OS(커널 포함)를 통째로 올립니다. 무겁고 느립니다.

🐳 Docker 컨테이너

호스트 컴퓨터의 Linux 커널을 공유하면서 프로세스 공간만 완벽하게 격리합니다. 매우 가볍고 빠르게 실행됩니다.

⚠️ 주의: 도커 컨테이너를 단순히 '아주 가벼운 가상머신'이라고 부르기도 하지만, 기술적으로는 별도의 OS 커널을 통째로 띄우는 것이 아니라 호스트의 커널을 공유하는 격리된 프로세스 실행 환경입니다.

PART 4. Docker의 핵심 개념 3가지 (Image, Container, Dockerfile)

도커를 다루기 위해 반드시 이해해야 할 세 가지 핵심 개념과 그 관계를 살펴봅니다.

  • 1. Dockerfile: 이미지를 만들기 위한 텍스트 레시피 파일
  • 2. Docker Image: 레시피대로 만들어진 읽기 전용 실행 템플릿
  • 3. Docker Container: 이미지를 실행하여 동작하는 격리된 프로세스

PART 5. Docker가 실제로 작동하는 구조 (Client와 Daemon)

우리가 터미널에 명령어를 입력할 때 내부에서는 어떤 일이 일어날까요?

  • Docker Client: 사용자가 입력하는 명령어(docker run ...)를 받는 인터페이스입니다.
  • Docker Daemon (dockerd): 백그라운드에서 실질적으로 이미지를 만들고 컨테이너를 관리하는 엔진입니다.

사용자가 docker run nginx를 입력하면, Client가 Daemon에게 요청을 보내고, Daemon은 로컬에 이미지가 있는지 확인한 뒤 없으면 Docker Hub에서 다운로드(Pull)하여 컨테이너를 실행합니다.

PART 6. Docker Hub & Registry

Docker Hub는 전 세계 개발자들이 만든 도커 이미지를 공유하는 거대한 공개 저장소(Registry)입니다.

Terminal
# Nginx 공식 웹서버 이미지를 내 컴퓨터로 다운로드
docker pull nginx

# 내 컴퓨터에 다운로드된 이미지 목록 확인
docker images

PART 7. 필수 Docker 실습 명령어

실무에서 가장 자주 사용하는 핵심 명령어와 옵션 의미를 알아봅니다.

Terminal - 컨테이너 백그라운드 실행
docker run -d -p 8080:80 --name my-nginx nginx

명령어 옵션 상세 해설:

  • docker run: 이미지를 기반으로 새로운 컨테이너를 생성하고 실행
  • -d (Detach): 터미널 창을 막지 않고 백그라운드(Background)에서 실행
  • -p 8080:80 (Port Forwarding): 내 컴퓨터의 8080번 포트로 들어오는 요청을 컨테이너 내부의 80번 포트로 연결
  • --name my-nginx: 생성될 컨테이너의 이름을 my-nginx로 지정
  • nginx: 사용할 이미지 이름
Terminal - 컨테이너 상태 관리
# 실행 중인 컨테이너 확인
docker ps

# 모든 컨테이너(정지된 것 포함) 확인
docker ps -a

# 컨테이너 중지
docker stop my-nginx

# 컨테이너 삭제
docker rm my-nginx

PART 8. Docker를 활용한 MySQL 8 실습

웹 개발 백엔드 과정에서 필수적인 MySQL 데이터베이스 서버를 도커로 아주 간단하게 띄워보겠습니다.

Terminal - MySQL 8 컨테이너 실행
docker run -d \
  --name mysql8 \
  -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=1234 \
  -e MYSQL_DATABASE=study_db \
  mysql:8.0
  • -e MYSQL_ROOT_PASSWORD=1234: root 계정 비밀번호를 1234로 설정
  • -e MYSQL_DATABASE=study_db: 컨테이너가 생성될 때 study_db 데이터베이스 자동 생성

⚠️ 데이터 영속성 주의: 컨테이너를 그냥 삭제(docker rm)하면 내부에 저장했던 데이터도 함께 사라집니다. 실무에서는 데이터를 안전하게 보존하기 위해 Docker Volume 기술을 반드시 사용해야 합니다!

PART 9. Docker Volume과 Network

  • Docker Volume: 컨테이너를 삭제해도 데이터가 호스트 컴퓨터 디스크에 안전하게 남아있도록 연결해 주는 저장 공간 기능입니다.
  • Docker Network: 여러 개의 컨테이너(예: Spring Boot 컨테이너와 MySQL 컨테이너)끼리 서로 안전하게 통신할 수 있도록 가상의 네트워크망을 제공합니다.

PART 10. 실무 개발에서 Docker 활용

실제 웹 개발 팀에서는 다음과 같은 구조로 개발 환경을 구성합니다.

  • 데이터베이스 & 캐시: MySQL, Redis 등을 Docker 컨테이너로 실행하여 PC에 직접 복잡하게 설치하지 않고 깔끔하게 관리합니다.
  • 애플리케이션: Spring Boot 코드는 IntelliJ에서 직접 실행하며 도커 내의 MySQL과 연결해 테스트합니다.

PART 11. Docker Compose 입문

여러 개의 컨테이너(MySQL, Redis, Web 등)를 각각 명령어로 실행하려면 번거롭습니다. Docker Compose는 docker-compose.yml 파일 하나에 여러 서비스를 정의하고 명령어 한 줄로 동시에 실행/종료할 수 있는 도구입니다.

Terminal
# 정의된 모든 컨테이너 백그라운드 실행
docker compose up -d

# 모든 컨테이너 중지 및 정리
docker compose down

PART 12. 종합 학습 확인 퀴즈

학습 내용을 얼마나 이해했는지 퀴즈로 확인해 보세요!

Q1. Docker 컨테이너에 대한 설명으로 올바른 것은?

1. 컨테이너마다 완전한 별도의 Guest OS 커널이 독립적으로 설치된다.
2. 호스트 컴퓨터의 OS 커널을 공유하면서 프로세스 공간을 격리하여 가볍게 실행된다.
3. 가상머신(VirtualBox)과 기술적으로 완전히 동일하다.
정답은 2번입니다! 도커 컨테이너는 호스트의 Linux 커널을 공유하기 때문에 가상머신보다 훨씬 가볍고 빠르게 동작합니다.

Q2. Docker Image와 Container의 관계로 올바른 것은?

1. Container가 붕어빵 틀이고 Image가 붕어빵이다.
2. Image(읽기 전용 템플릿)를 기반으로 여러 개의 Container(실행 중인 프로세스)를 만들 수 있다.
3. Image와 Container는 완전히 같은 의미이다.
정답은 2번입니다! Image는 설계도/템플릿이며, 이를 실행한 상태가 Container입니다. 하나의 이미지로 여러 컨테이너를 생성할 수 있습니다.
