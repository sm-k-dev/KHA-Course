💡 이 강의의 최종 목표 (핵심 요약)

"WSL2는 Windows 안에서 Linux를 실행하는 기술입니다. VirtualBox처럼 가상화 기술을 사용하지만, 사용자가 직접 가상 컴퓨터를 생성하고 운영체제를 설치/관리하는 방식이 아니라 Windows가 Linux 실행 환경을 자동으로 관리해 줍니다. WSL2는 Hyper-V 기반 경량 가상머신에서 실제 Linux 커널을 실행하며, Ubuntu는 그 Linux 환경에서 사용하는 배포판입니다."

PART 1. WSL2를 왜 사용하는가? 개념 도입

1. 운영체제(OS)란 무엇인가?

컴퓨터 하드웨어(CPU, RAM, SSD 등)는 스스로 작동할 수 없는 전자 부품 모음입니다. 운영체제(Operating System)는 이 하드웨어를 제어하고, 사용자가 프로그램을 실행할 수 있도록 중재해 주는 기본 소프트웨어입니다.

🪟 Windows 운영체제

전 세계 개인용 PC 시장의 표준입니다. 그래픽 화면(GUI) 기반으로 클릭과 아이콘 중심의 뛰어난 사용자 편의성을 제공합니다.

🐧 Linux 운영체제

전 세계 웹 서버와 구글, 네이버 등 대형 클라우드 서버의 90% 이상을 차지하는 서버용 운영체제입니다. 텍스트 명령어(CLI) 중심입니다.

2. 개발자가 Linux 환경을 사용하는 이유

우리가 만들 웹 애플리케이션(백엔드 서버, 데이터베이스 등)은 실제로 **Linux 서버**에 배포되어 실행됩니다. 따라서 개발 과정에서도 실제 배포 환경과 동일한 Linux 환경에서 코딩해야 "내 컴퓨터에서는 잘 되는데 서버에서는 안 돼요!"라는 문제를 방지할 수 있습니다.

3. Windows에서 Ubuntu(Linux)를 사용해야 하는 이유 & WSL2의 등장

웹 개발자 대부분은 Windows PC를 개인용 컴퓨터로 사용합니다. 하지만 서버 개발 도구, Docker, Git 등 현대 웹 개발 핵심 기술은 Linux 환경에 최적화되어 있습니다.

과거에는 Windows 컴퓨터에서 Linux를 쓰기 위해 VirtualBox 같은 heavy한 가상머신을 켜거나, 컴퓨터 1대에 OS 2개를 듀얼 부팅하는 불편함이 있었습니다. 이러한 문제를 해결하기 위해 Microsoft가 Windows 내부에서 Linux를 완벽하게 융합 실행하도록 만든 기술이 바로 WSL2입니다.

PART 2. VirtualBox부터 이해하기 기존 기술 리뷰

WSL2를 정확히 이해하려면, 여러분이 이미 접해보았을 Traditional 가상머신 프로그램인 VirtualBox의 작동 방식을 먼저 짚고 넘어가야 합니다.

가상머신 (Virtual Machine) 개념

① 정확한 정의 소프트웨어로 실제 컴퓨터 하드웨어를 흉내 내어 만든 '가상 컴퓨터'입니다.
② 왜 필요한가? 하나의 PC에서 다른 운영체제(예: Windows에서 Linux)를 안전하게 독립 테스트하기 위해 필요합니다.
③ 실제 역할 CPU, RAM, 하드디스크를 가상으로 쪼개어 가상 컴퓨터에 할당합니다.
④ 위치 Windows 위에 설치된 일반 앱(VirtualBox) 내부에서 격리되어 존재합니다.

PART 3. WSL2의 정체와 핵심 용어 핵심 심화

WSL2는 단순한 응용 프로그램이 아닙니다. Hyper-V 가상화 기술 기반 위에 실제 Linux 커널을 올려 Windows와 완전히 통합시킨 아키텍처입니다. 핵심 용어를 파악해 봅시다.

1. WSL (Windows Subsystem for Linux) & WSL2

① 정확한 정의 Windows 안에서 Linux 환경을 호환성 있게 직접 실행할 수 있도록 지원하는 Microsoft의 기술입니다.
② 왜 필요한가? VirtualBox처럼 느리거나 번거롭지 않게, Windows를 쓰면서 동시에 Linux 터미널을 사용하기 위함입니다.
③ 실제 역할 WSL1(명령어 변환 방식)의 한계를 극복하고, WSL2는 실제 Linux 커널을 경량 가상머신 형태로 실행시켜 100% Linux system call 호환성을 제공합니다.
④ WSL2 내 위치 Windows 시스템 내부 가상화 레이어 전체를 총괄하는 메인 브리지 위치에 있습니다.

2. Hyper-V 기반 가상화 (Hypervisor)

① 정확한 정의 Microsoft가 개발한 하드웨어 자원 분할 전용 가상화 기술(Type-1 Hypervisor 기술)입니다.
② 왜 필요한가? 실제 하드웨어(CPU/RAM)를 속도가 저하되지 않도록 효율적으로 가상 OS에 나눌 수 있는 인프라를 제공합니다.
③ 실제 역할 WSL2 전용 초경량 가상머신(Utility VM)을 1초 만에 띄우고 메모리를 필요할 때만 가변적으로 할당합니다.
④ WSL2 내 위치 Windows 커널 및 실제 하드웨어 바로 위에 위치하는 가상화 엔진 계층입니다.

3. Linux Kernel & Ubuntu 배포판

① 정확한 정의 Kernel: OS의 엔진 핵심.
Ubuntu: 커널 + 유저 프로그램(터미널, 개발도구)을 묶은 배포판(Distribution).
② 왜 필요한가? 커널만으로는 사용자가 명령을 내릴 수 없으므로, 사용하기 쉬운 배포판(Ubuntu 등) 형태가 필수적입니다.
③ 실제 역할 WSL2 안에서 MS가 직접 튜닝한 실제 Linux Kernel이 구동되고, 그 위에서 Ubuntu의 패키지 매니저(apt) 및 명령어가 실행됩니다.
④ WSL2 내 위치 Hyper-V 가상화 레이어 상단에서 실제 개발 작업이 이루어지는 소프트웨어 층입니다.

⚠️ 반드시 구분해야 할 핵심 구분 포인트!

  • Hyper-V: 가상화 환경을 제공하는 기본 기술입니다.
  • WSL2: Hyper-V를 바탕으로 초경량 가상머신에서 실제 Linux 커널을 자동 관리/실행하는 아키텍처입니다.
  • Linux Kernel: 하드웨어를 다루는 핵심 엔진입니다.
  • Ubuntu: 커널 기반 위에 구축되어 개발자가 접하는 소프트웨어 환경(배포판)입니다.
  • 차이점: VirtualBox는 사용자가 직접 가상 PC를 만들고 OS ISO를 구해서 설치/관리해야 하지만, WSL2는 Windows가 이를 100% 자동 관리해 줍니다.

PART 6. WSL2 필수 실습 명령어 실습 터미널 가이드

실제 터미널 명령어를 입력할 때, Windows PowerShell 환경인지 Ubuntu 터미널 환경인지를 반드시 구분해야 합니다.

1. Windows PowerShell에서 사용하는 WSL 관리 명령어

PowerShell (Windows) WINDOWS COMMAND
PS C:\Users\Student> wsl --install

👉 [의미] WSL2 필수 기능과 기본 Ubuntu 배포판을 자동으로 다운로드하여 설치합니다.

PS C:\Users\Student> wsl --list --verbose

👉 [의미] 현재 설치된 Linux 배포판 목록과 WSL 실행 버전(WSL1 vs WSL2)을 확인합니다.

PS C:\Users\Student> wsl

👉 [의미] Windows에서 기본 Linux (Ubuntu) 터미널 접속 모드로 진입합니다.

PS C:\Users\Student> wsl --shutdown

👉 [의미] 현재 실행 중인 모든 WSL2 경량 가상머신 환경을 완전히 종료하여 메모리를 환수합니다.

2. Ubuntu 터미널 내부에서 사용하는 Linux 명령어

Ubuntu Terminal (Linux) UBUNTU COMMAND
student@my-pc:~$ pwd

👉 [의미] Print Working Directory - 현재 내가 위치한 Linux 작업 디렉토리 경로를 출력합니다.

student@my-pc:~$ ls -la

👉 [의미] List - 현재 폴더 안의 숨김 파일 포함 전체 목록과 권한 정보를 확인합니다.

student@my-pc:~$ mkdir my-project

👉 [의미] Make Directory - 'my-project'라는 이름의 새 작업 폴더를 생성합니다.

student@my-pc:~$ java -version

👉 [의미] Ubuntu 내부에 설치된 Java 백엔드 개발 환경 버전을 점검합니다.

PART 7. 개발자가 WSL2를 사용하는 이유 실무 활용 웹 개발 환경

WSL2를 사용하면 Windows의 편리한 그래픽 도구와 Linux의 강력한 개발 도구를 혼합하여 사용할 수 있습니다.

🖥️ Windows 환경에서 실행하는 프로그램

  • VS Code / IntelliJ IDEA (코드 편집기 GUI)
  • Google Chrome (웹 브라우저)
  • Codex / Slack / Figma (커뮤니케이션 & AI 도구)

🐧 WSL2 (Ubuntu) 내부 실행 프로그램

  • Linux OS 환경
  • Java / JDK, Node.js, Python (런타임)
  • Git (버전 관리 시스템)
  • Docker (컨테이너 가상화 엔진)
💡 핵심 요점: 모든 개발 프로그램을 WSL2 내부에 설치할 필요는 없습니다. 예를 들어, 코드 작성은 Windows의 VS Code에서 하고, 그 코드가 실제로 동작하는 웹 서버 엔진은 WSL2의 Ubuntu 상에서 실시간으로 돌아가도록 두 환경이 긴밀하게 협력합니다.
