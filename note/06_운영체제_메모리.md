## 1. 가상 메모리

**정의** — 각 프로세스가 자기만의 연속된 주소 공간을 가진 것처럼 보이게 하는 기법이다. 실제 주소는 운영체제와 하드웨어(MMU)가 물리 메모리로 바꾼다.

**목적과 책임**
- 프로세스끼리 메모리를 서로 침범하지 못하게 격리한다.
- 물리 메모리보다 큰 프로그램도 실행할 수 있게 한다(일부만 메모리에 올린다).
- 같은 코드(예: 라이브러리)를 여러 프로세스가 공유할 수 있다.

**구별해야 할 개념 / 흔한 오해** — 가상 메모리는 디스크를 메모리처럼 쓰는 것이 아니다. 디스크로 내보내는 것(스왑)은 가상 메모리를 구현하는 한 방법일 뿐이다.

---

## 2. 페이징

**정의** — 주소 공간과 물리 메모리를 같은 크기의 조각(페이지, 프레임)으로 나누어 대응시키는 방식이다. 대응 정보는 페이지 테이블에 있다.

**페이지 부재 (Page Fault)** — 필요한 페이지가 메모리에 없을 때 발생한다. 운영체제가 디스크에서 페이지를 읽어 올리고 다시 실행한다. 부재가 많으면 디스크 입출력이 늘어 전체가 느려진다(스래싱).

---

## 3. 페이지 교체 알고리즘

메모리(프레임)가 가득 찼을 때 어떤 페이지를 내보낼지 정하는 방법이다.

- **FIFO:** 먼저 들어온 페이지를 내보낸다. 구현은 쉽지만 자주 쓰는 페이지도 오래됐다는 이유로 내보낼 수 있다.
- **LRU (최근 최소 사용):** 가장 오래 쓰이지 않은 페이지를 내보낸다. 지역성을 잘 활용하지만 매번 사용 순서를 갱신해야 해서 비용이 든다.
- **OPT (최적):** 앞으로 가장 오래 쓰이지 않을 페이지를 내보낸다. 이론상 최선이지만 미래를 알 수 없어서 기준선으로만 쓴다.

**구현 (검증 완료): 프레임 3개, 참조열 `1 2 3 4 1 2 5 1 2 3 4 5`**

```java
static int fifoFaults(int[] refs, int frames) {
    Deque<Integer> mem = new ArrayDeque<>();
    int faults = 0;
    for (int r : refs) {
        if (mem.contains(r)) continue;                 // 이미 있으면 부재 없음
        faults++;
        if (mem.size() == frames) mem.pollFirst();     // 가장 먼저 들어온 것을 내보냄
        mem.addLast(r);
    }
    return faults;
}

static int lruFaults(int[] refs, int frames) {
    LinkedHashSet<Integer> mem = new LinkedHashSet<>();
    int faults = 0;
    for (int r : refs) {
        if (mem.contains(r)) { mem.remove(r); mem.add(r); continue; }   // 최근 사용으로 갱신
        faults++;
        if (mem.size() == frames) { Integer oldest = mem.iterator().next(); mem.remove(oldest); }
        mem.add(r);
    }
    return faults;
}
```

- **확인:** 같은 참조열에서 FIFO의 부재는 9번, LRU는 10번이다. 이 예제에서는 FIFO가 더 적었다. 순서에 따라 결과는 달라진다.
- **Belady 이상 (중요):** FIFO는 프레임을 늘렸는데 부재가 **늘어날 수** 있다. 같은 참조열에서 프레임을 4개로 늘리면 FIFO 부재는 10번으로 늘어난다(검증 완료). LRU는 프레임을 늘리면 부재가 줄거나 같다.

**면접 기준:** "페이지 교체는 메모리가 찼을 때 무엇을 내보낼지 정하는 방법입니다. LRU는 최근에 쓰인 페이지를 남기고, FIFO는 Belady 이상이 생길 수 있습니다."

## 4. 파일 시스템 (개념)

**정의** — 디스크 위에서 파일과 디렉터리를 저장하고 찾는 방법을 정한 구조다.

**핵심 개념**
- **inode(유닉스 계열):** 파일의 크기, 권한, 데이터 블록 위치를 담은 정보. 파일 이름은 inode를 가리키는 링크다.
- **하드 링크와 소프트 링크:** 하드 링크는 같은 inode를 가리키는 또 다른 이름, 소프트 링크는 경로를 가리키는 파일이다. 원본을 지우면 소프트 링크는 깨진다.
- **저널링:** 쓰기 중 정전이 나도 일관성을 지키기 위해 변경 내용을 먼저 기록한다.

**실습 (선택):** `ls -li`로 inode 번호를 보고, `ln`으로 하드 링크와 소프트 링크를 만들어 원본을 지웠을 때 차이를 확인한다.

## 5. 백엔드와의 연결

- 메모리가 부족하면 스왑이 일어나 응답이 느려진다. JVM 힙 크기 설정과 연결된다.
- 페이지 부재가 많으면 디스크 I/O가 늘어 DB와 로그 쓰기가 느려진다.
- 컨테이너(Docker)는 메모리 제한을 걸어 한 컨테이너가 전체 메모리를 쓰지 못하게 한다.
