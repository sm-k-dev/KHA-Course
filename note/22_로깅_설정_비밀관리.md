## 1. 로깅 (SLF4J)

**정의** — 로깅은 실행 중 상태를 기록하는 일이다. Java에서는 **SLF4J**라는 추상화 인터페이스를 쓰고, 실제 구현은 Logback 같은 라이브러리가 맡는다. 코드는 구현에 묶이지 않는다.

```java
private static final Logger log = LoggerFactory.getLogger(OrderService.class);

public void place(Long userId, Long orderId) {
    log.info("주문 접수 userId={} orderId={}", userId, orderId);  // {} 자리표시자
    try {
        // ...
    } catch (Exception e) {
        log.error("주문 실패 orderId={}", orderId, e);             // 마지막 인자가 예외면 스택 트레이스가 남는다
        throw e;
    }
}
```

**자리표시자 `{}`를 쓰는 이유**: 문자열을 `+`로 만들면 로그 레벨이 꺼져 있어도 문자열을 만든다. `{}`는 실제로 출력할 때만 값을 채운다.

### 1.1 로그 레벨

| 레벨 | 쓰는 상황 | 운영 기본 |
|---|---|---|
| TRACE | 아주 세부적인 흐름 | 끔 |
| DEBUG | 개발 중 확인 값 | 끔 |
| INFO | 정상 흐름의 중요한 이벤트 (주문 접수, 배포 시작) | 켬 |
| WARN | 비정상이지만 처리는 계속됨 (재시도, 기본값 사용) | 켬 |
| ERROR | 요청이 실패함. 바로 확인해야 함 | 켬, 알림 연결 |

**실수 예**: 정상 흐름마다 `ERROR`를 남기면, 진짜 장애가 로그 속에 묻힌다.

### 1.2 민감 정보를 남기지 않는다

- 비밀번호, 토큰, 주민등록번호, 카드 번호, 세션 ID는 **어떤 레벨에서도** 로그에 쓰지 않는다.
- 객체를 통째로 로그에 넣지 않는다. `toString()`에 민감 필드가 들어 있을 수 있다.
- 로그는 개인정보 처리 기준의 보관 기간과 접근 권한을 따른다.

```java
log.info("로그인 시도 userId={}", userId);            // 좋음
log.info("로그인 시도 request={}", loginRequest);     // 나쁨: 비밀번호가 찍힐 수 있다
```

## 2. 설정: 환경마다 다른 값은 코드 밖에 둔다

**12-factor 원칙** — 설정(DB 주소, 외부 API 키, 기능 스위치)은 코드에 넣지 않고 **환경 변수**로 주입한다. 같은 빌드 산출물이 개발, 스테이징, 운영에서 그대로 돌아가야 한다.

```yaml
# application.yml: 값은 환경 변수에서 읽고, 기본값은 개발용으로만 둔다
spring:
  datasource:
    url: ${DB_URL:jdbc:mysql://localhost:3306/app}
    username: ${DB_USER}           # 기본값 없음: 없으면 기동 실패 (운영 실수 방지)
    password: ${DB_PASSWORD}
```

- 기본값(`:` 뒤)은 **개발용 로컬 값**만 둔다. 운영 비밀번호를 기본값으로 두지 않는다.
- 기본값이 없는 변수는 누락하면 기동이 실패하게 해서 조용한 오동작을 막는다.

### 2.1 `.env` 파일

개발 편의를 위해 `.env` 파일에 환경 변수를 모을 수 있다.

```
DB_USER=app
DB_PASSWORD=change-me-locally
```

**규칙**: `.env`는 **Git에 올리지 않는다** (`.gitignore`에 추가). 대신 `.env.example`에 키 이름만 적어서 올린다.

## 3. 비밀 관리

| 나쁜 방법 | 문제 | 나은 방법 |
|---|---|---|
| 소스 코드에 키를 하드코딩 | Git 기록에 영원히 남는다 | 환경 변수 또는 비밀 저장소 |
| `application.yml`에 운영 비밀번호 | 저장소 접근자 모두가 본다 | 배포 시 주입 (CI/CD 비밀 변수, 클라우드 시크릿 매니저) |
| 키를 채팅이나 이슈에 붙여넣기 | 검색과 캐시에 남는다 | 즉시 폐기(rotate)하고 새 키 발급 |

**키가 노출되면**: 즉시 폐기하고 새 키를 발급한다. 저장소에서 지우는 것만으로는 안전하지 않다. Git 기록에 남아 있기 때문이다.

---

## 4. 실습 과제

1. 주문 코드 한 개에 `log.info`를 넣고, 자리표시자 `{}`와 문자열 `+`를 바꿔 쓴 두 버전을 비교한다. (실행 검증은 Spring 프로젝트가 있을 때 한다.)
2. 본인 프로젝트의 `application.yml`에서 비밀번호처럼 보이는 값을 찾아 환경 변수로 옮긴다.
3. `.gitignore`에 `.env`가 들어 있는지 확인하고, 없으면 추가한다.

## 단원 통과 기준

- [ ] INFO, WARN, ERROR를 상황에 맞게 구분할 수 있다.
- [ ] 자리표시자 `{}`를 쓰는 이유를 설명할 수 있다.
- [ ] 12-factor의 설정 원칙을 설명하고, 기본값을 어디까지 둘지 말할 수 있다.
- [ ] 키가 노출됐을 때 저장소에서 지우는 것만으로는 안전하지 않은 이유를 설명할 수 있다.
