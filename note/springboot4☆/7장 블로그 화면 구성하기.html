0. 7장 한눈에 보기

6장에서는 블로그 글을 API로 다뤘습니다. 주소로 요청하면 JSON 데이터가 돌아왔습니다. 그런데 사람이 보는 것은 JSON이 아니라 웹 화면입니다. 7장은 같은 데이터를 화면(HTML)로 보여 주는 방법을 배웁니다.

이 장에서 만드는 화면은 세 가지입니다. 글 목록 화면, 글 상세 화면, 글을 쓰고 고치는 입력 화면입니다. 화면은 타임리프(Thymeleaf)라는 템플릿 엔진으로 만듭니다.

🎬 애니메이션: 요청 한 번이 화면이 되기까지

  1. ① 6장과 달리 이번에는 화면을 돌려줍니다. 화면은 HTML 파일에 데이터가 채워진 것입니다.
  2. ② 브라우저가 /articles 주소로 화면을 요청합니다.
  3. ③ 컨트롤러는 서비스에 글 목록을 부탁해 받아 옵니다.
  4. ④ 글은 모델(Model)에 담기고, 컨트롤러는 "articleList"라는 화면 이름만 돌려줍니다.
  5. ⑤ 타임리프가 articleList.html을 열고 모델의 값을 채워 완성된 화면을 보냅니다.
  6. ⑤ 타임리프가 articleList.html을 열고 모델의 값을 채워 완성된 화면을 보냅니다.

🧠 확인 퀴즈 0

Q. 6장의 API 응답과 7장의 화면 응답은 무엇이 다릅니까?

A. API는 JSON 데이터를, 화면은 데이터가 채워진 HTML을 돌려줍니다.

1. 타임리프란?

템플릿 엔진(Template Engine)은 "빈칸이 있는 양식"에 데이터를 넣어 완성된 문서를 만드는 도구입니다. 결혼식 청첩장을 떠올려 보세요. 문구는 똑같고 이름과 날짜만 칸을 채워 넣습니다. 템플릿 엔진도 HTML이라는 양식의 빈칸에 서버가 준 데이터를 넣습니다.

타임리프(Thymeleaf)는 스프링이 많이 권장하는 템플릿 엔진입니다. 다른 템플릿 엔진으로는 JSP, 프리마커 등이 있습니다. 타임리프의 장점은 HTML 파일이 그대로 웹 브라우저에서 열린다는 점입니다. 디자이너가 HTML 파일을 미리 열어 보며 작업하기 쉽습니다.

🎬 애니메이션: 데이터 + 양식 = 완성된 화면

  1. ① 왼쪽에 서버가 가진 데이터가 있습니다. 이름과 나이입니다.
  2. ② 가운데에는 빈칸이 있는 HTML 양식이 있습니다.
  3. ③ 템플릿 엔진이 하는 일은 HTML의 빈칸 자리를 서버가 보낸 값으로 메우는 것입니다.
  4. ④ 결과 화면은 값이 채워진 HTML입니다. 데이터가 바뀌면 화면도 그때그때 바뀝니다.
  5. ④ 결과 화면은 값이 채워진 HTML입니다. 데이터가 바뀌면 화면도 그때그때 바뀝니다.

📌 HTML과 타임리프 문법이 섞인 모습

타임리프 문법은 HTML 태그 안에 th:로 시작하는 속성을 넣는 방식입니다. 브라우저는 th: 속성을 무시하고 나머지 HTML만 보여 주므로, 양식 파일을 미리 열어 봐도 깨지지 않습니다.

🧠 확인 퀴즈 1

Q. 서버 데이터를 HTML 양식의 빈칸에 넣어 완성된 화면을 만드는 도구의 이름은?

A. 템플릿 엔진입니다. 스프링에서 많이 쓰는 템플릿 엔진이 타임리프입니다.

2. 타임리프 표현식과 문법

타임리프 문법은 크게 표현식과 속성(문법)으로 나뉩니다. 표현식은 값을 가리키는 기호이고, 속성은 HTML 태그에 붙여서 동작을 정하는 이름입니다. 처음에는 낯설지만, 자주 쓰는 여섯 가지만 익히면 대부분의 화면을 만들 수 있습니다.

🔤 표현식 네 가지

표현식뜻예
${...}변수 값을 꺼냄${article.title}
#{...}메시지(글자) 파일의 값을 꺼냄#{menu.home}
@{...}주소(URL)를 만듦@{/articles/1}
*{...}th:object로 고른 객체의 값을 꺼냄*{name}

🎬 애니메이션: 표현식이 값으로 바뀌는 과정

  1. ① 왼쪽은 타임리프 양식, 오른쪽은 실행 결과입니다.
  2. ② ${article.title}은 모델의 article 객체에서 title 값을 꺼냅니다.
  3. ③ @{...}는 주소를 만듭니다. id 값이 주소 뒤에 붙습니다.
  4. ④ *{content}는 바로 위 th:object로 고른 객체의 content 값을 꺼냅니다.
  5. ④ *{content}는 바로 위 th:object로 고른 객체의 content 값을 꺼냅니다.

⚙️ 자주 쓰는 속성 여섯 가지

속성설명예
th:text글자를 채움th:text="${person.name}"
th:each목록 개수만큼 태그를 반복th:each="item : ${articles}"
th:if조건이 참일 때만 보임th:if="${person.age} >= 20"
th:unless조건이 거짓일 때만 보임th:unless="${person.age} >= 20"
th:href링크 주소를 채움th:href="@{/articles/{id}(id=${item.id})}"
th:object, th:with객체를 고르거나 변수를 새로 정함th:object="${person}"

🎬 애니메이션: th:each로 목록 반복하기

  1. ① 목록에 글이 세 건 있습니다.
  2. ② 1회차: item에 첫 번째 글이 들어가 태그 하나가 만들어집니다.
  3. ③ 2회차: item에 두 번째 글이 들어갑니다.
  4. ④ 3회차까지 끝나면 같은 모양의 태그가 세 개 만들어집니다.
  5. ④ 3회차까지 끝나면 같은 모양의 태그가 세 개 만들어집니다.
📌 *{...}와 ${...}의 차이${...}는 어디서든 쓸 수 있는 "전체 이름표"이고, *{...}는 th:object로 먼저 고른 객체 안에서만 쓰는 "짧은 이름"입니다. 같은 객체를 여러 줄에서 쓸 때 편합니다.
🧠 확인 퀴즈 2

Q. 화면에 변수나 메시지 글자를 출력할 때 쓰는 속성은? (① th:with ② th:unless ③ th:object ④ th:text ⑤ th:if)

A. ④ th:text입니다. 글자를 채우는 속성입니다.

3. 의존성과 모델

타임리프를 쓰려면 먼저 라이브러리를 추가해야 합니다. 그리고 컨트롤러가 화면으로 데이터를 전달하는 통로인 모델(Model)을 이해해야 합니다.

📦 1단계: build.gradle에 타임리프 추가

dependencies { // 타임리프 템플릿 엔진 (화면 HTML을 만들어 줌) implementation 'org.springframework.boot:spring-boot-starter-thymeleaf' // ... 기존 의존성은 그대로 둡니다 }
⚠️ 반드시 새로고침추가한 뒤 Gradle 탭의 🔄(새로고침)을 눌러야 실제로 내려받습니다. 화면이 안 나오면 새로고침을 먼저 확인하세요.

🎬 애니메이션: 컨트롤러 → 모델 → 뷰

  1. ① 컨트롤러는 화면에 필요한 데이터를 준비합니다.
  2. ② 모델은 상자입니다. "person"이라는 이름표를 붙여 객체를 넣습니다.
  3. ③ "today"처럼 이름표와 값을 여러 개 넣을 수도 있습니다.
  4. ④ 뷰(HTML)는 같은 이름표로 값을 꺼내 화면에 보여 줍니다.
  5. ④ 뷰(HTML)는 같은 이름표로 값을 꺼내 화면에 보여 줍니다.
💡 Model 매개변수컨트롤러 메서드 매개변수에 Model model이라고 쓰면 스프링이 모델 상자를 알아서 만들어 넘겨 줍니다. 직접 new로 만들 필요가 없습니다. import는 org.springframework.ui.Model입니다.
🧠 확인 퀴즈 3

Q. 컨트롤러가 뷰로 보낼 값을 담을 때 Model에 값을 넣는 메서드 이름은?

A. addAttribute()입니다. 값은 모델(Model) 객체에 담기고, 뷰가 같은 이름으로 꺼냅니다.

4. 연습: 예제 컨트롤러와 화면

블로그 기능을 만들기 전에, 타임리프 문법을 가볍게 익히는 연습을 합니다. 가상의 사람 정보를 만들어 화면에 보여 주는 예제입니다. 연습이 끝나면 이 예제 파일은 지워도 됩니다.

📝 1단계: 예제 컨트롤러 (ExampleController.java)

controller 패키지에 파일을 만들고 아래 코드를 넣습니다.

package me.yourname.springbootdeveloper.controller; import java.time.LocalDate; import java.util.List; import lombok.Getter; import lombok.Setter; import org.springframework.stereotype.Controller; import org.springframework.ui.Model; import org.springframework.web.bind.annotation.GetMapping; @Controller // 이 클래스는 화면을 돌려주는 컨트롤러 public class ExampleController { @GetMapping("/thymeleaf/example") // /thymeleaf/example 요청을 이 메서드에 연결 public String thymeleafExample(Model model) { // 모델을 받아 화면에 넘길 데이터를 담음 Person examplePerson = new Person(); // 사람 객체 만들기 examplePerson.setId(1L); // id 값 넣기 examplePerson.setName("홍길동"); // 이름 넣기 examplePerson.setAge(11); // 나이 넣기 examplePerson.setHobbies(List.of("운동", "독서")); // 취미 목록 넣기 model.addAttribute("person", examplePerson); // "person"이라는 이름표로 저장 model.addAttribute("today", LocalDate.now()); // "today"라는 이름표로 오늘 날짜 저장 return "example"; // example.html 이라는 화면 이름을 돌려줌 } @Setter // 모든 필드에 값 넣는 메서드 자동 생성 @Getter // 모든 필드 값 꺼내는 메서드 자동 생성 static class Person { // 화면에 보여 줄 사람 정보 묶음 private Long id; private String name; private int age; private List<String> hobbies; } }
💡 return 값의 의미@Controller가 붙은 메서드가 "example"을 돌려주면, 스프링은 resources/templates/example.html 파일을 찾아 화면으로 만듭니다. 문자열은 파일 이름입니다.

📝 2단계: 화면 파일 (src/main/resources/templates/example.html)

templates 폴더에 example.html을 만듭니다. 파일 유형은 HTML 5를 선택합니다.

<!DOCTYPE html> <html xmlns:th="http://www.thymeleaf.org"> <!-- 타임리프 문법을 쓰겠다는 선언 --> <head> <meta charset="UTF-8"> <title>Title</title> </head> <body> <h1>타임리프 익히기</h1> <p th:text="${today}"></p> <!-- 오늘 날짜 출력 --> <div th:object="${person}"> <!-- person 객체를 선택 --> <p th:text="'이름 : ' + *{name}"></p> <!-- 문자열과 이름을 이어 붙임 --> <p th:text="'나이 : ' + *{age}"></p> <p>취미</p> <ul th:each="hobby : *{hobbies}"> <!-- 취미 개수만큼 반복 --> <li th:text="${hobby}"></li> <span th:if="${hobby == '운동'}">(대표 취미)</span> <!-- 운동일 때만 표시 --> </ul> </div> <a th:href="@{/articles/{id}(id=${person.id})}">글 보기</a> </body> </html>

🎬 애니메이션: 예제 화면 한 줄씩 채워지기

  1. ① 처음에는 빈칸입니다. 아직 데이터가 들어가지 않은 양식입니다.
  2. ② th:text="${today}"가 오늘 날짜를 넣습니다.
  3. ③ th:object로 person을 고른 뒤, *{name}과 *{age}가 이름과 나이를 채웁니다.
  4. ④ th:each로 취미를 반복하고, th:if로 "운동"에만 (대표 취미)를 붙입니다.
  5. ④ th:each로 취미를 반복하고, th:if로 "운동"에만 (대표 취미)를 붙입니다.

▶ 3단계: 실행해서 확인하기

서버를 실행한 뒤 브라우저에서 http://localhost:8080/thymeleaf/example에 접속합니다. 이름, 나이, 취미가 보이면 성공입니다. 화면이 안 나오면 test 폴더에 같은 파일을 잘못 만들었는지 확인하세요.

🧠 확인 퀴즈 4

Q. 반복하기 위해 태그에 붙이는 속성은? 조건이 참일 때만 보이게 하는 속성은?

A. 반복은 th:each, 조건은 th:if입니다.

5. 블로그 글 목록 화면

이제 실제 블로그 목록 화면을 만듭니다. 6장에서 만든 서비스의 findAll()로 글을 가져오고, 화면용 객체로 바꾼 뒤 모델에 담습니다. 그다음 articleList.html에서 글 개수만큼 카드를 반복해서 보여 줍니다.

📝 1단계: 화면용 DTO (ArticleListViewResponse.java)

dto 패키지에 만듭니다. 화면에서 필요한 값만 골라 담는 객체입니다.

package me.yourname.springbootdeveloper.dto; import lombok.Getter; import me.yourname.springbootdeveloper.domain.Article; @Getter // 타임리프가 값을 꺼낼 수 있도록 getter 생성 public class ArticleListViewResponse { private final Long id; // 글 번호 private final String title; // 제목 private final String content; // 내용 public ArticleListViewResponse(Article article) { // 엔티티 한 건을 받아 값을 복사 this.id = article.getId(); this.title = article.getTitle(); this.content = article.getContent(); } }

📝 2단계: 컨트롤러 메서드 (BlogViewController.java)

controller 패키지에 만듭니다. API용 컨트롤러(BlogApiController)와 이름을 나눠서, "화면을 주는 컨트롤러"임을 분명히 합니다.

package me.yourname.springbootdeveloper.controller; import java.util.List; import lombok.RequiredArgsConstructor; import me.yourname.springbootdeveloper.dto.ArticleListViewResponse; import me.yourname.springbootdeveloper.service.BlogService; import org.springframework.stereotype.Controller; import org.springframework.ui.Model; import org.springframework.web.bind.annotation.GetMapping; @RequiredArgsConstructor // 서비스 주입용 생성자 자동 생성 @Controller // 화면을 돌려주는 컨트롤러 (@RestController 아님) public class BlogViewController { private final BlogService blogService; @GetMapping("/articles") // GET /articles 요청 연결 public String getArticles(Model model) { List<ArticleListViewResponse> articles = blogService.findAll() // 전체 글 가져오기 .stream() // 목록을 흐름으로 바꾸기 .map(ArticleListViewResponse::new) // 글 한 건마다 화면용 객체로 변환 .toList(); // 다시 목록으로 모으기 model.addAttribute("articles", articles); // "articles" 이름표로 모델에 담기 return "articleList"; // articleList.html 화면 이름 반환 } }
⚠️ @RestController와 @Controller6장의 API 컨트롤러는 @RestController로 JSON을 돌려줬습니다. 화면을 만드는 이 컨트롤러는 @Controller를 써야 합니다. 두 어노테이션을 헷갈리면 화면 대신 글자 문자열이 나옵니다.

📝 3단계: 목록 화면 (src/main/resources/templates/articleList.html)

7. 생성·수정 시간 자동 기록

글을 언제 썼는지, 언제 고쳤는지는 사람이 직접 입력하지 않아도 자동으로 기록되면 좋습니다. 스프링 데이터 JPA는 이 기능을 Auditing(감사 기록)이라고 부르며, 몇 개의 어노테이션으로 켤 수 있습니다.

📝 1단계: Article 엔티티에 시간 필드 추가

package me.yourname.springbootdeveloper.domain; import jakarta.persistence.*; import java.time.LocalDateTime; import lombok.*; import org.springframework.data.annotation.CreatedDate; import org.springframework.data.annotation.LastModifiedDate; import org.springframework.data.jpa.domain.support.AuditingEntityListener; @EntityListeners(AuditingEntityListener.class) // 저장·수정 때 시간을 채우는 감시자 연결 @Entity @Getter @NoArgsConstructor(access = AccessLevel.PROTECTED) public class Article { @Id @GeneratedValue(strategy = GenerationType.IDENTITY) @Column(name = "id", updatable = false) private Long id; @Column(name = "title", nullable = false) private String title; @Column(name = "content", nullable = false) private String content; @CreatedDate // 처음 저장될 때 현재 시간 기록 @Column(name = "created_at") private LocalDateTime createdAt; @LastModifiedDate // 값이 바뀌어 저장될 때마다 현재 시간 기록 @Column(name = "updated_at") private LocalDateTime updatedAt; // 빌더 생성자, update 메서드 등 기존 코드는 그대로 둡니다 }

📝 2단계: 스프링 부트 시작 클래스에 Auditing 켜기

package me.yourname.springbootdeveloper; import org.springframework.boot.SpringApplication; import org.springframework.boot.autoconfigure.SpringBootApplication; import org.springframework.data.jpa.config.EnableJpaAuditing; @EnableJpaAuditing // created_at, updated_at 자동 기록 기능 켜기 @SpringBootApplication public class SpringBootDeveloperApplication { public static void main(String[] args) { SpringApplication.run(SpringBootDeveloperApplication.class, args); } }

📝 3단계: 테스트 데이터에 시간 넣기 (import.sql)

서버가 켜질 때마다 실행되는 import.sql은 시간 열을 자동으로 채우지 않습니다. 그래서 NOW()로 현재 시간을 직접 넣어 줍니다.

INSERT INTO article (title, content, created_at, updated_at) VALUES ('제목 1', '내용 1', NOW(), NOW()); INSERT INTO article (title, content, created_at, updated_at) VALUES ('제목 2', '내용 2', NOW(), NOW()); INSERT INTO article (title, content, created_at, updated_at) VALUES ('제목 3', '내용 3', NOW(), NOW());

🎬 애니메이션: 저장하면 시간이 자동으로 찍히는 과정

  1. ① 개발자는 save()만 부릅니다. 시간을 직접 계산하지 않습니다.
  2. ② @EntityListeners가 연결한 감시자가 저장 직전에 끼어듭니다.
  3. ③ 감시자가 created_at과 updated_at에 현재 시간을 넣습니다.
  4. ④ 나중에 글을 고치면 updated_at만 다시 기록됩니다. created_at은 그대로입니다.
  5. ④ 나중에 글을 고치면 updated_at만 다시 기록됩니다. created_at은 그대로입니다.

🧩 어노테이션 정리

어노테이션역할
@EnableJpaAuditingAuditing 기능 전체를 켬 (시작 클래스에 붙임)
@EntityListeners(AuditingEntityListener.class)이 엔티티를 감시자가 살펴보게 함
@CreatedDate처음 저장할 때 시간을 기록
@LastModifiedDate저장·수정할 때마다 시간을 기록
🚨 자주 하는 실수@EnableJpaAuditing을 빼면 시간이 전부 null로 남습니다. 두 시간 필드에 붙인 @CreatedDate, @LastModifiedDate는 켜기 전에는 아무 일도 하지 않습니다.
🧠 확인 퀴즈 7

Q. 엔티티 필드 위에 붙여서 마지막으로 수정된 시각을 자동으로 채우는 어노테이션은?

A. @LastModifiedDate입니다. 처음 만든 시각은 @CreatedDate로 채웁니다.

  5. ⑤ 알림 창을 띄우고, location.replace로 목록 화면 주소로 옮겨 갑니다.
  6. ⑤ 알림 창을 띄우고, location.replace로 목록 화면 주소로 옮겨 갑니다.

9. 수정·생성 화면 구분하기

글 입력 화면은 두 가지 역할을 합니다. 기존 글을 고치는 수정과, 빈 화면에서 새 글을 쓰는 생성입니다. 두 경우 모두 같은 화면을 쓰므로, 주소에 번호가 있는지 보고 화면을 나눕니다.

🎬 애니메이션: 같은 화면, 다른 두 길

  1. ① 사용자가 /new-article 주소로 들어옵니다. 같은 화면이지만 목적이 두 가지입니다.
  2. ② 컨트롤러는 주소에 ?id= 값이 있는지 먼저 봅니다.
  3. ③ 없으면 빈 칸과 [등록] 버튼이 있는 생성 화면을 보여 줍니다.
  4. ④ 있으면 그 글을 찾아 채워 넣고 [수정] 버튼이 있는 수정 화면을 보여 줍니다.
  5. ④ 있으면 그 글을 찾아 채워 넣고 [수정] 버튼이 있는 수정 화면을 보여 줍니다.

📝 1단계: 컨트롤러 메서드 (BlogViewController.java)

@GetMapping("/new-article") // /new-article 요청 연결 public String newArticle(@RequestParam(required = false) Long id, Model model) { // id는 주소 ?id=값 에서 가져옴. 없어도 됨 (required = false) if (id == null) { // id가 없으면 새 글 쓰기 model.addAttribute("article", new ArticleViewResponse()); // 빈 객체 전달 } else { // id가 있으면 수정 Article article = blogService.findById(id); // 기존 글 조회 model.addAttribute("article", new ArticleViewResponse(article)); // 채운 객체 전달 } return "newArticle"; // newArticle.html 화면 이름 반환 }
💡 @RequestParam은 무엇?주소 뒤의 ?id=1처럼 물음표 뒤에 붙는 값을 매개변수로 받는 어노테이션입니다. required = false는 "이 값이 없어도 된다"는 뜻입니다.
⚠️ 빈 객체가 필요한 이유생성 화면도 화면 파일에서 article.title을 읽습니다. 값이 없으면 오류가 나므로, 빈 ArticleViewResponse 객체를 넘겨 주는 것입니다. 이 객체에는 ArticleViewResponse()라는 기본 생성자가 필요합니다.

📝 2단계: 화면 파일 (src/main/resources/templates/newArticle.html)

<!DOCTYPE html> <html xmlns:th="http://www.thymeleaf.org"> <head> <meta charset="UTF-8"> <title>블로그 글</title> <link rel="stylesheet" href="https://stackpath.bootstrapcdn.com/bootstrap/4.1.3/css/bootstrap.min.css"> </head> <body> <div class="container mt-5"> <div class="row"> <div class="col-lg-8"> <article> <!-- id가 있으면 값이 들어 있고, 없으면 비어 있음 --> <input type="hidden" id="article-id" th:value="${article.id}"> <header class="mb-4"> <input type="text" class="form-control" placeholder="제목" id="title" th:value="${article.title}"> </header> <section class="mb-5"> <textarea class="form-control h-25" rows="10" placeholder="내용" id="content" th:text="${article.content}"></textarea> </section> <!-- id가 있을 때는 [수정], 없을 때는 [등록] 버튼만 보이게 함 --> <button th:if="${article.id != null}" type="button" id="modify-btn" class="btn btn-primary btn-sm">수정</button> <button th:if="${article.id == null}" type="button" id="create-btn" class="btn btn-primary btn-sm">등록</button> </article> </div> </div> </div> <script src="/js/article.js"></script> </body> </html>

🎬 애니메이션: 같은 화면 안에서 버튼이 나뉘는 과정

  1. ① 두 버튼은 같은 자리에 있지만, 조건에 맞는 한 개만 남습니다.
  2. ② 새 글: id가 없어서 == null 조건이 참이 되고 [등록]이 보입니다.
  3. ③ 기존 글: id가 있어서 != null 조건이 참이 되고 [수정]이 보입니다.
  4. ③ 기존 글: id가 있어서 != null 조건이 참이 되고 [수정]이 보입니다.
📌 hidden 입력칸은 왜 쓰나요?type="hidden"은 화면에 보이지 않지만 자바스크립트가 읽을 수 있는 칸입니다. 수정할 글 번호를 여기에 숨겨 두고 요청을 보낼 때 꺼내 씁니다.
🧠 확인 퀴즈 9

Q. 같은 화면에서 id가 있을 때만 [수정] 버튼을 보이게 하려면 어떤 속성을 씁니까?

A. th:if입니다. 조건 ${article.id != null}이 참일 때만 버튼이 나타납니다.

10. 생성 기능 마무리

새 글 화면에서 [등록]을 누르면 입력한 제목과 내용을 생성 API(POST /api/articles)로 보내야 합니다. 자바스크립트가 입력칸의 값을 읽어 JSON으로 바꾸고, fetch로 보냅니다.

🎬 애니메이션: 입력칸 값이 서버로 가는 길

  1. ① [등록] 버튼을 누르면 자바스크립트가 입력칸을 읽기 시작합니다.
  2. ② 제목과 내용의 값을 꺼냅니다.
  3. ③ 꺼낸 값을 JSON 문자열로 바꿔 POST 요청에 담아 보냅니다.
  4. ④ 6장의 생성 API가 저장하고 201 응답을 돌려줍니다.
  5. ⑤ 응답이 끝나면 알림을 띄우고 목록 화면으로 이동합니다.
  6. ⑤ 응답이 끝나면 알림을 띄우고 목록 화면으로 이동합니다.

📝 자바스크립트 등록 코드 (static/js/article.js에 추가)

// 등록 기능 const createButton = document.getElementById('create-btn'); // ① 등록 버튼 찾기 if (createButton) { createButton.addEventListener('click', event => { // ② 클릭하면 아래 실행 fetch('/api/articles', { // ③ 생성 API 주소로 요청 method: 'POST', // 보내는 방식은 POST headers: { 'Content-Type': 'application/json' // 보내는 내용은 JSON이라고 알려 줌 }, body: JSON.stringify({ // 객체를 JSON 문자열로 바꿈 title: document.getElementById('title').value, // 제목 입력칸의 값 content: document.getElementById('content').value // 내용 입력칸의 값 }) }) .then(() => { // ④ 요청이 끝나면 실행 alert('등록 완료되었습니다.'); location.replace('/articles'); // 목록으로 이동 }); }); }
📌 headers와 bodyheaders는 "이 요청은 JSON입니다"라고 알려 주는 안내문입니다. body는 실제로 보내는 짐입니다. 서버는 안내문을 보고 짐을 어떻게 풀지 정합니다.

🔁 생성 버튼 추가 (articleList.html)

<div class="container"> <!-- 글 등록 화면으로 가는 버튼 --> <button type="button" id="create-btn" th:onclick="|location.href='@{/new-article}'|" class="btn btn-secondary btn-sm mb-3">글 등록</button> <div class="row-6" th:each="item : ${articles}"> ...</div> </div>
⚠️ id 충돌 주의목록 화면의 [글 등록] 버튼 id와 입력 화면의 [등록] 버튼 id가 같은 이름이면 안 됩니다. 이 장에서는 두 화면이 서로 다른 HTML 파일이라 같은 create-btn 이름을 써도 충돌하지 않지만, 한 화면에 두 개를 두면 안 됩니다.
🧠 확인 퀴즈 10

Q. 입력칸의 값을 서버로 보낼 때, 자바스크립트 객체를 JSON 문자열로 바꾸는 함수는?

A. JSON.stringify()입니다.

11. 수정 기능 마무리

수정 화면에서 [수정]을 누르면 바뀐 제목과 내용을 수정 API(PUT /api/articles/{id})로 보냅니다. 생성과 거의 같지만, 주소에 글 번호가 들어가고 메서드가 PUT이라는 점이 다릅니다.

🎬 애니메이션: 수정 버튼 클릭의 흐름

  1. ① 수정 화면에는 글 번호가 숨겨져 있습니다. 이 번호가 주소에 들어갑니다.
  2. ② article.js가 PUT 방식의 요청을 만들고 바뀐 값을 JSON으로 담습니다.
  3. ③ 6장의 수정 API가 해당 글을 찾아 값을 고치고, 바뀐 시간을 기록합니다.
  4. ④ 완료되면 알림을 띄우고 상세 화면으로 돌아갑니다.
  5. ④ 완료되면 알림을 띄우고 상세 화면으로 돌아갑니다.

📝 자바스크립트 수정 코드 (static/js/article.js에 추가)

// 수정 기능 const modifyButton = document.getElementById('modify-btn'); // ① 수정 버튼 찾기 if (modifyButton) { modifyButton.addEventListener('click', event => { // ② 클릭하면 아래 실행 let params = new URLSearchParams(location.search); // 주소의 ?id=값 읽기 준비 let id = params.get('id'); // id 값 꺼내기 fetch(`/api/articles/${id}`, { // ③ 수정 API 주소 (글 번호 포함) method: 'PUT', // 수정은 PUT 방식 headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ title: document.getElementById('title').value, content: document.getElementById('content').value }) }) .then(() => { // ④ 완료 후 실행 alert('수정이 완료되었습니다.'); location.replace(`/articles/${id}`); // 상세 화면으로 이동 }); }); }

🔁 수정 버튼 주소 고치기 (article.html)

<!-- 상세 화면의 [수정] 버튼: 수정 화면 주소에 글 번호를 붙여 이동 --> <button type="button" id="modify-btn" th:onclick="|location.href='@{/new-article?id={articleId}(articleId=${article.id})}'|" class="btn btn-primary btn-sm">수정</button>
💡 PUT과 POST의 차이POST는 "새로 만들어 주세요", PUT은 "이 번호의 것을 고쳐 주세요"라는 뜻입니다. 6장의 REST 규칙에서 배운 메서드 역할 그대로입니다.
🚨 실행 전 꼭 확인수정 API(6장)의 서비스에 @Transactional이 붙어 있어야 변경 감지가 동작합니다. 시간 기록(7.3)이 제대로 되려면 @EnableJpaAuditing도 켜져 있어야 합니다.
🧠 확인 퀴즈 11

Q. 수정 요청과 생성 요청의 HTTP 메서드 차이는? 그리고 수정 요청 주소에는 무엇이 들어갑니까?

A. 수정은 PUT, 생성은 POST입니다. 수정 주소에는 글 번호(id)가 들어갑니다. 예: /api/articles/1

12. 연습문제와 체크리스트

먼저 스스로 풀어 보고, 막히면 정답 보기를 펼치세요.

✏️ 문제 1: 화면을 만드는 도구

HTML 틀의 빈칸에 서버가 준 값을 채워 완성된 화면을 만드는 종류의 도구를 무엇이라고 부르나요?

정답 보기

템플릿 엔진입니다. 스프링에서 많이 쓰는 것이 타임리프입니다.

✏️ 문제 2: 값 출력 속성

화면에 변수 값을 글자로 찍어 보여 줄 때 붙이는 타임리프 속성은? ① th:with ② th:unless ③ th:object ④ th:text ⑤ th:if

정답 보기

④ th:text입니다. (th:with는 변수 정의, th:unless는 거짓일 때 표시, th:object는 객체 선택, th:if는 참일 때 표시입니다.)

✏️ 문제 3: 값을 담는 객체

컨트롤러가 화면(뷰)에 넘길 값들을 담아 두는 객체의 이름은?

정답 보기

모델(Model)입니다. 컨트롤러가 addAttribute로 담고, 뷰가 같은 이름으로 꺼냅니다.

✏️ 문제 4: 시간 자동 기록

글을 처음 저장한 시각과 마지막으로 고친 시각을 자동으로 채우고 싶습니다. 이 기능을 켜려면 시작 클래스에 어떤 어노테이션을 붙여야 할까요?

정답 보기

@EnableJpaAuditing입니다. 엔티티의 @CreatedDate, @LastModifiedDate와 함께 씁니다.

✏️ 문제 5: 목록 반복

글 개수만큼 카드를 반복하는 목록 화면 코드의 빈칸을 채우세요. <div class="card" th:___="item : ${articles}">

정답 보기

th:each입니다.

✏️ 문제 6: 주소와 메서드

글 번호 7번을 수정하는 요청의 HTTP 메서드와 주소를 쓰세요.

정답 보기

PUT /api/articles/7입니다.

💡 도전 과제상세 화면에 "작성일: yyyy년 MM월 dd일" 형식으로 날짜를 다시 보여 주도록 바꿔 보세요. 힌트는 #temporals.format의 형식 글자만 바꾸면 됩니다.
