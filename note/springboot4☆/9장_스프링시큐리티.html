레슨 3

👤 회원 도메인 만들기

💡 왜 필요한가요?

스프링 시큐리티가 인증 객체로 사용할 수 있도록 UserDetails 인터페이스를 구현한 User 클래스를 만듭니다[cite: 2].

📄 domain/User.java
domain/User.java
@Table(name = "users")
@NoArgsConstructor(access = AccessLevel.PROTECTED)
@Getter
@Entity
public class User implements UserDetails {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    @Column(name = "email", nullable = false, unique = true)
    private String email;
    @Column(name = "password")
    private String password;

    @Override
    public String getUsername() { return email; }
    @Override
    public String getPassword() { return password; }
    // 기타 UserDetails 필수 오버라이드 메서드 생략 (true 반환)
}

🛠️ 미션 3: 도메인 및 레포지토리 만들기

  1. User.java와 UserRepository.java를 생성합니다[cite: 2].
레슨 4

⚙️ 서비스 계층 만들기

💡 왜 필요한가요?

DB에서 사용자 정보를 가져오는 UserDetailsService 구현체를 작성합니다[cite: 2].

📄 service/UserDetailService.java
service/UserDetailService.java
@RequiredArgsConstructor
@Service
public class UserDetailService implements UserDetailsService {
    private final UserRepository userRepository;
    @Override
    public UserDetails loadUserByUsername(String email) {
        return userRepository.findByEmail(email)
                .orElseThrow(() -> new IllegalArgumentException(email));
    }
}

레슨 5

🛡️ 시큐리티 설정하기

💡 왜 필요한가요?

URL별 접근 권한, 로그인 페이지, 로그아웃, 비밀번호 암호화 방식을 한 곳에서 설정합니다[cite: 2].

📄 config/WebSecurityConfig.java
config/WebSecurityConfig.java
@Configuration @EnableWebSecurity @RequiredArgsConstructor
public class WebSecurityConfig {
    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        return http
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/login", "/signup", "/user").permitAll()
                .anyRequest().authenticated())
            .formLogin(form -> form.loginPage("/login").defaultSuccessUrl("/articles"))
            .logout(logout -> logout.logoutSuccessUrl("/login").invalidateHttpSession(true))
            .csrf(AbstractHttpConfigurer::disable)
            .build();
    }
    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }
}

레슨 6

📝 회원가입 구현하기

💡 왜 필요한가요?

회원가입 폼 데이터를 받아 비밀번호를 BCrypt로 암호화한 뒤 DB에 저장하는 로직을 구현합니다[cite: 2].

📄 service/UserService.java & controller/UserApiController.java
service/UserService.java
@RequiredArgsConstructor @Service
public class UserService {
    private final UserRepository userRepository;
    private final PasswordEncoder passwordEncoder;

    public Long save(AddUserRequest dto) {
        return userRepository.save(User.builder()
                .email(dto.getEmail())
                .password(passwordEncoder.encode(dto.getPassword()))
                .build()).getId();
    }
}

🛠️ 미션 6: 회원가입 API 구현

  1. AddUserRequest, UserService, UserApiController를 작성합니다[cite: 2].

레슨 8 (핵심 요약)

🔍 파일별 코드 실행 흐름 완벽 추적기

💡 비전공자가 가장 많이 멘붕오는 구간 완벽 해결!

화면 띄우기부터 DB 처리까지 어떤 파일이 먼저 실행되는지 헷갈리시죠? 아래 탭을 눌러 우리가 직접 짠 코드(회원가입)와 스프링 시큐리티가 가로채는 코드(로그인)의 차이와 내부 동작을 확인하세요.

📝 회원가입 흐름
(내가 작성한 코드 100% 실행)
🔑 로그인 흐름
(시큐리티 내부 동작 포함!)
1
📄 UserViewController.java
사용자가 주소창에 http://localhost:8080/signup을 입력하면 컨트롤러가 요청을 받아 signup.html을 띄웁니다[cite: 2].
2
📄 signup.html
사용자가 이메일과 비밀번호를 입력하고 [Submit]을 누릅니다. (`POST /user` 요청 발생)[cite: 2]
3
📄 UserApiController.java
POST /user 요청이 들어오면 AddUserRequest 바구니에 담겨 컨트롤러로 전달되며, userService.save()를 호출합니다[cite: 2].
4
📄 UserService.java
비밀번호 암호화가 일어납니다. 평문 비밀번호를 BCryptPasswordEncoder로 해시 처리한 뒤 UserRepository를 통해 DB에 저장합니다[cite: 2].
1
📄 UserViewController.java
/login 접속 시 컨트롤러가 return "login";을 실행해 로그인 화면을 띄웁니다[cite: 2].
2
📄 login.html
사용자가 아이디와 비밀번호를 입력하고 [Submit]을 누릅니다. (`POST /login` 요청)[cite: 2]
3
📄 WebSecurityConfig.java 시큐리티가 낚아챔!
우리 코드에는 @PostMapping("/login")이 없습니다! UsernamePasswordAuthenticationFilter가 이 요청을 공중에서 낚아챕니다[cite: 2].
🕵️
⚙️ [숨은 로직] 매니저와 실무자
필터는 가로챈 아이디/비번을 인증 매니저(AuthenticationManager)에게 넘기고, 매니저는 DB 조사를 전담하는 실무자 인증 제공자(DaoAuthenticationProvider)에게 일을 맡깁니다[cite: 2].
4
📄 UserDetailService.java
실무자(인증 제공자)가 우리가 만든 이 파일의 loadUserByUsername() 메서드를 자동으로 호출하여 DB에서 유저 정보를 가져옵니다[cite: 2].
5
🛡️ [숨은 로직] 비밀번호 비교 & 금고 보관
실무자가 PasswordEncoder.matches(내가_친_비번, DB_암호화_비번)을 실행해 일치하는지 비교합니다. 일치하면 인증 도장을 찍어 SecurityContextHolder(세션 금고)에 보관합니다[cite: 2]!
6
🔄 브라우저 이동
인증 성공 시 설정된 .defaultSuccessUrl("/articles") 경로로 이동합니다[cite: 2].
