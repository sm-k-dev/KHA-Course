📝 새 글 등록 → 🪣 S3 버킷 업로드
코드가 움직이는 순서, 30단계 애니메이션

글쓰기 화면에서 이미지를 고르는 순간부터, S3 버킷 콘솔에 파일이 보일 때까지 따라갑니다.

왼쪽에는 실제 프로젝트 코드가, 오른쪽에는 그 코드가 하는 일이 움직이는 그림으로 나옵니다.

0. 전체 지도와 용어

💡 왜 이 흐름을 알아야 하나요? 배포 서버(일래스틱 빈스톡)는 다시 배포하면 디스크 파일이 사라집니다.
그래서 이미지는 모든 서버가 함께 쓰는 S3에 올립니다.
오류가 나면 "몇 번째 단계에서 멈췄는지"를 알아야 고칠 수 있습니다.

큰 그림: 요청은 2번 갑니다

전체 흐름 요약

① 이미지 고를 때 — POST /api/upload

article.js → 토큰 검사 필터 → UploadController → AwsS3Service → S3 버킷에 파일 저장 → 주소(URL) 돌려받음

② [등록] 누를 때 — POST /api/articles

article.js → 토큰 검사 필터 → BlogApiController → BlogService → DB에 글 + 이미지 주소 저장

핵심: 이미지 파일은 ①에서 이미 S3에 올라갑니다. ②에서는 주소 글자만 DB에 저장합니다.

그림은 흐름을 요약한 예시입니다.

용어를 생활 비유로

🪣 S3 버킷인터넷에 있는 대형 창고입니다. 이 프로젝트의 창고 이름은 blog-tlstkdrnr4671입니다.
🏷️ 키(key)창고 안 물건의 위치표입니다. 예: uploads/3f2a….png
🧰 빈(Bean)스프링이 미리 만들어 공구함에 넣어 둔 객체입니다. 필요한 곳에 꺼내 줍니다.
🎭 프로파일(Profile)"오늘의 근무 모드"입니다. local이면 내 PC 저장, 없으면 S3 저장입니다.
🎫 액세스 토큰놀이공원 손목 팔찌입니다. /api/** 문을 지날 때마다 검사합니다.
🔑 IAM 역할EC2 서버에 걸어 둔 "창고 출입증"입니다. 이게 있어야 S3에 넣을 수 있습니다.
📜 버킷 정책창고 정문 안내문입니다. "uploads/ 물건은 누구나 구경 가능"이라고 적혀 있습니다.
📦 multipart택배 상자 여러 칸에 파일과 값을 나눠 담아 보내는 방식입니다.

🧠 퀴즈 1

AwsS3Service가 키를 "uploads/" + UUID + "." + ext로 만드는 가장 중요한 이유 두 가지는?

정답은 3번입니다. UUID는 매번 다른 이름이라 덮어쓰기를 막습니다. 버킷 정책의 Resource가 …/uploads/*라서 이 경로 아래 파일만 브라우저가 읽을 수 있습니다.

2. 관련 코드 전체 보기

💡 왜 전체 코드를 따로 보나요? 애니메이션은 "실행되는 줄"만 강조합니다. 여기서는 각 파일을 처음부터 끝까지 읽을 수 있습니다.
모두 C:\Blog 프로젝트의 실제 파일 내용 그대로입니다. 일부 큰 파일은 관련 부분만 원래 줄 번호와 함께 보여줍니다.
흐름 순서대로 정렬했습니다. 제목을 누르면 펼쳐집니다. 각 파일의 [복사] 버튼으로 내용을 복사할 수 있습니다.

🧠 퀴즈 2

인텔리제이에서 활성화된 프로파일을 local로 실행하면 이미지는 어디에 저장될까요?

정답은 1번입니다. @Profile("local")인 LocalFileStorageService만 빈으로 등록됩니다. AwsS3Service는 @Profile("!local")이라 빠집니다. 그래서 S3 흐름은 배포 서버(프로파일 없음)에서 동작합니다.

3. 버킷에 올라갔는지 직접 확인

💡 왜 확인하나요? 화면에 미리보기가 떴다면 업로드는 성공입니다. 하지만 "어디에, 어떤 이름으로" 들어갔는지 직접 보면 흐름이 머리에 남습니다.
  1. 배포된 블로그에서 글쓰기 화면을 엽니다. 로그인 후 /new-article로 이동합니다.
    예: http://(빈스톡 환경 주소)/new-article
  2. F12 → [Network(네트워크)] 탭을 열고 이미지를 고릅니다. 목록에 upload가 생깁니다. 눌러서 [Response(응답)]를 봅니다.
    ✅ 이렇게 나오면 성공 — 상태 201, 응답에 https://…amazonaws.com/uploads/ 주소가 있음 
    {"imageUrl":"https://blog-tlstkdrnr4671.s3.ap-northeast-2.amazonaws.com/uploads/3f2a9c1e-7b4d-4e2a-9f1c-0d8e5b6a2c41.png"}
  3. AWS 콘솔에서 확인합니다. S3 → 버킷 blog-tlstkdrnr4671 → uploads/ 폴더를 엽니다.
    ✅ 이렇게 나오면 성공 — 방금 시간으로 된 .png(또는 .jpg) 파일이 목록 맨 위(정렬 시)에 있음
  4. (선택) AWS CLI가 설치된 PC라면 터미널에서 확인합니다. 버킷의 uploads 목록을 봅니다. 
    aws s3 ls s3://blog-tlstkdrnr4671/uploads/
    ✅ 이렇게 나오면 성공 — 날짜·크기·UUID 파일 이름 한 줄씩 (아래는 예시) 
    2026-11-04 14:15:07     245812 3f2a9c1e-7b4d-4e2a-9f1c-0d8e5b6a2c41.png
  5. (선택) 저장된 콘텐츠 유형을 확인합니다. <파일이름> 자리에 위 목록의 이름을 넣습니다. 
    aws s3api head-object --bucket blog-tlstkdrnr4671 --key uploads/<파일이름>
    실제 예시: aws s3api head-object --bucket blog-tlstkdrnr4671 --key uploads/3f2a9c1e-7b4d-4e2a-9f1c-0d8e5b6a2c41.png
    ✅ 이렇게 나오면 성공 — "ContentType": "image/png" 가 보임 (예시) 
    {
    "LastModified": "2026-11-04T05:15:07+00:00",
    "ContentLength": 245812,
    "ETag": "\"9b2cf535f27731c974343645a3985328\"",
    "ContentType": "image/png",
    ...
}
  6. (선택) 누구나 읽을 수 있는지 확인합니다. 윈도우 PowerShell에서는 curl이 다른 명령이라 curl.exe로 씁니다. 
    curl.exe -I https://blog-tlstkdrnr4671.s3.ap-northeast-2.amazonaws.com/uploads/<파일이름>
    ✅ 이렇게 나오면 성공 — 첫 줄 200 OK, Content-Type: image/png (예시) 
    HTTP/1.1 200 OK
Content-Type: image/png
Content-Length: 245812
Server: AmazonS3
⚠️ CLI에서 Unable to locate credentials가 나오면 내 PC에 AWS 키가 설정되지 않은 것입니다. CLI 확인은 선택 사항이니 콘솔(3번)로 확인하면 됩니다. 키 설정이 필요하면 아래를 실행해 안내에 따라 입력합니다. 
aws configure

※ CLI 출력은 AWS 공식 형식을 따른 예시입니다. 날짜·크기·ETag 값은 환경마다 다릅니다.

🧠 퀴즈 3

curl.exe -I로 이미지 주소를 열었더니 403 Forbidden이 나왔습니다. 가장 먼저 볼 곳은?

4. 자주 나는 오류와 해결

💡 왜 미리 알아두나요? 아래 오류는 위 30단계 중 특정 단계에서 납니다. 단계 번호를 함께 적었습니다. 플레이어에서 그 단계를 다시 보면 원인이 보입니다.
⚠️ 1) 업로드 시 500 오류, 로그에 403 AccessDenied … not authorized to perform: s3:PutObject — 18단계
EC2 출입증(IAM 역할)에 S3 권한이 없습니다. 콘솔: IAM → 역할 → aws-elasticbeanstalk-ec2-role → 권한 추가 → 정책 연결 → AmazonS3FullAccess.
CLI로 하려면 (관리자 권한 키가 설정된 PC에서): 
aws iam attach-role-policy --role-name aws-elasticbeanstalk-ec2-role --policy-arn arn:aws:iam::aws:policy/AmazonS3FullAccess
✅ 성공 시 출력 없이 끝납니다. 다시 업로드하면 201이 옵니다.
⚠️ 2) 업로드는 됐는데 미리보기 이미지가 깨짐 (이미지 주소가 403) — 22단계
버킷 정책이 없거나, "모든 퍼블릭 액세스 차단"이 켜져 있습니다. 버킷 → 권한 → 버킷 정책에 아래를 저장합니다. 
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PublicReadUploads",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::blog-tlstkdrnr4671/uploads/*"
    }
  ]
}
✅ 저장 후 이미지 주소를 새 탭에서 열면 그림이 보입니다.
⚠️ 3) 1MB가 넘는 사진만 업로드 실패 (MaxUploadSizeExceededException) — 12단계
스프링 부트는 기본으로 파일 1개당 1MB까지만 받습니다. 현재 application.yaml에 크기 설정이 없습니다. 이미 있는 spring: 바로 아래에 두 칸 들여 붙입니다. (spring:을 하나 더 만들면 안 됩니다) 
  servlet:
    multipart:
      max-file-size: 10MB
      max-request-size: 10MB
✅ 다시 배포 후 2~5MB 사진이 201로 올라가면 성공입니다.
⚠️ 4) 업로드 시 "이미지 업로드에 실패했습니다." 알림 + Network에 401 — 9~11단계
액세스 토큰이 만료됐습니다. 글 등록은 httpRequest()가 토큰을 다시 받아 오지만, 이미지 업로드는 fetch를 직접 써서 재발급을 하지 않습니다. 다시 로그인하면 해결됩니다. 근본적으로는 업로드도 재발급 흐름을 타도록 고치는 것이 좋습니다.
⚠️ 5) 서버가 안 뜨고 NoUniqueBeanDefinitionException 또는 NoSuchBeanDefinitionException — 4단계
FileStorageService 구현이 2개 등록됐거나 0개입니다. @Profile("local")과 @Profile("!local")이 정확히 반대인지 확인합니다.
⚠️ 6) (참고) .jpg 파일의 콘텐츠 유형이 image/jpg로 저장됨 — 16단계
코드가 "image/" + ext로 만들기 때문입니다. 표준 이름은 image/jpeg입니다. 대부분 브라우저는 그대로 보여주지만, 정확히 하려면 jpg를 jpeg로 바꿔 주면 됩니다.

🧠 퀴즈 4

내 PC에서 ./gradlew build를 하면 AWS 키가 없는데도 S3Client 빈 생성이 실패하지 않는 이유는?

정답은 1번입니다. DefaultCredentialsProvider는 요청을 보낼 때 ①~⑥ 순서로 키를 찾습니다. 그래서 빈 생성 시점에는 오류가 나지 않습니다.

5. 최종 점검

💡 아래 순서를 보지 않고 말할 수 있으면 완주입니다.
#누가무엇을
1S3Config서버 시작 때 S3Client 빈을 1개 만든다 (리전 ap-northeast-2)
2article.js파일 선택 → FormData('file') → POST /api/upload + Bearer 토큰
3TokenAuthenticationFilter토큰 검사 → SecurityContext에 사용자 저장 → /api/** 통과
4UploadControllerMultipartFile에서 bytes·원래 이름을 꺼내 store() 호출
5AwsS3Service확장자 → 키(uploads/UUID.ext) → PutObjectRequest → putObject → getUrl
6S3IAM 역할 임시 키로 서명된 PUT을 받아 파일 저장
7article.js201 응답의 imageUrl을 숨은 칸에 넣고 미리보기(S3에서 직접 GET)
8article.js → BlogService[등록] → POST /api/articles → Article.imageUrl에 주소 저장 → INSERT
