0. 1장 지도

이 장은 백엔드(Backend)가 무엇인지 처음부터 그려 보는 장입니다. 우리가 웹사이트에서 글을 쓰고 저장 버튼을 누르면, 그 뒤에서 어떤 일이 일어나는지 순서대로 따라갑니다.

가장 먼저 기억할 그림은 세 개의 상자입니다. 사용자가 쓰는 화면(클라이언트), 요청을 처리하는 프로그램(서버), 데이터를 오래 보관하는 창고(데이터베이스)입니다. 이 장을 마치면 세 상자가 어떻게 말을 주고받는지 설명할 수 있습니다.

🎬 애니메이션: 요청 한 번이 지나가는 길

  1. 이 장의 큰 그림입니다. 세 상자가 요청과 응답을 주고받습니다.
  2. 1단계: 클라이언트가 서버에 요청을 보냅니다.
  3. 2단계: 서버가 데이터베이스에서 필요한 데이터를 찾습니다.
  4. 3단계: 데이터베이스가 찾은 데이터를 서버에 돌려줍니다.
  5. 4단계: 서버가 응답을 만들어 클라이언트에 보내고, 화면에 결과가 보입니다.

1. 클라이언트와 서버

클라이언트(Client)는 무엇인가를 요청(Request)하는 쪽입니다. 웹 브라우저, 스마트폰 앱이 대표적입니다. 서버(Server)는 그 요청을 받아 처리(Process)하고 결과를 돌려주는 쪽입니다. 백엔드는 주로 서버 쪽에서 일어나는 일을 가리킵니다.

한 가지 기억할 점은, 클라이언트와 서버가 항상 다른 컴퓨터에 있을 필요는 없다는 것입니다. 개발할 때는 내 컴퓨터 한 대에서 브라우저와 서버 프로그램을 함께 실행하기도 합니다.

🎬 애니메이션: 요청과 응답의 왕복

  1. 클라이언트와 서버는 요청과 응답을 주고받는 한 쌍입니다.
  2. 1단계: 클라이언트가 서버에게 요청을 보냅니다.
  3. 2단계: 서버가 요청을 받아 처리 중입니다.
  4. 3단계: 서버가 결과를 응답으로 돌려주고, 클라이언트가 받습니다.
구분클라이언트서버
하는 일사용자에게 화면을 보여 주고 요청을 보냄요청을 받아 확인하고, 데이터를 찾거나 저장함
예시브라우저, 모바일 앱글 목록을 만들어 주는 백엔드 프로그램
사용자가 보나?예, 화면으로 보임아니요, 뒤에서 조용히 일함
📌 예시로 생각해 보기메모 앱에서 "저장" 버튼을 누르면, 앱(클라이언트)은 "이 내용을 저장해 주세요"라는 요청을 보냅니다. 서버는 내용을 확인하고 저장한 뒤 "저장 완료"라는 응답을 돌려줍니다.
⚠️ 자주 하는 오해"서버는 큰 컴퓨터여야 한다"는 생각은 틀렸습니다. 서버는 역할의 이름입니다. 내 노트북에서 실행하는 프로그램도 요청을 받으면 서버가 됩니다.
🧠 확인 퀴즈 1

Q. 클라이언트와 서버 중 요청을 받아 처리하는 쪽은 어느 쪽인가요?

A. 서버입니다. 클라이언트는 요청을 보내고 결과를 화면에 보여 주는 쪽입니다.

2. 요청과 응답의 구조

요청(Request)과 응답(Response)은 정해진 모양의 메시지입니다. 사람이 편지를 쓸 때 첫 줄에 받는 사람을 적고, 다음에 부가 정보를 적고, 마지막에 본문을 쓰는 것과 비슷합니다. 컴퓨터끼리도 이런 규칙을 정해 두고 주고받습니다.

🎬 애니메이션: 요청 메시지를 한 줄씩 읽기

  1. 요청 메시지는 네 부분으로 나뉩니다. 오른쪽 설명과 함께 보세요.
  2. 1단계: 시작 줄은 무엇을(메서드)과 어디에(주소)를 알려 줍니다.
  3. 2단계: 헤더는 보내는 데이터의 형식 같은 부가 정보를 담습니다.
  4. 3단계: 빈 줄은 헤더가 끝났다는 표시입니다.
  5. 4단계: 본문에는 실제로 전달할 데이터가 들어갑니다.

요청 예시 (메모 저장)

POST /memos HTTP/1.1 Host: localhost:8080 Content-Type: application/json {"title": "장보기", "content": "우유, 계란"}

응답 예시 (저장 완료)

HTTP/1.1 201 Created Content-Type: application/json {"id": 1, "title": "장보기", "content": "우유, 계란"}
부분요청에서의 역할응답에서의 역할
시작 줄메서드, 주소, 버전버전, 상태 코드와 설명
헤더보내는 데이터의 형식 등받는 데이터의 형식 등
본문보낼 데이터돌려줄 데이터
📌 Content-Type 헤더이 헤더는 "본문이 어떤 형식인지" 알려 줍니다. JSON이라면 application/json이라고 씁니다. 받는 쪽은 이 값을 보고 본문을 올바르게 해석합니다.
🧠 확인 퀴즈 2

Q. 요청 메시지에서 실제 전달할 데이터는 어느 부분에 들어가나요?

A. 본문(Body)입니다. 헤더는 본문에 대한 부가 정보를 담습니다.

3. HTTP 메서드

HTTP 메서드(Method)는 요청이 무엇을 하고 싶은지를 알려 주는 단어입니다. 메모 앱을 예로 들면, 목록을 보고 싶은지, 새로 쓰고 싶은지, 고치고 싶은지, 지우고 싶은지를 메서드로 나타냅니다.

이 네 가지를 CRUD라고 줄여 부르기도 합니다. CRUD는 Create(생성), Read(조회), Update(수정), Delete(삭제)의 첫 글자를 딴 말입니다.

🎬 애니메이션: 메서드가 하는 일 비교

  1. 메서드는 같은 주소라도 하는 일을 바꿉니다. 아래 네 줄을 비교해 보세요.
  2. 1단계: GET은 데이터를 읽기만 합니다.
  3. 2단계: POST는 새 데이터를 만들어 저장합니다.
  4. 3단계: PUT은 기존 데이터를 고칩니다.
  5. 4단계: DELETE는 기존 데이터를 지웁니다.
메서드CRUD메모 앱에서의 뜻성공 시 대표 상태 코드
GETRead목록 또는 한 개 조회200 OK
POSTCreate새 메모 저장201 Created
PUTUpdate기존 메모 수정200 OK
DELETEDelete기존 메모 삭제200 OK 또는 204 No Content
⚠️ 주의GET은 데이터를 바꾸지 않아야 합니다. "조회 버튼을 눌렀더니 데이터가 지워졌다"면 설계가 잘못된 것입니다. 바꾸는 일은 POST, PUT, DELETE로 합니다.
📌 주소와 메서드는 한 쌍같은 주소 /memos/3이라도 GET이면 조회, DELETE면 삭제입니다. 주소는 "대상"을, 메서드는 "동작"을 나타냅니다.
🧠 확인 퀴즈 3

Q. 메모를 새로 저장하고 싶을 때 가장 어울리는 메서드는 무엇인가요?

A. POST입니다. POST는 새 데이터를 만들 때 주로 사용합니다.

4. 상태 코드

상태 코드(Status Code)는 서버가 "이 요청의 결과가 어떤지"를 숫자 세 자리로 알려 주는 표시입니다. 숫자의 첫 자리가 큰 분류를 나타냅니다.

🎬 애니메이션: 같은 서버, 다른 결과

  1. 같은 서버라도 요청 결과에 따라 상태 코드가 달라집니다.
  2. 1단계: 200은 성공입니다. 요청이 정상적으로 끝났습니다.
  3. 2단계: 404는 주소를 찾지 못했다는 뜻입니다. 주소 오타를 먼저 의심합니다.
  4. 3단계: 500은 서버 내부 오류입니다. 서버 로그를 확인해야 합니다.
첫 자리분류대표 예뜻
2xx성공200, 201요청이 정상 처리됨
3xx이동301, 302다른 주소로 옮겨졌음
4xx요청 쪽 문제400, 401, 403, 404요청 내용이나 권한을 확인해야 함
5xx서버 쪽 문제500, 503서버가 처리에 실패함
📌 자주 나오는 네 가지200 OK(성공), 201 Created(새로 만듦 성공), 401 Unauthorized(로그인 필요), 404 Not Found(주소 없음). 4장과 11장에서 다시 만납니다.
🧠 확인 퀴즈 4

Q. 주소를 잘못 입력했을 때 보통 받게 되는 상태 코드는 무엇인가요?

A. 404 Not Found입니다. 요청한 주소에 해당하는 자원이 없다는 뜻입니다.

5. 주소(URL) 읽는 법

웹 주소(URL)는 "어떤 규칙으로, 어느 컴퓨터의, 어느 프로그램에게, 무엇을 달라고 할지"를 한 줄에 담은 것입니다. 주소를 읽을 줄 알면 요청이 어디로 가는지 바로 짐작할 수 있습니다.

🎬 애니메이션: 주소를 다섯 조각으로 나누기

아래 주소에서 각 조각이 무엇을 뜻하는지 단계마다 확인해 보세요.

https://shop.example.com:8443/items/search?keyword=apple
  1. 예제 주소입니다. 다섯 조각으로 나누어 봅니다.
  2. 1단계: https는 프로토콜입니다. 통신 규칙을 정합니다.
  3. 2단계: shop.example.com은 도메인입니다. 찾아갈 컴퓨터의 이름입니다.
  4. 3단계: 8443은 포트입니다. 그 컴퓨터의 어느 프로그램인지 가리킵니다.
  5. 4단계: /items/search는 경로입니다. 어떤 기능을 쓸지 나타냅니다.
  6. 5단계: ?keyword=apple은 쿼리 문자열입니다. 조건 값을 전달합니다.
조각예생략 가능?
프로토콜https://브라우저가 보통 자동으로 붙입니다
도메인shop.example.com필수
포트:8443https는 443, http는 80이 기본이라 보통 생략합니다
경로/items/search없으면 메인 화면으로 봅니다
쿼리?keyword=apple조건이 없으면 생략합니다
⚠️ 쿼리는 주소에 보입니다?password=1234처럼 민감한 정보를 쿼리에 넣으면 주소창과 기록에 그대로 남습니다. 비밀번호는 본문에 담아 보내야 합니다.
🧠 확인 퀴즈 5

Q. 주소에서 컴퓨터 이름에 해당하는 조각은 무엇인가요?

A. 도메인입니다. 예를 들어 shop.example.com이 그 컴퓨터의 이름입니다.

6. IP 주소와 포트

IP 주소는 네트워크 위에서 컴퓨터 한 대를 찾는 번호입니다. 예를 들어 127.0.0.1은 "지금 내가 쓰는 이 컴퓨터"를 뜻하고, 이름으로는 localhost라고 씁니다.

포트(Port)는 컴퓨터 한 대 안에서 프로그램 하나를 찾는 번호입니다. 한 컴퓨터에 웹 서버, 데이터베이스, 메신저가 동시에 떠 있을 수 있으므로, 번호로 구분합니다. 번호는 0부터 65535까지 있습니다.

🎬 애니메이션: 주소 → 컴퓨터 → 프로그램

  1. IP는 컴퓨터를, 포트는 그 안의 프로그램을 찾습니다.
  2. 1단계: 요청은 먼저 IP 주소로 컴퓨터를 찾아갑니다.
  3. 2단계: 컴퓨터 안에는 여러 프로그램이 있고, 포트 번호로 구분합니다.
  4. 3단계: localhost:8080 요청은 포트 8080의 백엔드 프로그램에 도착합니다.
번호자주 보는 용도
80HTTP 일반 웹 (주소에서 보통 생략)
443HTTPS 보안 웹 (주소에서 보통 생략)
3306MySQL 데이터베이스
8080개발할 때 스프링 부트 서버에서 자주 쓰는 번호
📌 같은 포트는 동시에 못 씁니다이미 8080을 쓰는 프로그램이 있으면 새 서버는 8080으로 뜨지 못합니다. 이때는 다른 번호를 쓰거나, 먼저 떠 있는 프로그램을 끕니다.
🧠 확인 퀴즈 6

Q. 내 컴퓨터 안에서 프로그램을 구분하는 번호는 무엇인가요?

A. 포트 번호입니다. IP는 컴퓨터를, 포트는 프로그램을 찾습니다.

7. 백엔드가 하는 일

백엔드 서버는 요청 하나를 받으면 대개 다섯 단계를 거칩니다. 이 순서는 이후 장에서 배우는 스프링 부트의 컨트롤러 → 서비스 → 리포지터리와 같은 흐름으로 이어집니다.

🎬 애니메이션: 요청 하나의 여정

  1. 요청 하나가 서버 안에서 다섯 단계를 지나갑니다.
  2. 1단계: 요청을 받습니다. 주소와 메서드를 먼저 확인합니다.
  3. 2단계: 입력값이 올바른지 확인합니다. 예: 제목이 비어 있지 않은지.
  4. 3단계: 데이터베이스에서 찾거나 저장합니다.
  5. 4단계: 응답에 담을 결과를 만듭니다.
  6. 5단계: 상태 코드와 함께 응답을 보내고 끝납니다.
단계메모 앱 예시

8. 데이터베이스 기초

데이터베이스(Database, DB)는 데이터를 오래 보관하고, 필요할 때 찾아 쓸 수 있게 정리해 둔 저장소입니다. 대부분의 데이터베이스는 표(Table) 모양으로 데이터를 담습니다.

용어뜻예
테이블(Table)같은 종류의 데이터를 모아 둔 표users 표
열(Column)항목 하나. 세로 칸name, email
행(Row)데이터 한 건. 가로 줄민수 한 명의 기록
기본키(Primary Key)행을 하나로 구별하는 값id 열

🎬 애니메이션: 표 하나가 만들어지는 순서

  1. 표는 제목, 열 이름, 데이터 행 순서로 이해하면 쉽습니다.
  2. 1단계: 열 이름을 정합니다. id, name, email이 세로 칸입니다.
  3. 2단계: 행을 쌓습니다. 한 줄이 한 사람의 기록입니다.
  4. 3단계: id 열은 행마다 다른 값을 가져 기본키가 됩니다.
⚠️ 기본키는 겹치면 안 됩니다id가 1인 사람이 두 명이면 "1번 회원"을 찾을 수 없습니다. 그래서 데이터베이스는 기본키 값이 중복되지 않도록 막아 줍니다.
🧠 확인 퀴즈 8

Q. 행을 하나로 구별하는 기본키의 특징은 무엇인가요?

A. 같은 표 안에서 값이 중복되지 않는다는 것입니다.

9. 관계형 DB와 NoSQL

데이터베이스는 크게 관계형(RDB)과 NoSQL로 나눕니다. 이 책은 스프링 부트와 함께 자주 쓰는 관계형 데이터베이스를 중심으로 다룹니다.

🎬 애니메이션: 두 방식의 차이

  1. 두 방식은 데이터를 담는 모양이 다릅니다.
  2. 1단계: 관계형 DB는 표를 기준으로 데이터를 정리하고 SQL로 다룹니다.
  3. 2단계: NoSQL은 정해진 표 없이 문서나 키-값 형태로 저장하는 경우가 많습니다.
비교관계형 DB (RDB)NoSQL
데이터 모양표(행과 열)문서, 키-값, 그래프 등
구조 변경미리 정한 틀이 있어 변경이 신중함유연하게 바꾸기 쉬움
조회 방법SQL제품마다 다른 방식
대표 제품MySQL, PostgreSQL, MariaDBMongoDB, Redis
잘 맞는 곳회원, 주문처럼 관계가 뚜렷한 데이터대량 로그, 빠른 임시 저장
📌 SQL이란?SQL(Structured Query Language)은 관계형 데이터베이스에 "이 데이터를 찾아 줘"라고 말하는 공통 언어입니다. 5장에서 직접 써 봅니다.
🧠 확인 퀴즈 9

Q. 표(행과 열)를 기준으로 데이터를 저장하고 SQL로 다루는 방식은 무엇인가요?

A. 관계형 데이터베이스(RDB)입니다.
