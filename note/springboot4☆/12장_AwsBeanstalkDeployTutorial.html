준비배포 완료

레슨 0시작 전 준비와 전체 구조

💡 왜 하나요?

지금까지는 내 PC에서만 서버를 실행했습니다. 다른 사람이 휴대폰으로 접속하려면 인터넷에 연결된 서버에 프로젝트를 올려야 합니다. 이 작업을 배포라고 합니다.

이번 실습에서 쓰는 AWS 서비스

리전(Region)
AWS 데이터센터가 있는 지역입니다. 이번 실습은 모두 아시아 태평양(서울) ap-northeast-2에서 합니다.
EC2
AWS가 빌려주는 가상 서버 컴퓨터입니다. 스프링 부트 jar 파일이 여기서 실행됩니다.
RDS
AWS가 관리해 주는 데이터베이스 서버입니다. 이번 실습은 MySQL 8.0을 씁니다.
S3
파일을 저장하는 AWS 저장소입니다. 블로그에 올린 이미지가 저장됩니다. 저장소 1개를 버킷이라고 부릅니다.
IAM
AWS 안에서 누가 무엇을 할 수 있는지 정하는 권한 관리 서비스입니다. 역할(Role)은 권한 묶음입니다.
일래스틱 빈스톡
EC2·RDS·보안 그룹 등을 한 화면에서 만들고 jar 파일을 올려 실행해 주는 서비스입니다.

🧠 퀴즈

스프링 부트 jar 파일이 실제로 실행되는 AWS 서비스는 무엇인가요?

jar 파일은 가상 서버인 EC2에서 java -jar 명령으로 실행됩니다. RDS는 데이터베이스, S3는 파일 저장소입니다.

레슨 1IAM 역할 2개 만들기

💡 왜 하나요?

빈스톡이 EC2를 만들고 관리하려면 권한이 필요합니다. 권한 묶음인 역할을 미리 2개 만들어 둡니다.

역할 이름누가 쓰나요사용 사례
aws-elasticbeanstalk-instance-role빈스톡이 만든 EC2 서버Elastic Beanstalk - Compute
elasticbeanstalk-service-role빈스톡 서비스 자신Elastic Beanstalk - Environment

① EC2용 역할

  1. 상단 검색창에 IAM을 입력해 들어갑니다.
  2. 왼쪽 메뉴 역할 → 역할 생성을 누릅니다.
  3. 신뢰할 수 있는 엔터티 유형: AWS 서비스를 선택합니다.
  4. 서비스 또는 사용 사례: Elastic Beanstalk를 선택합니다.
  5. 사용 사례: Elastic Beanstalk - Compute를 선택하고 다음을 누릅니다.
  6. 아래 정책 3개가 들어 있는지 확인하고 다음을 누릅니다.
자동으로 들어가는 정책
AWSElasticBeanstalkMulticontainerDocker
AWSElasticBeanstalkWebTier
AWSElasticBeanstalkWorkerTier
  1. 역할 이름에 아래 값을 붙여넣고 역할 생성을 누릅니다.
역할 이름
aws-elasticbeanstalk-instance-role

② 빈스톡 서비스용 역할

  1. 다시 역할 생성을 누릅니다.
  2. AWS 서비스 → Elastic Beanstalk를 선택합니다.
  3. 사용 사례: Elastic Beanstalk - Environment를 선택하고 다음을 누릅니다.
  4. 정책 2개(AWSElasticBeanstalkEnhancedHealth, AWSElasticBeanstalkManagedUpdatesCustomerRolePolicy)를 확인하고 다음을 누릅니다.
  5. 역할 이름에 아래 값을 붙여넣고 역할 생성을 누릅니다.
역할 이름
elasticbeanstalk-service-role
✅ 이렇게 나오면 성공

IAM → 역할 목록에서 검색창에 elasticbeanstalk를 입력하면 두 역할이 모두 보입니다.

⚠️ “이미 존재하는 이름입니다” 오류

같은 이름의 역할이 이미 있다는 뜻입니다. 이름 끝에 2를 붙여 만드세요. 다음 레슨에서는 내가 만든 이름을 선택하면 됩니다.

예시 이름
aws-elasticbeanstalk-instance-role2

EC2 서버용 역할은 Compute, 빈스톡 서비스용 역할은 Environment입니다.

레슨 3이전 콘솔로 전환하고 RDS 추가하기

💡 왜 하나요?

빈스톡 화면에서 RDS를 추가하면 EC2가 DB에 접속할 수 있도록 보안 그룹 규칙까지 자동으로 만들어집니다.

⚠️ 구성 화면에 “네트워킹 및 데이터베이스”가 없어요

AWS가 바꾼 새 콘솔 구성 화면에는 데이터베이스 항목이 없습니다. 맨 위 파란 안내 상자의 이전 콘솔을 사용 링크를 눌러 기존 화면으로 바꾸세요.

  1. 빈스톡 왼쪽 메뉴 환경 → 내 환경 이름을 누릅니다.
  2. 왼쪽 아래 구성을 누릅니다.
  3. 새 콘솔 화면이면 이전 콘솔을 사용 링크를 누릅니다.
  4. 네트워킹 및 데이터베이스 카드의 편집을 누릅니다.
  5. 아래로 내려 데이터베이스 활성화 토글을 켭니다.
  6. 아래 표의 값을 입력하고 맨 아래 적용을 누릅니다.
항목입력값설명
엔진mysql
엔진 버전8.0 버전 중 최신목록 맨 위 8.0.x를 고릅니다
인스턴스 클래스db.t3.micro가장 작은 사양입니다
스토리지5GB 단위입니다
사용자 이름ebroot원하는 이름을 써도 됩니다
암호8자 이상다시 볼 수 없으니 꼭 메모하세요

사용자 이름 예시

⚠️ “새 버전으로 전환” 버튼은 누르지 마세요

누르면 데이터베이스 항목이 없는 새 콘솔 화면으로 돌아갑니다.

  1. 환경 상태가 업데이트 중으로 바뀝니다. 약 10분 기다립니다.

  3. 왼쪽 데이터베이스 → awseb-e-로 시작하는 DB 식별자를 누릅니다.
  4. 연결 및 보안 탭의 엔드포인트를 복사해 메모장에 붙여 둡니다.
✅ 이렇게 나오면 성공

레슨 4내 PC에서 RDS 접속해 테이블 만들기

💡 왜 하나요?

RDS의 MySQL은 비어 있습니다. 블로그가 쓰는 blog 데이터베이스와 테이블 3개를 직접 만들어야 합니다.

① 보안 그룹에 내 IP 허용

  1. RDS → 데이터베이스 → DB 식별자 → 연결 및 보안 탭으로 갑니다.
  2. VPC 보안 그룹 링크를 누릅니다.
  3. 보안 그룹 ID를 누르고 인바운드 규칙 탭 → 인바운드 규칙 편집을 누릅니다.
  4. 규칙 추가를 누르고 유형 MYSQL/Aurora, 소스 내 IP를 고릅니다.
  5. 규칙 저장을 누릅니다.
⚠️ 장소를 옮기면 다시 접속이 안 돼요

집·학원처럼 인터넷이 바뀌면 내 IP도 바뀝니다. 인바운드 규칙의 소스를 다시 내 IP로 고르고 저장하세요.

② 인텔리제이에서 접속

  1. 인텔리제이 설정 → 플러그인에서 Database Navigator(Oracle)를 설치하고 IDE를 다시 시작합니다.
  2. 왼쪽 도구 메뉴의 DB Browser → + → MySQL을 누릅니다.
  3. 아래 표대로 입력하고 Test Connection을 누릅니다.
항목입력값
Host레슨 3에서 복사한 엔드포인트
Port3306
Databasemysql
User / Password레슨 3에서 정한 사용자 이름 / 암호
✅ 이렇게 나오면 성공

Connection Successful 안내창이 나타납니다.

⚠️ Test Connection이 오래 걸리다 실패해요 (timeout)

① 인바운드 규칙의 소스가 지금 내 IP인지 확인하세요. ② RDS 연결 및 보안 탭의 퍼블릭 액세스 가능이 아니요라면 RDS 수정 → 연결 → 추가 구성 → 퍼블릭 액세스 가능을 선택하고 즉시 적용하세요.

③ SQL 실행

  1. DB Browser의 Connection을 우클릭 → Open SQL Console을 누릅니다.
  2. 아래 SQL 전체를 붙여넣고 ▶ 버튼으로 실행합니다.
rds-schema.sql
create database blog;

use blog;

create table article (
    id bigint not null AUTO_INCREMENT,
    author varchar(255) not null,
    content varchar(255) not null,
    created_at timestamp,
    title varchar(255) not null,
    image_url varchar(255),
    updated_at timestamp,
    primary key (id)
);

create table refresh_token (
    id bigint not null AUTO_INCREMENT,
    refresh_token varchar(255) not null,
    user_id bigint not null,
    primary key (id)
);

create table users (
    id bigint not null AUTO_INCREMENT,
    created_at timestamp,
    email varchar(255) not null,
    nickname varchar(255),
    password varchar(255),
    updated_at timestamp,
    primary key (id)
);

show tables;
✅ 이렇게 나오면 성공

마지막 show tables; 결과에 article, refresh_token, users 3개가 나옵니다.

⚠️ “Can't create database 'blog'; database exists” 오류

blog 데이터베이스가 이미 있다는 뜻입니다. 첫 줄 create database blog;만 지우고 다시 실행하세요.

🛠️ 미션

RDS에 blog 데이터베이스와 테이블 3개를 만들고 show tables 결과를 확인하세요.

레슨 5jar 빌드하고 빈스톡에 업로드하기

💡 왜 하나요?

내 PC에서 만든 jar 파일을 빈스톡에 올리면 EC2가 그 파일을 실행합니다.

jar 파일
자바 클래스와 필요한 라이브러리를 하나로 묶은 실행 파일입니다. java -jar 파일명.jar로 실행합니다.
  1. 인텔리제이 오른쪽 Gradle 탭을 엽니다.
  2. Tasks → build → build를 더블클릭합니다.
  3. 빌드가 끝나면 build/libs 폴더를 엽니다.
  4. -plain이 없는 jar 파일을 바탕화면 등 찾기 쉬운 곳에 복사합니다.
  1. 빈스톡 환경 개요 화면에서 업로드 및 배포를 누릅니다.
  2. 파일 선택으로 복사해 둔 jar를 고릅니다.
  3. 버전 레이블은 매번 다르게 적고 배포를 누릅니다.
버전 레이블 예시

레슨 6환경 속성 입력하기

💡 왜 하나요?

DB 주소·암호·API 키는 코드에 적으면 안 됩니다. 빈스톡 환경 속성에 넣으면 서버가 시작될 때 이 값이 application.yml의 같은 설정을 덮어씁니다.

환경 속성
서버 운영체제의 환경 변수입니다. 스프링 부트는 SPRING_DATASOURCE_URL을 spring.datasource.url로 바꿔 읽습니다.
  1. 빈스톡 환경 → 구성 → 업데이트, 모니터링 및 로깅 카드의 편집을 누릅니다.
  2. 맨 아래 환경 속성까지 내립니다.
  3. 환경 속성 추가를 눌러 아래 9개를 하나씩 입력합니다.
  4. 적용을 누릅니다.
이름 (복사)값설명
SERVER_PORT5000빈스톡 nginx가 요청을 넘기는 포트
SPRING_DATASOURCE_URLjdbc:mysql://<엔드포인트>:3306/blog<엔드포인트>를 레슨 3 값으로 바꿉니다
SPRING_DATASOURCE_USERNAMEebrootRDS 사용자 이름
SPRING_DATASOURCE_PASSWORD레슨 3에서 정한 암호
JWT_SECRET_KEYstudy-springboot
SPRING_SECURITY_OAUTH2_CLIENT_REGISTRATION_GOOGLE_CLIENT_ID<구글 클라이언트 ID>구글 클라우드 콘솔에서 복사
SPRING_SECURITY_OAUTH2_CLIENT_REGISTRATION_GOOGLE_CLIENT_SECRET<구글 클라이언트 보안 비밀>구글 클라우드 콘솔에서 복사
SPRING_SECURITY_OAUTH2_CLIENT_REGISTRATION_GOOGLE_SCOPEemail, profile
SPRING_AI_OPENAI_API_KEYOpenAI에서 발급

실제 입력 예시: jdbc:mysql://awseb-e-ab12cd.c9xyz.ap-northeast-2.rds.amazonaws.com:3306/blog

✅ 이렇게 나오면 성공

환경 상태가 OK(초록)가 됩니다. 도메인 주소 뒤에 /login을 붙여 열면 로그인 화면이 나옵니다.

주소 형식

레슨 7구글 로그인 리디렉션 URI 추가하기

💡 왜 하나요?

구글은 미리 등록된 주소로만 로그인 결과를 보내 줍니다. 빈스톡 주소를 등록하지 않으면 400 오류: redirect_uri_mismatch가 나옵니다.

  1. 구글 클라우드 콘솔에 접속합니다.
  2. API 및 서비스 → 사용자 인증 정보로 갑니다.
  3. OAuth 2.0 클라이언트 ID 이름을 누릅니다.
  4. 승인된 리디렉션 URI에서 URI 추가를 누릅니다.
  5. 아래 형식으로 입력하고 저장을 누릅니다.
입력 형식
http://<도메인>/login/oauth2/code/google

실제 입력 예시: http://springboot-developer-env.eba-mrugwd2n.ap-northeast-2.elasticbeanstalk.com/login/oauth2/code/google

✅ 이렇게 나오면 성공

약 3~5분 뒤 /login에서 구글 로그인을 누르면 계정 선택 화면이 나오고, 로그인 후 블로그 글 목록으로 이동합니다.

⚠️ 여전히 redirect_uri_mismatch

① 주소가 http로 시작하는지 ② 끝에 /가 붙지 않았는지 ③ 도메인 철자가 맞는지 확인하세요. 저장 후 몇 분 기다려야 적용됩니다.

🛠️ 미션

리디렉션 URI를 추가하고 배포된 사이트에서 구글 로그인에 성공하세요.

🧠 퀴즈

승인된 리디렉션 URI 끝에 붙는 경로는?

스프링 시큐리티가 구글 로그인 결과를 받는 기본 경로입니다.

레슨 8S3에 이미지 저장하기

💡 왜 하나요?

EC2 디스크는 재배포하거나 서버가 바뀌면 지워집니다. 이미지는 S3에 저장해야 사라지지 않습니다.

① 버킷 만들기

  1. 검색창에 S3 → 버킷 만들기를 누릅니다.
  2. 아래 표대로 설정하고 버킷 만들기를 누릅니다.
항목설정
AWS 리전아시아 태평양(서울) ap-northeast-2
버킷 이름springboot-developer-본인아이디
객체 소유권ACL 활성화됨
이 버킷의 퍼블릭 액세스 차단 설정모든 퍼블릭 액세스 차단 체크 해제 + 경고 확인 체크

실제 입력 예시: springboot-developer-hong1234

② 버킷 정책 넣기

  1. 만든 버킷 → 권한 탭 → 버킷 정책의 편집을 누릅니다.
  2. 아래 JSON을 붙여넣고 본인아이디 부분만 내 버킷 이름에 맞게 바꿉니다.
  3. 변경 사항 저장을 누릅니다.
버킷 정책 JSON
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PublicReadUploads",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::springboot-developer-본인아이디/uploads/*"
    }
  ]
}
⚠️ “정책에 잘못된 리소스가 있습니다” 오류

Resource의 버킷 이름이 실제 버킷 이름과 다를 때 납니다. 버킷 이름을 그대로 복사해 바꾸세요.

③ EC2 역할에 S3 업로드 권한 주기

  1. 빈스톡 환경 → 구성 → 서비스 액세스 카드의 EC2 인스턴스 프로파일 이름을 확인합니다.
  2. IAM → 역할 → 그 이름을 누릅니다.
  3. 권한 추가 → 정책 연결을 누릅니다.
  4. 검색창에 아래 이름을 넣고 체크한 뒤 권한 추가를 누릅니다.
정책 이름
AmazonS3FullAccess

④ 버킷 이름 바꾸고 다시 배포

  1. 프로젝트 src/main/resources/application.yml의 bucket 값을 내 버킷 이름으로 바꿉니다.
  2. 레슨 5처럼 build → 업로드 및 배포를 다시 합니다. 버전 레이블은 v2처럼 바꿉니다.
application.yml
cloud:
  aws:
    region: ap-northeast-2
    s3:
      bucket: springboot-developer-본인아이디
✅ 이렇게 나오면 성공

배포된 사이트에서 글을 쓰며 이미지를 올리면 미리보기가 보입니다. S3 버킷의 uploads/ 폴더에 UUID.png 파일이 생깁니다.

⚠️ 이미지 업로드 시 500 오류

로그에 AccessDenied … s3:PutObject가 보이면 ③에서 권한을 다른 역할에 연결한 것입니다. 구성 → 서비스 액세스의 EC2 인스턴스 프로파일 이름을 다시 확인하세요.

🛠️ 미션

배포된 사이트에서 이미지를 올리고 S3 uploads/ 폴더에 파일이 생긴 것을 확인하세요.

🧠 퀴즈

S3 업로드(PutObject) 권한은 어디에 연결하나요?

버킷 정책은 누구나 읽기(GetObject)만 허용합니다. 업로드 권한은 EC2가 쓰는 IAM 역할에 줍니다.

레슨 9오류가 나면 로그 보기

💡 왜 하나요?

배포 후 오류는 대부분 작은 입력 실수입니다. 로그 파일을 열면 어디가 틀렸는지 정확히 나옵니다.

  1. 빈스톡 환경 → 왼쪽 로그를 누릅니다.
  2. 로그 요청 → 전체를 누릅니다.

  4. zip 압축을 풀고 var/log/web.stdout.log를 메모장으로 엽니다.

레슨 10실습 끝나면 정리하기

💡 왜 하나요?

EC2와 RDS는 켜 두는 시간만큼 요금이 계산됩니다. 실습을 마치면 아래 순서로 지워야 요금이 나가지 않습니다.

  1. 빈스톡 → 환경 → 내 환경 선택 → 작업 → 환경 종료를 누르고 환경 이름을 입력해 확인합니다. EC2와 RDS(삭제 정책 Delete)가 함께 지워집니다.
  2. S3 → 내 버킷 선택 → 비어 있음으로 파일을 모두 지운 뒤 삭제를 누릅니다.
  3. RDS → 데이터베이스 목록이 비어 있는지 확인합니다. 남아 있으면 선택 → 작업 → 삭제를 누릅니다.
  4. 결제 및 비용 관리 화면에서 비용이 늘지 않는지 다음 날 한 번 더 확인합니다.
✅ 이렇게 나오면 성공

빈스톡 환경 목록, RDS 데이터베이스 목록, 내 S3 버킷이 모두 비어 있습니다.

⚠️ 버킷 삭제 버튼이 눌리지 않아요

버킷 안에 파일이 남아 있으면 삭제할 수 없습니다. 먼저 비어 있음을 실행하세요.

🛠️ 미션

실습이 끝난 뒤 환경 종료 → 버킷 비우기·삭제 → RDS 목록 확인까지 마치세요.

🧠 퀴즈

빈스톡 환경을 종료하면 함께 지워지는 것은? (삭제 정책 Delete 기준)

환경에 묶인 EC2와 RDS는 함께 지워집니다. 직접 만든 S3 버킷과 IAM 역할은 남습니다.

AWS 콘솔 화면은 수시로 바뀝니다. 버튼 이름이 조금 달라도 같은 위치의 메뉴를 찾으면 됩니다.
