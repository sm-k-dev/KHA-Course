빌드(Build)란 무엇일까?

IntelliJ IDEA에서 Spring Boot 프로젝트를 개발할 때 꼭 알아야 하는 빌드의 의미와 실행 과정을 학습합니다.

학습 목표

이 자료를 학습하면

  • 빌드(Build)가 무엇인지 설명할 수 있습니다.
  • 소스 코드, 컴파일, 라이브러리, JAR 파일의 관계를 이해할 수 있습니다.
  • IntelliJ에서 Gradle 빌드를 실행하는 방법을 알 수 있습니다.
  • 빌드(Build), 실행(Run), 배포(Deploy)의 차이를 구분할 수 있습니다.

1. 빌드(Build)의 정확한 의미

빌드(Build)란 개발자가 작성한 소스 코드와 프로젝트 설정, 필요한 라이브러리 등을 바탕으로 프로그램을 검사·컴파일하고, 실행하거나 배포할 수 있는 결과물을 만드는 과정입니다.

Spring Boot 프로젝트에는 Java 소스 코드뿐 아니라 HTML, CSS, JavaScript, 설정 파일, 외부 라이브러리 등이 포함될 수 있습니다. 이 파일들을 프로젝트 설정에 따라 처리하여 결과물을 만드는 작업이 빌드입니다.

중요: 빌드는 단순히 파일을 압축하는 작업이 아닙니다. Java 컴파일, 리소스 처리, 테스트 실행(설정에 따라), JAR 생성 등 여러 작업이 포함될 수 있습니다.

2. 빌드하기 전 프로젝트 구조

예를 들어 다음과 같은 Spring Boot 프로젝트가 있다고 가정하겠습니다.

MySpringProject/ ├─ src/ │ └─ main/ │ ├─ java/ │ │ └─ com/example/ │ │ └─ HelloController.java │ └─ resources/ │ ├─ application.properties │ ├─ templates/ │ └─ static/ ├─ build.gradle └─ settings.gradle
파일 또는 폴더역할
src/main/javaJava 클래스와 프로그램의 주요 로직을 작성하는 위치
src/main/resources설정 파일, 화면 템플릿, 정적 파일 등을 저장하는 위치
build.gradleGradle 빌드 설정과 외부 라이브러리 의존성 등을 정의하는 파일
settings.gradleGradle 프로젝트 또는 여러 모듈의 구성을 정의하는 파일

이 단계에서는 개발자가 작성한 원본 파일들이 주로 src 폴더에 있습니다. 아직 빌드 결과물이 생성되지 않았을 수 있습니다.

3. 빌드를 실행하면 어떤 일이 일어날까?

① 소스 코드와 설정 확인프로젝트에 어떤 파일과 빌드 설정이 있는지 확인
↓
② 필요한 라이브러리 준비Spring Boot, 데이터베이스 드라이버 등 의존성 확인 및 다운로드
↓
③ Java 컴파일.java 소스 코드를 JVM이 실행할 수 있는 .class 바이트코드로 변환
↓
④ 리소스 처리 및 테스트설정 파일·화면 리소스 처리, 설정된 테스트 작업 수행
↓
⑤ 빌드 결과물 생성예: 실행 가능한 Spring Boot JAR 파일

모든 빌드에서 테스트가 자동으로 성공적으로 수행되는 것은 아닙니다. Gradle의 어떤 작업을 실행했는지, 프로젝트 설정이 어떻게 되어 있는지에 따라 세부 과정은 달라집니다.

4. 컴파일(Compile)이란?

Java 컴파일은 Java 소스 코드 파일을 JVM(Java Virtual Machine)이 실행할 수 있는 바이트코드 파일로 변환하는 작업입니다.

// 개발자가 작성하는 Java 소스 코드
public class Hello {
    public static void main(String[] args) {
        System.out.println("안녕하세요!");
    }
}
Hello.java개발자가 작성한 Java 소스 코드
↓ 컴파일
Hello.classJVM이 실행할 수 있는 바이트코드

컴파일 과정에서 문법이나 자료형 등의 오류가 발견되면 컴파일이 실패할 수 있습니다. 다만 컴파일 성공이 프로그램의 모든 기능이 정상이라는 뜻은 아닙니다.

5. Gradle은 무엇일까?

Gradle은 프로젝트에 필요한 라이브러리를 관리하고, 빌드 작업을 실행하는 빌드 도구(Build Tool)입니다.

IntelliJ IDEA는 Gradle과 연동하여 개발자가 버튼을 누르거나 명령어를 입력하면 빌드를 실행할 수 있도록 지원합니다.

build.gradle 예시

plugins {
    id 'java'
    id 'org.springframework.boot' version '3.x.x'
}

dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-web'
}
  • plugins: 프로젝트에서 사용할 Gradle 플러그인을 선언합니다.
  • dependencies: 프로젝트가 사용하는 외부 라이브러리를 선언합니다.
  • implementation: 애플리케이션 구현에 필요한 의존성을 지정합니다.

위 코드는 구조를 설명하기 위한 예시입니다. 실제 프로젝트에서는 Spring Boot 버전과 필요한 의존성을 프로젝트 상황에 맞게 지정해야 합니다.

6. IntelliJ IDEA에서 빌드하기

방법 1. Gradle 창에서 실행

  1. IntelliJ IDEA에서 Spring Boot 프로젝트를 엽니다.
  2. 오른쪽의 Gradle 도구 창을 엽니다.
  3. Tasks → build → build 항목을 찾습니다.
  4. build를 더블클릭합니다.
  5. 하단 Build 창에서 실행 결과를 확인합니다.

방법 2. 터미널 명령어로 실행

Windows 터미널에서는 프로젝트 최상위 폴더에서 다음 명령어를 실행합니다.

gradlew.bat build

macOS 또는 Linux에서는 다음 명령어를 사용합니다.

./gradlew build
BUILD SUCCESSFUL
Gradle이 요청된 빌드 작업을 오류 없이 완료했다는 의미입니다.

반대로 BUILD FAILED가 표시되면 빌드 중 오류가 발생한 것입니다. Build 창이나 터미널의 오류 메시지를 확인해야 합니다.

7. 빌드가 끝나면 무엇이 만들어질까?

Gradle Java 프로젝트의 일반적인 빌드 결과는 프로젝트 내부의 build 폴더에 저장됩니다.

MySpringProject/ ├─ src/ ← 개발자가 작성한 원본 파일 ├─ build.gradle └─ build/ ← 빌드 결과가 저장되는 폴더 ├─ classes/ │ └─ java/ │ └─ main/ │ └─ ... .class ├─ resources/ └─ libs/ └─ MySpringProject-0.0.1-SNAPSHOT.jar
  • build/classes: 컴파일된 Java 클래스 파일 등이 저장됩니다.
  • build/resources: 빌드 과정에서 처리된 리소스 파일 등이 저장됩니다.
  • build/libs: JAR 등 패키징 결과물이 저장될 수 있습니다.

JAR(Java ARchive)은 Java 클래스와 리소스 등을 하나의 파일로 묶는 파일 형식입니다. Spring Boot 프로젝트는 실행에 필요한 구성을 포함한 실행 가능한 JAR를 만들 수 있습니다.

JAR 파일의 정확한 이름과 생성 여부는 프로젝트의 Gradle 설정 및 빌드 작업에 따라 달라집니다.

8. 빌드(Build), 실행(Run), 배포(Deploy)의 차이

구분의미예시
코딩프로그램의 소스 코드를 작성하는 작업Controller 클래스 작성
빌드소스 코드 등을 처리하여 실행·배포 가능한 결과물을 만드는 작업JAR 파일 생성
실행프로그램을 실제로 동작시키는 작업Spring Boot 서버 시작
배포프로그램을 운영 환경에 설치하거나 전달하여 서비스하도록 하는 작업운영 서버에 JAR 배포

빌드와 실행 명령어 비교

① 빌드 명령어

gradlew.bat build

프로젝트를 빌드합니다. 설정에 따라 테스트와 JAR 생성 등이 수행됩니다.

② JAR 실행 명령어

java -jar build/libs/MySpringProject-0.0.1-SNAPSHOT.jar

생성된 실행 가능 JAR 파일을 실행합니다. 실제 파일명은 프로젝트의 결과물 이름에 맞춰야 합니다.

③ 브라우저 접속 예시

http://localhost:8080

서버가 정상 실행 중이고 해당 주소에 처리할 화면이나 API가 구성되어 있다면 브라우저에서 접속할 수 있습니다.

IntelliJ의 초록색 Run 버튼으로 애플리케이션을 실행할 때도 내부적으로 컴파일 등 필요한 작업이 수행될 수 있습니다. 따라서 빌드와 실행은 서로 다른 개념이지만 실제 개발 과정에서는 연결되어 있습니다.

마무리: 이것만 기억하세요!

빌드(Build) : 소스 코드 등을 처리하여 실행하거나 배포할 수 있는 결과물을 만드는 작업

실행(Run) : 만들어진 프로그램을 실제로 동작시키는 작업

배포(Deploy) : 프로그램을 운영 환경에 설치하여 사용자에게 서비스를 제공하는 작업

Spring Boot 개발에서는 코드를 작성한 뒤 빌드하고, 실행하여 테스트한 다음, 완성된 프로그램을 운영 서버에 배포합니다.
