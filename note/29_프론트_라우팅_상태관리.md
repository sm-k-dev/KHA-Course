## 1. 라우팅: 주소에 따라 화면을 고른다

**정의** — 라우팅은 URL 경로에 따라 어떤 화면을 보여 줄지 정하는 일이다.

| 방식 | 누가 화면을 고르는가 | 특징 |
|---|---|---|
| 서버 라우팅 | 서버가 HTML을 새로 만든다 | 페이지 이동마다 전체 로드 |
| 클라이언트 라우팅 | 브라우저의 JavaScript가 화면을 바꾼다 | 이동이 빠르고, 새로고침 시 서버가 같은 경로를 처리할 설정이 필요 |

SPA(단일 페이지 애플리케이션)는 클라이언트 라우팅을 쓴다. 그래서 `/posts/1`을 직접 열어도 서버가 `index.html`을 돌려주도록 설정해야 한다.

### 1.1 React Router 예

```tsx
import { BrowserRouter, Routes, Route, Navigate, useParams } from 'react-router-dom';

function PostDetail() {
  const { id } = useParams();          // URL의 :id 값
  return <h1>글 {id}</h1>;
}

export default function App() {
  return (
    <BrowserRouter>
      <Routes>
        <Route path="/" element={<h1>home</h1>} />
        <Route path="/posts/:id" element={<PostDetail />} />
        <Route path="*" element={<Navigate to="/" replace />} />
      </Routes>
    </BrowserRouter>
  );
}
```

### 1.2 보호된 페이지

```tsx
function RequireAuth({ children, loggedIn }: { children: JSX.Element; loggedIn: boolean }) {
  if (!loggedIn) return <Navigate to="/login" replace />;
  return children;
}
```

**주의**: 이 검사는 **화면만** 막는다. 실제 데이터 접근 권한은 서버가 다시 확인해야 한다(31장 RBAC). 브라우저의 코드는 사용자가 언제든지 바꿀 수 있다.

## 2. 상태 관리: 상태를 어디에 둘지 고른다

**정의** — 상태는 시간이 지나며 바뀌고 화면에 영향을 주는 값이다. 상태를 둘 위치를 잘못 고르면 불필요한 렌더링과 동기화 버그가 생긴다.

| 종류 | 예 | 둘 곳 |
|---|---|---|
| 화면 한 곳의 값 | 입력 중인 텍스트, 모달 열림 여부 | 컴포넌트의 `useState` |
| 여러 곳이 공유하는 값 | 로그인한 사용자, 테마 | 가까운 공통 부모 또는 Context |
| 여러 화면이 공유하는 복잡한 값 | 장바구니, 필터 조건 | 전역 스토어 (Zustand, Redux Toolkit) |
| 서버에서 가져온 값 | 글 목록, 사용자 정보 | 서버 상태 라이브러리 (TanStack Query 등) |

**원칙**: 서버에서 온 데이터를 `useState`에 복사해서 들고 있지 않는다. 캐시, 재요청, 로딩 상태를 직접 관리해야 해서 버그가 생기기 쉽다. 서버 상태는 서버 상태 라이브러리에 맡긴다.

### 2.1 Context 예

```tsx
const AuthContext = createContext<{ user: string | null; login: (u: string) => void } | null>(null);

export function AuthProvider({ children }: { children: React.ReactNode }) {
  const [user, setUser] = useState<string | null>(null);
  return (
    <AuthContext.Provider value={{ user, login: setUser }}>
      {children}
    </AuthContext.Provider>
  );
}

export function useAuth() {
  const ctx = useContext(AuthContext);
  if (!ctx) throw new Error('useAuth는 AuthProvider 안에서만 쓴다');
  return ctx;
}
```

**주의**: Context의 `value`가 바뀌면 그 값을 쓰는 모든 자식이 다시 렌더링된다. 자주 바뀌는 값을 큰 Context에 넣지 않는다.

## 3. 흔한 실수

| 실수 | 결과 | 고치는 방법 |
|---|---|---|
| 서버 데이터를 `useState`에 복사 | 원본과 어긋남 | 서버 상태 라이브러리 사용 |
| 모든 상태를 전역에 둠 | 어디서 바뀌는지 찾기 어려움 | 필요한 범위만 전역으로 |
| 경로 파라미터를 문자열로 가정 | 숫자 비교 실패 | `Number(id)`로 변환하고 검사 |
| 렌더링 중에 상태를 바꿈 | 무한 렌더링 | 이벤트 핸들러나 `useEffect`에서 변경 |

## 4. 실습 과제

1. 1.1 예제를 Vite 프로젝트에 넣고 `/posts/7`을 직접 열어 `글 7`이 나오는지 확인한다.
2. 게시글 목록을 `useState`로 복사하지 않고 서버 상태 라이브러리로 가져오는 구조를 그려 본다.
3. 로그인 상태를 Context로 옮긴 뒤, 로그인 상태와 무관한 자식 컴포넌트가 다시 렌더링되는지 React DevTools로 확인한다.
