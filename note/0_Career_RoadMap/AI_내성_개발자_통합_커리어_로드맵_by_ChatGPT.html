6. AI 코드 이해도·월말 평가

“한 줄 한 줄 설명하기”는 암기가 아니라 역할·흐름·이유·실패·검증을 설명할 수 있다는 뜻이다. 라이브러리 내부 전체를 암기할 필요는 없다.

위 체크박스는 브라우저에서 임시 자기평가용으로 사용할 수 있다. 체크 상태는 파일에 저장되지 않는다. 실제 통과는 실행 가능한 코드, 테스트 결과, 구두 설명으로 확인한다.

월말에 남길 네 가지 증거

  1. 설명 노트: 정의·원리·유사 개념 비교
  2. 실행 코드: Git 커밋 및 AI 도움 여부 기록
  3. 검증 자료: 테스트 결과·실패 사례·디버깅 기록
  4. 설계 기록: 기술 선택 이유와 대안(ADR)

3개월마다 점검할 질문

새로운 코드의 흐름을 추적할 수 있는가? AI 없이 핵심 로직을 작성할 수 있는가? 실패를 재현하고 고칠 수 있는가? 사용자의 문제와 설계의 타당성을 설명할 수 있는가?

8. 최종 성공 기준

24개월 동안 기술 이름을 모두 공부했는가가 아니라, 처음 보는 문제를 분석하고, 설계·구현·테스트·배포하며, AI가 만든 결과의 정확성·보안·운영을 검증할 수 있는가로 평가한다.

24개월 기본 계획 이후에도 필요하면 최대 36개월까지 심화한다. 취업 준비 활동은 이 문서의 진도 및 평가 기준에 포함하지 않는다.

9. 이해도 기반 가변형 학습 운영 체계

24개월은 기준 일정이지 필수 이수 기간이 아닙니다. 이미 아는 개념은 사전 진단과 실습 검증을 통과한 뒤 빠르게 진행합니다. 12개월은 빠른 진행 시나리오, 18개월은 압축형, 24개월은 기본형, 최대 36개월은 심화·보완형으로 운영할 수 있습니다. 기간 단축은 동일한 깊이의 숙달을 보장하지 않습니다.

챕터 운영 루프
사전 진단 → 학습 경로 결정 → 필요한 개념 학습 → 실습·테스트 → 이해도 검증 → 다음 챕터 또는 보완 학습

9.1 사전 진단: 매 챕터 시작 전

평가 영역확인할 것증거
개념·원리정의, 동작 과정, 관련 CS 지식자신의 말로 설명
코드 해석입력·출력, 객체 책임, 실행 흐름처음 보는 코드 분석
오류 분석잘못된 구현, 예외·경계 조건오류 재현 및 원인 진단
독립 구현AI 없이 핵심 부분을 구현할 수 있는가작은 코딩 과제와 테스트

9.2 진단 결과에 따른 경로

현재 수준진행 방식
처음 배우는 내용정의 → 원리 → 예제 → 직접 구현 → 검증
배웠으나 기억이 흐릿함취약 개념 복습 → 집중 실습 → 검증
이미 이해한 내용바로 실습·설명 평가 후 통과 가능
실무 경험이 있는 내용경계 조건·설계 대안·장애 시나리오로 심화 검증

9.3 챕터 완료 기준: 네 가지 모두 확인

  1. 개념과 내부 동작 원리를 자신의 말로 설명할 수 있다.
  2. AI 없이 핵심 코드를 작성하거나 수정할 수 있다.
  3. AI 생성 코드의 오류·위험을 발견하고 근거를 제시할 수 있다.
  4. 정상·예외·경계 테스트를 통과하고 기술 선택 이유를 설명할 수 있다.

체크리스트는 자기평가일 뿐이며, 실제 통과 여부는 구두 설명·실행 코드·테스트 결과로 판단합니다. 보안, 시스템 설계, 장애 대응은 짧은 시험만으로 완성되지 않으므로 프로젝트 경험과 재평가를 함께 요구합니다.

9.4 진도 관리와 3개월 주기 재평가

각 모듈마다 상태(미시작 / 진단 통과 / 학습 중 / 검증 통과 / 보완 필요), 진단일, 실습 링크, 테스트 결과, 설명 노트, 미해결 질문을 기록합니다. 3개월마다 CS 원리 이해도, 독립 구현 능력, AI 코드 검증 능력, 프로젝트 성과를 재점검해 다음 분기의 깊이와 속도를 조정합니다.
