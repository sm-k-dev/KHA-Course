# 통합 커리어 목표 | Career Vision

> 개정: 2026-10-30 · 원본 2개 커리어 목표와 3개 HTML 자료를 비교하여 통합

## 1. 최종 비전

**AI-Native Backend & Platform Engineer — AI 시스템을 안전하게 설계·구현·검증·운영하는 엔지니어**

Java/Spring Boot 백엔드를 중심 전문성으로 삼고, AI Application/Agent Engineering, Cloud·DevOps, Data Engineering, Security를 실제 제품의 요구사항에 맞게 통합한다. AI가 작성한 코드와 에이전트 행동을 검증하고 통제하며, 문제 정의·아키텍처 판단·운영 결과에 책임지는 개발자가 된다. 'AI 내성'은 대체 불가능을 보장하는 표현이 아니라 변화에 적응하는 기술적 자립성을 뜻한다.

## 2. 전문성의 깊이: 중심축과 실무 확장

| 영역 | 목표 깊이 | 확인 가능한 결과 |
|---|---|---|
| Backend / Software Engineering (중심) | 독립적으로 설계·구현·테스트·개선 | Java, Spring Boot, REST, JPA, SQL, 트랜잭션, 동시성, 테스트 |
| AI Application / Agent Engineering (차별화) | 실제 기능 구현 및 평가·통제 | LLM API, RAG, 평가, Tool Calling, Single/Sub/Multi-Agent, Loop/Harness |
| Cloud / DevOps (운영) | 직접 배포·관측·복구 | Linux, Docker, AWS, CI/CD, 로그·메트릭·트레이싱 |
| Data Engineering (신뢰성) | 소규모 파이프라인 직접 구현 | Python, SQL, ETL/ELT, 재처리·품질 검증 |
| Network & Network Security (기존 전공 기반) | 이해도 진단 후 실습으로 재검증, 백엔드·클라우드에 적용 | TCP/IP, Routing/Switching, VLAN, Subnetting, Firewall, IDS/IPS, VPN, Wireshark, tcpdump |
| Application / Cloud / AI Security (횡단 전문성) | 설계부터 검증까지 적용 | 인증·인가, TLS/mTLS, IAM, VPC, OWASP, Secret 관리, Prompt Injection, Agent 권한 통제 |

**균형의 의미:** 모든 영역을 같은 깊이로 마스터하는 것이 아니라, 각 영역에서 작동하는 결과물을 만들되 백엔드와 시스템 설계에 가장 깊이 투자한다. React/TypeScript와 Python 웹 프레임워크는 필요할 때 사용하는 보조 스택으로 유지한다.

## 3. 기반 역량

- **CS:** 컴퓨터 구조, 메모리, 자료구조·알고리즘, OS/JVM, 네트워크, DB, 분산 시스템. 필요한 부분은 설명을 넘어 실험으로 확인한다.
- **Software Engineering:** OOP, 설계 원칙, API 계약, 테스트, 리팩터링, 시스템 디자인, 장애 분석.
- **AI Literacy:** 모델의 불확실성, 컨텍스트, 데이터·권한 경계, 비용·지연·품질 평가. 도구 사용법은 별도 AI 가이드 참조.
- **STEM:** 수학(논리·확률통계·선형대수)을 우선하고 물리·화학·생물·지구과학은 장기 병행. 개발 진도를 침해하지 않는다.
- **커뮤니케이션:** 기술적 선택의 이유, 대안, 실패와 개선을 문서·발표·면접에서 설명한다.

## 4. 성장 단계와 취업

**단기(2026년 말~2027년):** Java/Spring Boot Backend Engineer 채용 역량을 증명한다. 학원 수료(2026년 12월 초 목표), 포트폴리오·테스트·README·기술 면접을 우선한다. 기존 목표는 2027년 3월 지원 시작, 5~6월 입사이며 실제 상황에 따라 조정한다. 학원 연계 조건과 과거 경력 증빙을 확인한다.

**중기(약 1~3년):** 백엔드 신뢰성, 클라우드 배포·관측, 데이터 파이프라인, LLM/RAG 기능을 실제 서비스에 적용한다.

**장기(약 3~5년):** 통제 가능한 에이전트와 AI Security까지 설계하는 Backend & Platform Engineer로 확장한다. 조직·시장·실무 경험에 따라 전문화 방향을 재평가한다.

## 5. 경험과 포트폴리오의 위치

- 과거 웹 개발(HTML, JavaScript, jQuery, AJAX, JSP, Java, Spring Framework, Oracle)은 **기반 경험**으로 기록하고 현재 숙련도와 구분한다.
- **호주 Network Security 학사 학습 배경**을 기존 기반 전문성으로 명시한다. TCP/IP·서브네팅·라우팅·스위칭·VLAN·방화벽·IDS/IPS·VPN·패킷 분석은 진단 후 부족한 부분만 복습하고, Linux·클라우드 네트워크·백엔드·AI Agent 보안으로 연결한다. 수강 경험 자체를 현업 숙련도로 단정하지 않는다.
- NEXORA / SentinelOps는 핵심 포트폴리오 기반이다. 기존 구현과 신규 개발, 개인 기여와 팀 기여를 분리한다.
- SentinelOps를 **AI Security & Reliability Platform**으로 점진 확장하되, AI가 필요 없는 기능에는 무리하게 AI를 넣지 않는다.

## 6. Network Security 전공 활용 전략

- **진단:** OSI/TCP-IP, DNS/TLS, 서브네팅, 라우팅, VLAN, NAT, 방화벽·ACL, VPN, IDS/IPS를 설명하거나 실습할 수 있는지 확인한다.
- **증명:** Wireshark/tcpdump로 패킷을 분석하고, 방화벽 규칙·네트워크 분리·TLS 연결 문제를 안전한 로컬 실습 환경에서 재현한다.
- **확장:** Spring Boot API 보안 → AWS VPC·IAM·Security Groups → DevSecOps·관측성 → AI Agent 도구 접근·SSRF 방어·샌드박스·감사 로그 순으로 적용한다.
- **우선순위:** Network Engineer 전체 교육과정을 처음부터 반복하지 않는다. 백엔드 취업과 프로젝트에 직접 연결되는 기술을 우선한다.

## 7. 학습·검증 원칙

1. **정의 → 원리 → 구현 → 개념의 경계 → 시스템 연결 → 설명·응용**의 학습 루프를 적용한다.
2. 매 챕터 시작 시 노트를 덮고 2~3분 설명해 선수 지식을 진단한다. 이미 가능한 내용은 압축한다.
3. 코드·테스트·실험·측정값으로 이해를 입증하고, AI 산출물은 독립적으로 검증한다.
4. 보안·테스트·운영은 후반에 몰아서 추가하지 않고 처음부터 필요한 최소 수준을 적용한다.
5. 학습량은 취업 준비·실제 업무를 우선해 유연하게 조절한다. 3개월마다 계획을 재평가한다.
6. 기술의 이름이나 수료증보다 **스스로 설계하고 문제를 해결한 증거**를 남긴다.

## 8. 최종 성취 기준

요구사항을 설명하고, 안전한 API와 데이터 흐름을 설계하며, 테스트·배포·장애 진단까지 수행한다. AI 기능의 정확도·비용·지연·위험을 측정하고, 에이전트의 권한·반복·승인·감사를 통제할 수 있다. 구현 근거와 트레이드오프를 타인에게 명확하게 전달한다.

## 9. 통합 시 결정 사항

- Claude 문서의 '5개 영역 같은 깊이'와 ChatGPT 문서의 '백엔드 중심'은 **중심 전문성 + 실무 구현 가능한 확장 영역**으로 절충했다.
- 2027년 취업 일정은 24개월 학습 로드맵에 종속시키지 않고 병렬 목표로 유지했다.
- AI 도구 제품 목록은 커리어 목표에서 제외하고 별도 가이드에 남겼다. Agent/Loop/Harness는 로드맵의 엔지니어링 학습 대상으로 채택했다.
