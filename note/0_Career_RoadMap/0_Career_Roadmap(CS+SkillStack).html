Phase 3
SQL & 관계형 데이터베이스
⏱️ 3-4주 | 난이도: 중급
🧠 CS 기초와의 연결: 알고리즘 (B-Tree INDEX로 O(N)을 O(log N)으로)

원리: INDEX는 B-Tree 자료구조로 검색을 O(log N)으로 최적화합니다. 100만 행에서 선형 탐색은 100만 번, B-Tree는 약 20번 비교.

📖 학습 내용
  • 기본 SQL: SELECT, WHERE, JOIN, GROUP BY, HAVING
  • JOIN 최적화: INNER, LEFT, RIGHT, FULL OUTER의 성능
  • 정규화: 1NF, 2NF, 3NF, BCNF로 데이터 중복 제거
  • INDEX: B-Tree 자료구조, COMPOSITE INDEX 설계
  • 트랜잭션: ACID 원칙, 동시성 제어

  • Spring Security: 권한 관리, JWT 토큰, 인증

Phase 6
Python Backend (FastAPI, Django)
⏱️ 4-5주 | 난이도: 중급~상급
🧠 CS 기초와의 연결: Python GIL과 멀티스레딩 vs Asyncio

📖 학습 내용

  • Django: 풀 스택 프레임워크, ORM, Admin 패널
  • ORM: SQLAlchemy, Django ORM으로 데이터베이스 연동
  • 비동기 처리: asyncio, async/await
  • GIL 이해: 멀티스레딩 vs asyncio vs multiprocessing 선택

Phase 7
LLM API & Prompt Engineering
⏱️ 3-4주 | 난이도: 중급
🧠 CS 기초와의 연결: 벡터 임베딩과 메모리 (Floating Point 연산)

원리: 텍스트를 벡터(수백~수천 개 숫자 배열)로 변환합니다. 유사한 단어끼리 벡터 공간에서 가깝게 위치합니다. 메모리 효율적 관리 필수.

📖 학습 내용
  • Java LLM 통합: Spring AI 또는 LangChain4j 프레임워크로 OpenAI/Claude API 자바 연동
  • Function Calling: AI가 자바 백엔드 메서드를 스스로 호출하도록 설계 (자동화의 핵심!)
  • Chat Completion: 대화형 AI 구현, 스트리밍 응답 처리
  • API 보안: API 키 관리, Rate Limiting, 비용 추적
  • Prompt Engineering: Few-shot, Chain of Thought, Role-playing
  • 임베딩: 텍스트를 벡터로 변환, 유사도 계산
  • 토큰화: 텍스트를 토큰으로 분할, 비용 계산
🔐 보안 통합: API 키 관리와 Rate Limiting

LLM API 호출은 비용이 발생하고, 악의적 사용으로부터 보호해야 합니다. 호주 IT 과정의 "Enterprise Security" 개념을 API 보안에 적용합니다. API 키는 환경변수로 관리하고, Rate Limiting으로 남용을 방지합니다.

Phase 8
RAG & Vector Database
⏱️ 3-4주 | 난이도: 상급
🧠 CS 기초와의 연결: 검색 알고리즘 (KNN, HNSW로 O(N)을 O(log N)으로)

원리: 벡터 DB는 HNSW(Hierarchical Navigable Small Worlds) 알고리즘으로 100만 개 벡터에서 유사한 것을 20번 정도 비교로 찾습니다. 이는 INDEX와 유사한 원리입니다.

📖 학습 내용
  • RAG 아키텍처: Retrieval + Augmented Generation
  • 벡터 임베딩: 텍스트를 벡터로 변환
  • 벡터 DB 선택: pgvector (PostgreSQL)로 가벼운 구현 또는 Pinecone, Weaviate, Qdrant (대규모)
  • 유사도 검색: Cosine Similarity, HNSW, IVF 알고리즘
  • 청킹 전략: 긴 문서 효율적 분할, 중복 제거
  • Pandas 기초: RAG에 넣을 CSV/문서 데이터 정제 (필요할 때 1-2일 학습)
  • 사내 문서 관리: RAG 기반 자사 문서 AI 지식 시스템
🔐 보안 통합: 벡터 DB 접근 제어

RAG 시스템에서 벡터 DB에 저장된 데이터는 민감할 수 있습니다. 호주 과정의 "권한 관리" 개념을 벡터 DB에 적용: 사용자별로 접근 가능한 벡터만 검색하도록 필터링합니다.

Phase 9
AI Security & Prompt Injection 방어
⏱️ 4-5주 | 난이도: 상급
🧠 CS 기초와의 연결: 암호화, 해싱, 권한 관리 (RBAC)

원리: Prompt Injection은 SQL Injection과 유사합니다. 방어: 입력 검증, 출력 필터링, 권한 기반 제어 (RBAC).

📖 학습 내용
  • Prompt Injection: 공격 방식과 방어 전략
  • 입력 검증: 길이 제한, 패턴 매칭, 악의적 입력 탐지
  • 출력 필터링: LLM 응답에서 민감 정보 제거
  • API 보안: API 키 관리, Rate Limiting, IP 필터링
  • RBAC: 사용자별 권한, 역할 기반 접근 제어
  • 암호화: AES 데이터 암호화, TLS 전송 암호화
  • 해싱: bcrypt, Argon2로 비밀번호 저장

Phase 11
Data Engineering: 파이프라인 & 검색엔진
⏱️ 4-5주 | 난이도: 상급
🧠 CS 기초와의 연결: 분산 처리와 로그 구조 (Partition & Map-Reduce)

원리: Kafka는 로그를 Partition으로 나눠 병렬로 처리하고, Spark는 데이터를 나눠서 여러 노드에서 계산합니다. Elasticsearch는 역색인(Inverted Index)으로 텍스트 검색을 빠르게 합니다. 모두 "나누고, 모으고, 찾는" 자료구조와 분산 처리의 응용입니다.

📖 학습 내용
  • ETL 파이프라인: 추출 → 변환 → 적재, Pandas로 데이터 정제 후 DB 적재
  • Kafka 심화: Topic, Partition, Consumer Group, 메시지 순서와 재처리 전략
  • Apache Spark: RDD와 DataFrame 개념, PySpark / Spark SQL로 대량 데이터 집계
  • Hadoop/HDFS 개념: 분산 저장과 블록 복제 원리 (실습보다 구조 이해 중심)
  • Elasticsearch: 인덱스와 매핑, 한국어 형태소 분석기, Query DSL로 검색 API 구현
  • ELK 파이프라인: Logstash 수집 → Elasticsearch 저장 → Kibana 대시보드
🔐 데이터 파이프라인 보안

수집한 데이터에는 개인정보가 섞이기 쉽습니다. 호주 Cyber Security 과정에서 배운 데이터 보호 개념을 적용합니다: 개인정보 마스킹, 파이프라인 접근 권한 분리(RBAC), 처리 이력의 감사 로그 기록.

💻 실습 프로젝트

1. 배치 ETL: 공공 데이터 CSV를 Pandas로 정제 → PostgreSQL 적재

2. 실시간 로그 파이프라인: AI 챗봇 요청 로그를 Kafka로 발행 → Spark로 사용 패턴 집계

3. 검색 API: Elasticsearch에 문서를 색인하고, Spring Boot에서 검색 API 제공

4. 운영 대시보드: Logstash → Elasticsearch → Kibana로 AI 사용량과 에러율 시각화
