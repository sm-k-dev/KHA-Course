AI SecurityPrompt Injection, 데이터 유출, 공급망, 위협 모델공격·방어 테스트 기록

Agent Architecture는 '누가 무엇을 하는가', Loop는 '언제 반복하고 멈추는가', Harness는 '어떻게 안전하고 재현 가능하게 실행하는가'를 다룹니다. Multi-Agent는 무조건 고급·우수한 구조가 아니며 비교 결과에 따라 채택합니다.

7. SentinelOps 통합 프로젝트

기반: NEXORA/SentinelOps 기존 구현을 보존하고, 기존 Java Dynamic Web Project에서 Spring Boot로의 전환 범위를 명시합니다. 개인·팀 기여를 구분합니다.

  1. 기초: REST API, 인증·인가, SQL/JPA, 테스트, API 계약.
  2. Security & Reliability: Domain Security Inspector, API Reliability Monitor, Secret Leak Detector, Webhook Security Gateway는 각각 독립된 기능으로 우선 구현하고 측정합니다.
  3. 운영: Docker·CI/CD·로그·메트릭·장애 시나리오를 연결합니다.
  4. AI: 로그 요약·RAG·읽기 전용 분석 Agent를 작은 기능부터 추가합니다.
  5. Agent Platform: 승인 기반 도구, 실행 제한, 감사 로그, Sub-Agent 평가 후 제품화합니다.

8. CS와 STEM 병행

CS: 메모리·JVM(자바), 자료구조(컬렉션), 네트워크(HTTP/TLS), OS(동시성), DB(인덱스·트랜잭션), 분산 시스템(Cloud/Queue)을 실습과 함께 연결합니다.

STEM: 우선 수학(함수·논리→확률·통계→벡터·선형대수→최적화·실험 설계). 물리·화학·생물·지구과학은 관심과 여유에 따라 병행하며, 과학 데이터 시뮬레이션·분석으로 연결할 수 있습니다.

권장 시간은 개발·프로젝트·취업 준비를 합쳐 주 15~22시간을 기준선으로 삼되, 학원·업무·면접 기간에는 줄입니다. STEM은 0~3시간 가변적으로 배정합니다.

9. 이해도 기반 운영

  1. 챕터 시작 전 2~3분 구두 설명과 짧은 코드 진단.
  2. 설명이 되면 실습·검증으로 이동하고, 막히는 개념만 집중 학습.
  3. 완료 조건: 원리 설명, 실행 가능한 구현, 정상·실패 테스트, 선택 근거 기록.
  4. 매월 코드/테스트/실험 결과/회고 4종 증거 보관.
  5. 3개월마다 진도·취업 우선순위·학습 시간·AI 도구 변화를 반영해 재계획.

10. 첫 4주 실행안 (현재 학원 진도와 연결)

1주: 현재 Java/Spring/SQL 수준 진단, 기존 SentinelOps 구조 및 기능 목록 정리. 2주: Spring Boot 3 기반 API 한 기능 이식, JUnit/MockMvc 테스트. 3주: 인증·인가와 예외·로그·시크릿 관리 점검. 4주: CI, README, 아키텍처 그림, 개인 기여 기록, 면접용 설명 5문항 작성. 팀 프로젝트 일정이 우선이면 이 계획은 축소합니다.

별도 AI 도구 활용 역량 통합 가이드는 제품 비교·IDE 도구·프롬프트·코딩 워크플로의 참고서로 유지합니다. 이 문서에는 제품 이름 중심 사용법 대신 에이전트 시스템을 직접 만드는 데 필요한 원리·설계·검증·운영을 넣었습니다.
