💡 왜 하나요? GitHub는 팀 공유 드라이브입니다. 계정이 있어야 팀장이 초대할 수 있습니다.
  1. https://github.com 접속 → 오른쪽 위 Sign up

    GitHub는 코드를 올리는 계정에 2단계 인증을 요구합니다. 노란 배너가 뜨거나 아래 순서로 직접 켭니다.

    ① 휴대폰에 Google Authenticator 또는 Microsoft Authenticator 앱 설치
    ② github.com 프로필 사진 → Settings → 왼쪽 Password and authentication → Enable two-factor authentication
    ③ 화면의 QR코드를 앱의 ＋ 버튼 → QR 스캔으로 찍기
    ④ 앱에 나온 6자리 숫자를 GitHub 칸에 입력 → Continue
    ⑤ Recovery codes 화면 → Download → 파일을 안전한 곳에 보관 → I have saved my recovery codes

    ⚠️ Recovery codes 파일을 절대 버리지 마세요 휴대폰을 잃어버렸을 때 계정에 들어갈 수 있는 유일한 열쇠입니다.
    🆘 로그인할 때마다 숫자를 물어봐요 정상입니다. 휴대폰 앱의 지금 보이는 6자리를 입력하세요. 숫자는 30초마다 바뀝니다.
  7. 이메일 인증 확인

    프로필 사진 → Settings → Emails에서 내 이메일 옆에 Unverified가 있으면 Resend verification email → 메일의 링크 클릭. 인증 안 된 계정은 초대 수락이 막힐 수 있습니다.

  8. Username을 팀장에게 전달

    아래 문장을 복사해서 단톡방에 보내세요.

👥 전원 11. 충돌(Conflict) 해결하기

두 사람이 같은 파일 같은 줄을 고치면 생깁니다. 당황하지 않고 순서대로 하면 됩니다.

💡 충돌이란? 문서 3번째 줄을 A는 "사과", B는 "바나나"로 바꿨을 때 컴퓨터가 "뭐가 맞아?" 하고 묻는 상황입니다. 사람이 골라주면 끝납니다.
📌 원칙: 충돌은 PR을 올린 팀원이 자기 브랜치에서 해결합니다 자기 코드를 가장 잘 알기 때문입니다. 팀장은 해결된 PR을 Merge만 합니다.

① 이클립스에서 해결 (추천)

  1. 내 브랜치 상태 확인: [CarProject2 feature/carlist]

    커밋 안 한 수정이 있으면 먼저 Commit 합니다.

  2. 프로젝트 우클릭 → Team›Fetch from Upstream
  3. Team›Merge... → Remote Tracking › origin/main 선택 → Merge

    = 최신 main을 내 브랜치로 가져와 섞기.

  4. 결과 Conflicting → 빨간 ◆ 아이콘 파일 열기

    Git Staging의 Unstaged Changes에도 빨간 표시로 모입니다.

  5. 표시 3줄을 지우고 남길 코드만 정리 → Ctrl+S
    😱 충돌 난 Top.jsp
    <nav class="main-menu">
  <a href="Main.jsp">홈</a>
<<<<<<< HEAD
  <a href="CarList.jsp">차량검색</a>
=======
  <a href="Login.jsp">로그인</a>
>>>>>>> refs/remotes/origin/main
</nav>
    😊 해결 후 Top.jsp (둘 다 살림)
    <nav class="main-menu">
  <a href="Main.jsp">홈</a>
  <a href="Login.jsp">로그인</a>
  <a href="CarList.jsp">차량검색</a>
</nav>
    표시뜻
    <<<<<<< HEAD여기부터 내 브랜치 코드
    =======경계선
    >>>>>>> …origin/main여기까지 main(남의) 코드
  6. Git Staging에서 그 파일을 Staged Changes로 끌어내리기 (Add to Index)

    빨간 ◆가 사라지면 해결 표시가 된 것입니다. 메시지는 "Merge remote-tracking branch 'origin/main'…"으로 자동 입력됩니다.

  7. Commit and Push...
  8. 👑 팀장: PR 새로고침 → 초록 Merge 버튼 확인 → 10장대로 Merge
✅ 이렇게 되면 성공 프로젝트 전체에 빨간 ◆가 없고, GitHub PR에 ✅ This branch has no conflicts가 뜹니다.
📌 표시를 직접 지우기 어렵다면 Merge Tool 충돌 파일 우클릭 → Team›Merge Tool. 왼쪽이 내 코드, 오른쪽이 main 코드입니다. 가운데 화살표 버튼으로 필요한 줄을 왼쪽으로 가져온 뒤 저장합니다.
⚠️ 너무 꼬여서 처음부터 다시 하고 싶어요 프로젝트 우클릭 → Team›Reset... → 내 브랜치(Local › feature/carlist) 선택 → Reset type Hard → Reset. 커밋 안 한 수정은 사라지니 충돌 정리 중에만 쓰세요.

② GitHub 웹에서 해결 (짧은 충돌일 때)

  1. PR 화면 Resolve conflicts
  2. 표시 3줄 지우고 코드 정리 → Mark as resolved → Commit merge
  3. 해결한 사람도 이클립스에서 Team›Pull

    웹에서 만든 커밋을 내 PC로 받아야 다음 Push가 거절되지 않습니다.

❓ 자주 묻는 질문 (눌러서 펼치기)

Q1. Git Bash나 Git 프로그램을 따로 설치해야 하나요?

아니요. Enterprise Java and Web 판 이클립스에는 Git 기능(EGit)이 들어 있습니다. 이 문서의 이클립스 메뉴만으로 끝까지 가능합니다.

Q2. 실수로 main에서 코딩하고 있었어요. 아직 커밋 전이에요.

괜찮습니다. 저장(Ctrl+S)만 한 상태에서 Team › Switch To › New Branch...로 내 브랜치를 만들면 수정 내용이 그대로 새 브랜치로 따라옵니다. 거기서 커밋하세요.

Q3. Pull을 했는데 팀원 파일이 안 보여요.

① 프로젝트 클릭 후 F5 ② 지금 브랜치가 main인지 확인 ③ 팀장이 정말 Merge 했는지 GitHub에서 🟣 Merged 확인.

Q4. Commit만 하고 Push를 깜빡했어요.

이름 옆에 ↑1이 보입니다. 프로젝트 우클릭 › Team › Push to Upstream 을 누르면 올라갑니다.

Q5. 토큰이 만료됐어요 / 토큰을 잃어버렸어요.

2장대로 새 토큰 발급 → 13장 에러 사전의 Secure Storage에서 github.com 항목 삭제 → 다음 Push/Pull 때 새 토큰 입력.

Q6. 다른 컴퓨터(집/학원)에서도 이어서 하고 싶어요.

새 컴퓨터에서 3장 설정 → 7장 Clone을 한 번 하면 됩니다. 이후엔 시작할 때 Pull, 끝날 때 Push만 지키면 두 컴퓨터가 같아집니다. 커밋 안 하고 컴퓨터를 옮기면 코드가 따라오지 않습니다.

Q7. 팀장이 너무 바빠요. 팀원이 Merge 해도 되나요?

기술적으로 가능하지만, 누가 합쳤는지 헷갈려 사고가 납니다. 팀장이 부재 시 대신할 부팀장 1명을 미리 정하세요.

Q8. JSP 파일 이름을 바꾸거나 폴더를 옮겼어요.

이클립스에서 우클릭 › Refactor › Rename 으로 바꾸면 Git이 자동으로 인식합니다. Git Staging에서 ＋＋ 후 커밋하면 됩니다. 탐색기(윈도우 폴더)에서 직접 바꾸지 마세요.

Q9. DB 연결 정보(아이디/비번)가 팀원마다 달라요.

수업용이면 팀 전체가 같은 연습 계정(예: 오라클 scott)을 만들어 쓰는 것이 가장 쉽습니다. 개인 비밀번호는 절대 커밋하지 마세요.

Q10. 모든 게 꼬여서 처음부터 다시 받고 싶어요. (팀원)

① 내 코드 중 안 올린 파일은 바탕화면에 복사 ② 프로젝트 우클릭 › Delete → ☑ Delete project contents on disk ③ 7장 Clone 다시 ④ 백업한 파일 붙여넣기 → 커밋. GitHub에 있는 코드는 사라지지 않습니다.
