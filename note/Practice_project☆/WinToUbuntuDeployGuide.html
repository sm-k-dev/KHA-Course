1. C:\ 경로 문제 — 가장 많이 터지는 곳

윈도우 전용 경로가 코드에 박혀 있으면 리눅스에서 기능이 통째로 죽습니다.

💡 왜 문제인가 윈도우는 C:\file_repo_edu 처럼 드라이브 문자와 역슬래시(\)를 씁니다.
리눅스에는 C 드라이브 자체가 없고, 경로 구분은 슬래시(/)입니다.
그래서 이 한 줄 때문에 자료실 게시판의 업로드·다운로드가 전부 실패합니다.

실제로 바뀐 코드 (util/FileRepo.java)

❌ 변경 전 (윈도우 전용)
// 첨부파일 저장소 최상위 폴더
private static final String DEFAULT_ROOT
        = "C:\\file_repo_edu";
✅ 변경 후 (양쪽 모두 동작)
// 운영체제에 맞는 경로를 자동으로 고른다
private static final String DEFAULT_ROOT
        = AppConfig.getFileRepoRoot();

새로 만든 도우미 클래스 (util/AppConfig.java)

public static String getFileRepoRoot() {

    // 윈도우면 C 드라이브, 리눅스면 /var/webapp/file_repo 를 기본값으로 쓴다
    String def = isWindows() ? "C:\\file_repo_edu"
                             : "/var/webapp/file_repo";

    // 1순위 JVM 옵션  2순위 환경변수  3순위 위 기본값
    return get("file.repo.path", "FILE_REPO_PATH", def);
}
🧩 3단계 우선순위란? 값을 찾는 순서를 정해 두는 방식입니다.
1순위 JVM 옵션 -Dfile.repo.path=... → 임시로 바꿀 때
2순위 환경변수 FILE_REPO_PATH → 서버에서 상시 사용
3순위 기본값 → 아무것도 안 했을 때 (개발 PC는 이걸로 충분)

폴더 자동 생성도 함께 넣었습니다

❌ 변경 전
public static File getRoot() {
    return new File(DEFAULT_ROOT);
}
✅ 변경 후
public static File getRoot() {
    File root = new File(DEFAULT_ROOT);
    if (!root.exists()) {
        root.mkdirs();   // 없으면 만든다
    }
    return root;
}
⚠️ 흔한 오류 증상 : 파일 업로드를 누르면 500 에러, 로그에 FileNotFoundException
원인 : 저장 폴더가 없거나 권한이 없음
해결 : 다음 레슨(2번)의 mkdir + chown 을 먼저 실행하세요.
🛠️ 미션 1
  • 내 프로젝트 전체에서 C:\ 가 들어간 줄을 찾아보세요.
  • 이클립스에서 Ctrl + H → File Search 탭 → 검색어에 C:\\ 입력
  • 주석이 아니라 실행되는 코드에 있는 것만 고치면 됩니다.
🧠 퀴즈 1 — 리눅스에서 C:\file_repo_edu 는 어떻게 될까요?
리눅스에는 드라이브 문자 개념이 없습니다. 자동 변환도 없습니다. 파일을 만들려다 실패해 예외가 발생합니다.

2. 폴더와 권한 — 코드만 고치면 안 되는 이유

코드가 폴더를 만들려 해도, 만들 권한이 없으면 실패합니다.

💡 왜 필요한가 리눅스는 폴더마다 주인이 정해져 있습니다.
/var 아래는 관리자(root) 소유입니다.
톰캣은 보통 tomcat 이라는 일반 계정으로 돌아가므로, 그냥 두면 폴더를 만들 수 없습니다.
  1. 톰캣이 어떤 계정으로 도는지 확인합니다 
    ps -ef | grep -i tomcat | head -2
     ubuntu@lightsail
    tomcat 1842 1 0 09:12 ? 00:00:31 /usr/lib/jvm/java-21.../bin/java ... ubuntu 3021 2880 0 09:40 pts/0 00:00:00 grep --color=auto -i tomcat
    맨 앞 단어가 실행 계정입니다. 위 예시는 tomcat. 숫자와 경로는 환경마다 다릅니다.
    ✅ 이렇게 나오면 성공맨 앞에 계정 이름(tomcat / ubuntu / root 중 하나)이 보이면 됩니다.
  2. 저장 폴더를 만들고 주인을 넘깁니다 
    sudo mkdir -p /var/webapp/file_repo/temp
sudo chown -R tomcat:tomcat /var/webapp/file_repo
sudo chmod -R 755 /var/webapp/file_repo

    ※ 1단계에서 확인한 계정이 ubuntu 였다면 tomcat:tomcat 을 ubuntu:ubuntu 로 바꾸세요.

  3. 제대로 되었는지 확인합니다 
    ls -ld /var/webapp/file_repo /var/webapp/file_repo/temp
     결과
    drwxr-xr-x 3 tomcat tomcat 4096 Sep 18 09:45 /var/webapp/file_repo drwxr-xr-x 2 tomcat tomcat 4096 Sep 18 09:45 /var/webapp/file_repo/temp
    날짜는 다를 수 있습니다. 소유자 두 칸이 톰캣 계정이면 성공입니다.
    ✅ 이렇게 나오면 성공소유자가 tomcat tomcat 으로 보이면 통과입니다.
🧩 명령어 뜻 풀이 mkdir -p : 중간 폴더까지 한 번에 만들기
chown : change owner, 주인 바꾸기
chmod 755 : 주인은 읽기·쓰기·실행, 나머지는 읽기·실행
sudo : 관리자 권한으로 실행
⚠️ 흔한 오류 증상 : Permission denied 가 계속 뜬다
원인 : 톰캣 실행 계정과 폴더 소유자가 다름
해결 : 1단계에서 본 계정 이름을 정확히 넣어 chown 을 다시 실행 
sudo chown -R $(ps -o user= -p $(pgrep -f catalina | head -1)) /var/webapp/file_repo
🛠️ 미션 2
  • 폴더 3개 명령을 실행하고 ls -ld 결과를 눈으로 확인하세요.
  • 소유자가 톰캣 계정이 아니면 다시 chown 하세요.
🧠 퀴즈 2 — chown 명령은 무엇을 바꿀까요?
chown = change owner. 권한 숫자를 바꾸는 것은 chmod 입니다. 두 개를 세트로 기억하세요.

3. localhost 문제 — 카카오 로그인이 반드시 깨지는 이유

localhost 는 주소가 아니라 "나 자신"이라는 뜻입니다.

💡 왜 문제인가 localhost 는 특정 컴퓨터를 가리키는 주소가 아닙니다.
"지금 이 코드를 읽고 있는 컴퓨터 자신" 이라는 뜻입니다.
브라우저가 이 주소를 받으면 사용자 본인의 PC로 돌아갑니다. 서버로 오지 않습니다.
🧩 비유 편지 봉투에 받는 사람 주소를 "우리 집"이라고 쓴 것과 같습니다.
내가 부치면 나에게 오지만, 친구가 부치면 친구 집으로 갑니다.

실제로 바뀐 코드 (Service/MemberService.java)

❌ 변경 전
private static final String KAKAO_REDIRECT_URI
  = "http://localhost:8081/CarProject"
  + "/member/kakaoCallback.me";
✅ 변경 후
private static final String KAKAO_REDIRECT_URI
  = util.AppConfig.getBaseUrl()
  + "/member/kakaoCallback.me";

서버 주소는 환경변수로 알려 줍니다

export APP_BASE_URL="http://내서버IP:8080/CarProject"

실제 예시 : export APP_BASE_URL="http://3.39.207.123:8080/CarProject"

⚠️ 흔한 오류 — KOE006 증상 : 카카오 로그인 클릭 시 KOE006 오류 화면
원인 : 카카오 개발자센터에 등록한 Redirect URI 와 코드가 만든 주소가 다름
해결 : 아래 주소를 한 글자도 틀리지 않게 개발자센터에 등록 
http://내서버IP:8080/CarProject/member/kakaoCallback.me
끝의 / 유무, 포트 번호, 대소문자까지 전부 일치해야 합니다.
🛠️ 미션 3
  • 내 Lightsail 인스턴스의 퍼블릭 IPv4 주소를 콘솔에서 확인하세요.
  • 그 IP로 APP_BASE_URL 문장을 완성해 메모장에 적어 두세요.
🧠 퀴즈 3 — 서버 코드에 localhost 를 그대로 두면?
localhost 는 "이 컴퓨터 자신"입니다. 브라우저에서 해석되므로 사용자 PC로 돌아가 버립니다.

4. API 키 분리 — 요금 폭탄을 막는 습관

키가 소스에 박혀 있으면 파일을 넘기는 순간 함께 넘어갑니다.

💡 왜 위험한가 API 키는 사용한 만큼 요금이 청구되는 신용카드와 같습니다.
소스에 적어 두면 GitHub 업로드, WAR 전달, 화면 공유만으로 유출됩니다.
실제로 GitHub에 올라간 키는 몇 분 안에 자동 수집 프로그램에 발견됩니다.

실제로 바뀐 코드 (Controller/ChatbotController.java)

❌ 변경 전
private static final String API_KEY
        = "sk-or-v1-실제키가그대로";
✅ 변경 후
private static final String API_KEY =
  util.AppConfig.get("openrouter.api.key",
                     "OPENROUTER_API_KEY",
                     "본인 key");

키는 서버의 쪽지에만 적습니다

export OPENROUTER_API_KEY="sk-or-v1-여기에본인키"
export KAKAO_REST_API_KEY="카카오_REST_API_키"
✅ 이렇게 되면 성공 WAR 파일 안을 아무리 뒤져도 키가 나오지 않습니다.
키를 바꿔도 재컴파일 없이 서버 쪽지만 고치면 됩니다.
⚠️ 이미 소스에 키를 넣어 공유한 적이 있다면 그 키는 이미 유출된 것으로 간주하세요.
발급처 사이트에서 기존 키를 삭제(Revoke) 하고 새로 발급받는 것이 유일한 해결입니다.
🛠️ 미션 4
  • 내 프로젝트에서 sk- 로 시작하는 문자열을 검색해 보세요.
  • 하나라도 나오면 그 키는 폐기 대상입니다.
🧠 퀴즈 4 — API 키를 소스코드에 적으면 안 되는 가장 큰 이유는?
키는 요금이 청구되는 수단입니다. 코드 밖(환경변수)에 두면 파일을 넘겨도 키는 남지 않습니다.

5. DB 접속 설정 — 자리표시자를 반드시 치우기

"MySQL서버IP주소" 같은 글자가 남아 있으면 100% 연결 실패입니다.

💡 자리표시자란 "여기에 나중에 실제 값을 넣으세요"라는 빈칸 표시입니다.
사람은 알아보지만 프로그램은 그냥 주소 이름으로 읽습니다.
그런 이름의 서버는 세상에 없으므로 연결이 실패합니다.

실제로 바뀐 설정 (META-INF/context.xml)

❌ 변경 전
url="jdbc:mysql://MySQL서버IP주소:3306
     /rentcar_edu?..."
✅ 변경 후
url="jdbc:mysql://localhost:3306
     /rentcar_edu?...&useUnicode=true"
🧩 여기서는 localhost 가 맞습니다 3번 레슨과 헷갈리기 쉽습니다. 기준은 누가 그 주소를 읽는가입니다.
브라우저가 읽는 주소(카카오 Redirect) → localhost 금지
서버 자신이 읽는 주소(DB 접속) → 같은 서버에 MySQL이 있으면 localhost 정답

DB와 전용 계정 만들기

sudo mysql -u root -p <<'EOF'
CREATE DATABASE IF NOT EXISTS rentcar_edu
  DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
CREATE USER IF NOT EXISTS 'carapp'@'localhost' IDENTIFIED BY '강한비밀번호';
GRANT ALL PRIVILEGES ON rentcar_edu.* TO 'carapp'@'localhost';
FLUSH PRIVILEGES;
EOF

설정 파일의 계정을 바꿉니다

sudo nano /opt/tomcat/webapps/CarProject/META-INF/context.xml
항목바꾸기 전바꾼 뒤
usernamerootcarapp
password0000본인이 정한 비밀번호

nano 저장 방법 : Ctrl+O → Enter → Ctrl+X

⚠️ 흔한 오류 증상 : Communications link failure
원인 : MySQL이 안 켜져 있거나 주소가 틀림
해결 
sudo systemctl status mysql --no-pager | head -5
증상 : Access denied for user → 계정/비밀번호 불일치입니다.
🛠️ 미션 5
  • DB와 전용 계정을 만들고, context.xml 의 계정을 바꾸세요.
  • root/0000 이 남아 있지 않은지 확인하세요.
🧠 퀴즈 5 — DB 접속 주소에 localhost 를 써도 되는 경우는?
DB 주소는 서버 자신이 읽습니다. 같은 서버 안에 MySQL이 있으면 localhost 가 정답입니다.

6. MySQL 드라이버 위치 — 왜 두 군데에 두나

커넥션풀을 만드는 주체가 톰캣이기 때문입니다.

💡 커넥션풀과 JNDI 커넥션풀 : DB 연결을 미리 여러 개 만들어 두고 돌려 쓰는 주차장입니다.
JNDI : 그 주차장을 jdbc/jspbeginner 같은 이름표로 찾는 방식입니다.
이 주차장을 만드는 주체가 톰캣 자신이라, 드라이버도 톰캣이 보는 자리에 있어야 합니다. 
sudo cp /opt/tomcat/webapps/CarProject/WEB-INF/lib/mysql-connector-java-8.0.25.jar /opt/tomcat/lib/
sudo chown tomcat:tomcat /opt/tomcat/lib/mysql-connector-java-8.0.25.jar
ls -l /opt/tomcat/lib/mysql-connector-java-8.0.25.jar
 결과
-rw-r--r-- 1 tomcat tomcat 2481933 Sep 18 09:52 /opt/tomcat/lib/mysql-connector-java-8.0.25.jar

8. 한글 깨짐과 9시간 오차

서버의 기본 언어·시간대가 한국 기준이 아니기 때문입니다.

💡 왜 생기나 우분투 서버는 기본 시간대가 UTC(협정 세계시)입니다. 한국보다 9시간 느립니다.
기본 문자 인코딩도 한국어 기준이 아니어서 한글이 ??? 로 저장될 수 있습니다. 
export JAVA_OPTS="$JAVA_OPTS -Dfile.encoding=UTF-8 -Duser.timezone=Asia/Seoul"
옵션뜻없으면
-Dfile.encoding=UTF-8글자를 UTF-8로 처리한글이 ??? 로 깨짐
-Duser.timezone=Asia/Seoul시간대를 서울로등록일시가 9시간 어긋남

서버 시간대 자체도 맞춰 둡니다

sudo timedatectl set-timezone Asia/Seoul
date
 결과
2026. 09. 18. (금) 18:52:31 KST
끝에 KST 가 보이면 성공입니다. 시각은 당연히 다릅니다.
✅ 이렇게 나오면 성공끝에 KST 가 표시되면 통과입니다.
⚠️ 흔한 오류 증상 : 글은 잘 써지는데 목록에서만 한글이 깨진다
원인 : DB 문자셋이 utf8mb4 가 아님
확인 
sudo mysql -e "SHOW VARIABLES LIKE 'character_set_database';"
결과가 utf8mb4 가 아니면 DB를 다시 만들어야 합니다.
🛠️ 미션 8
  • 시간대를 서울로 바꾸고 date 로 KST 를 확인하세요.
  • JAVA_OPTS 문장을 메모장에 복사해 두세요. 11번 레슨에서 씁니다.
🧠 퀴즈 8 — 우분투 서버의 기본 시간대는?
기본은 UTC 입니다. 그대로 두면 게시글 등록 시각이 9시간 과거로 표시됩니다.

9. 방화벽과 톰캣 버전 — 여기서 막히면 아무것도 안 됩니다

두 가지는 타협 불가입니다. 먼저 확인하고 넘어가세요.

💡 방화벽이란 서버의 현관문입니다. 기본은 전부 잠겨 있습니다.
웹 접속에 쓰는 8080 번 문을 직접 열어 주어야 브라우저가 들어올 수 있습니다.

Lightsail 방화벽 열기 (콘솔 화면)

 Amazon Lightsail — 인스턴스 → 네트워킹
방화벽 규칙 ┌──────────────┬──────────┬─────────────────────┐ │ 애플리케이션 │ 프로토콜 │ 포트 │ ├──────────────┼──────────┼─────────────────────┤ │ SSH │ TCP │ 22 │ │ HTTP │ TCP │ 80 │ │ 사용자 지정 │ TCP │ 8080 ← 이걸 추가 │ └──────────────┴──────────┴─────────────────────┘ 소스 IP : 모든 IPv4 주소
실제 화면 구성은 예시입니다. [+ 규칙 추가] → 추가 → [업데이트 규칙] 순서로 저장합니다.
⚠️ 가장 많이 놓치는 부분 소스 IP를 내 PC의 IP 하나로 지정하면 다른 사람은 접속하지 못합니다.
수업·시연용이면 모든 IPv4 주소로 두세요.
그리고 [추가] 버튼을 누른 뒤 반드시 [업데이트 규칙]까지 눌러야 저장됩니다.

톰캣 버전 확인 — 반드시 9.x

/opt/tomcat/bin/version.sh | grep "Server number"
 결과
Server number: 9.0.98.0
앞자리가 9 여야 합니다. 10 이상이면 앱이 아예 기동되지 않습니다.
💡 왜 톰캣 10 이상은 안 되나 톰캣 10부터 패키지 이름이 javax.servlet → jakarta.servlet 로 통째로 바뀌었습니다.
이름이 바뀐 것이라 호환되지 않습니다. 이 프로젝트는 javax 기반이므로 톰캣 9가 필요합니다.
✅ 이렇게 나오면 성공 Server number: 9.x.x 가 보이고, 브라우저에서 http://내IP:8080 이 열리면 통과입니다.
🛠️ 미션 9
  • Lightsail 방화벽에 TCP 8080 / 모든 IPv4 를 추가하세요.
  • 톰캣 버전이 9.x 인지 확인하세요.
🧠 퀴즈 9 — 톰캣 10에서 이 프로젝트가 안 되는 이유는?
패키지 이름 자체가 바뀐 변화라 호환되지 않습니다. 반드시 Tomcat 9.x 를 설치하세요.

10. 대소문자 함정 — 윈도우에서는 안 보이던 문제

윈도우는 구분하지 않고, 리눅스는 구분합니다.

💡 무슨 차이인가 윈도우에서 Main.jpg 와 main.jpg 는 같은 파일입니다.
리눅스에서는 완전히 다른 파일입니다.
그래서 개발 PC에서 잘 보이던 이미지가 서버에서만 깨집니다.
실제 파일명코드에 적힌 이름윈도우리눅스
Main.jpgMain.jpg✅✅
Main.jpgmain.jpg✅ 보임❌ 404
bl.JPGbl.jpg✅ 보임❌ 404

주소도 마찬가지입니다

 브라우저 주소창
http://3.39.207.123:8080/CarProject ← 정상 http://3.39.207.123:8080/carproject ← 404 http://3.39.207.123:8080/Carproject ← 404
WAR 파일명이 CarProject.war 이면 주소도 /CarProject 여야 합니다.
✅ 이번 프로젝트 점검 결과 이미지·CSS·JS 참조를 전수 검사한 결과 대소문자 불일치 0건이었습니다.
따라서 이 프로젝트에서는 추가 수정이 필요하지 않습니다.
⚠️ 앞으로를 위한 습관 파일명은 전부 소문자 + 하이픈으로 통일하세요. (예: main-banner.jpg)
한글 파일명, 공백이 든 파일명도 서버에서 문제가 됩니다.
🛠️ 미션 10
  • 내 프로젝트 img 폴더에서 대문자 확장자(.JPG, .PNG)를 찾아보세요.
  • 있다면 코드에서 어떻게 쓰고 있는지 대조해 보세요.
🧠 퀴즈 10 — 파일이 bl.JPG 인데 코드가 bl.jpg 이면?
윈도우는 대소문자를 구분하지 않아 개발 중에는 보입니다. 서버에 올린 뒤에야 깨져서 원인 찾기가 어렵습니다.

11. 전체 배포 실습 — 처음부터 끝까지

지금까지 배운 것을 순서대로 한 번에 실행합니다.

  1. 환경 확인 
    ps -ef | grep -i tomcat | head -1
/opt/tomcat/bin/version.sh | grep "Server number"
    ✅ 통과 기준실행 계정 확인 + Server number 가 9.x
  2. WAR 파일 업로드 (내 PC 터미널에서 실행) 
    scp -i 내키.pem CarProject.war ubuntu@내서버IP:/tmp/

    실제 예시 : scp -i LightsailKey.pem CarProject.war ubuntu@3.39.207.123:/tmp/

  3. 톰캣에 배치 
    sudo systemctl stop tomcat
sudo rm -rf /opt/tomcat/webapps/CarProject /opt/tomcat/webapps/CarProject.war
sudo cp /tmp/CarProject.war /opt/tomcat/webapps/
sudo chown tomcat:tomcat /opt/tomcat/webapps/CarProject.war
  4. 저장 폴더 준비 
    sudo mkdir -p /var/webapp/file_repo/temp
sudo chown -R tomcat:tomcat /var/webapp/file_repo
sudo chmod -R 755 /var/webapp/file_repo
  5. 환경변수 쪽지 만들기 — IP와 키 2개만 바꾸세요 
    sudo tee /opt/tomcat/bin/setenv.sh > /dev/null <<'EOF'
#!/bin/sh
export FILE_REPO_PATH="/var/webapp/file_repo"
export APP_BASE_URL="http://내서버IP:8080/CarProject"
export KAKAO_REST_API_KEY="카카오_REST_API_키"
export KAKAO_CLIENT_SECRET=""
export OPENROUTER_API_KEY="sk-or-v1-여기에본인키"
export JAVA_OPTS="$JAVA_OPTS -Dfile.encoding=UTF-8 -Duser.timezone=Asia/Seoul -Xms256m -Xmx768m"
EOF

sudo chmod +x /opt/tomcat/bin/setenv.sh
sudo chown tomcat:tomcat /opt/tomcat/bin/setenv.sh
  6. 톰캣 시작 → WAR 자동 압축 해제 
    sudo systemctl start tomcat
sleep 20
ls /opt/tomcat/webapps/CarProject/ | head -5
    ✅ 통과 기준폴더 목록이 보이면 WAR 압축 해제 성공입니다.
  7. MySQL 드라이버 복사 → 다시 시작 
    sudo cp /opt/tomcat/webapps/CarProject/WEB-INF/lib/mysql-connector-java-8.0.25.jar /opt/tomcat/lib/
sudo systemctl restart tomcat
  8. DB 계정 수정 
    sudo nano /opt/tomcat/webapps/CarProject/META-INF/context.xml

    username / password 를 내가 만든 계정으로 변경 → Ctrl+O → Enter → Ctrl+X → 다시 재시작

  9. 로그 확인 
    tail -n 40 /opt/tomcat/logs/catalina.out
     정상 로그 예시
    org.apache.catalina.startup.HostConfig.deployWAR Deploying web application archive [/opt/tomcat/webapps/CarProject.war] Deployment of web application archive ... has finished in [4,812] ms Server startup in [6123] milliseconds
    숫자는 환경마다 다릅니다. Server startup 줄이 보이면 정상 기동입니다.
    ✅ 통과 기준Server startup in [...] 가 보이고, 그 위에 빨간 Exception 이 없으면 성공입니다.
  10. 브라우저로 접속 
    http://내서버IP:8080/CarProject
⚠️ 화면이 안 뜰 때 순서대로 확인 1) Lightsail 방화벽 8080 열렸나 → 안 열리면 브라우저가 계속 로딩만 합니다.
2) 주소 대소문자 맞나 → /CarProject
3) 톰캣이 살아 있나 
sudo systemctl status tomcat --no-pager | head -6
4) 로그에 Exception 이 있나 
grep -i "exception\|severe" /opt/tomcat/logs/catalina.out | tail -20

  • 10단계를 순서대로 실행해 브라우저에서 메인 화면을 띄우세요.
  • 중간에 막히면 그 단계의 ⚠️ 박스를 먼저 읽으세요.
