💡 핵심 개념 5가지 (쉽게 이해하기)

🔧 1. Git이란?

코드의 변경 이력을 관리하는 프로그램입니다. 누가, 언제, 어떤 코드를 수정했는지 기록하고, 이전 버전으로 되돌릴 수도 있습니다.

📝 비유: 한글(HWP)의 "변경 내용 추적" 기능과 같습니다. 문서를 수정할 때마다 누가 뭘 바꿨는지 기록되는 것처럼, Git은 코드의 모든 변경을 기록합니다.
🐙 2. GitHub란?

Git으로 관리하는 코드를 인터넷에 저장하고 팀과 공유하는 서비스입니다. 구글 드라이브처럼 코드를 올리고 팀원끼리 함께 작업할 수 있습니다.

☁️ 비유: Git = 내 PC의 폴더, GitHub = 구글 드라이브. 내 폴더의 파일을 구글 드라이브에 올려서 팀원과 공유하는 것과 같습니다.
📦 3. Repository(저장소)란?

프로젝트 파일과 변경 이력을 저장하는 폴더입니다. 내 PC에 있는 것을 로컬 저장소, GitHub에 있는 것을 원격 저장소라고 합니다.

📂 비유: 로컬 저장소 = 내 책상 위 작업 폴더, 원격 저장소 = 팀 공유 클라우드 폴더.
🌿 4. Branch(브랜치)란?

메인 코드에서 복사본을 만들어 독립적으로 작업하는 공간입니다. 각 팀원이 자기 브랜치에서 작업하고, 완료되면 메인에 합칩니다.

🛤️ 비유: 기차 철로 분기점과 같습니다. 본선(main)에서 갈라져 나가서 작업한 뒤, 다시 본선에 합류(merge)합니다.
🔄 5. Commit, Push, Pull이란?

Commit = 변경 내역을 내 PC에 저장 (세이브포인트 만들기)
Push = 내 PC의 커밋을 GitHub에 업로드 (팀원에게 공유)
Pull = GitHub의 최신 코드를 내 PC로 다운로드 (팀원 작업 받기)

🎮 비유: Commit = 게임 세이브, Push = 세이브 파일을 클라우드에 업로드, Pull = 클라우드에서 세이브 파일 다운로드

🖥️ Git Bash 기초 터미널 명령어 (처음 쓰는 사람 필독!)

❓ Git Bash란?

Git을 사용하기 위한 명령어 입력 프로그램입니다. 마우스 클릭 대신 글자를 타이핑해서 컴퓨터에게 명령합니다.

⌨️ 비유: 카카오톡에서 친구에게 메시지 보내듯, Git Bash에 "명령어를 입력"하면 컴퓨터가 실행합니다.
ℹ️ 반드시 알아야 할 기초 명령어 4개
명령어의미사용 예시
pwd현재 내가 어디 있는지 확인pwd → /c/Users/홍길동
ls현재 폴더 안의 파일/폴더 목록 보기ls → 파일 이름들이 나열됨
cd 폴더명해당 폴더로 이동cd eclipse-workspace
cd ..상위(부모) 폴더로 이동cd .. → 한 칸 위로
⚠️ Git Bash 경로 표기 주의!

Windows 탐색기: C:\Users\홍길동\eclipse-workspace (역슬래시 \)
Git Bash에서는: /c/Users/홍길동/eclipse-workspace (슬래시 /로 변환!)
드라이브 C: → /c, D: → /d 로 바뀝니다.

Git Bash — 기초 명령어 연습 (지금 바로 따라 해보세요!)
# 1. 현재 위치 확인 (나 지금 어디 폴더에 있지?)
pwd

# 2. 현재 폴더의 파일/폴더 목록 보기
ls

# 3. eclipse-workspace 폴더로 이동 (★ 본인 사용자명으로 변경!)
cd /c/Users/$USER/eclipse-workspace

# 4. 이동 후 위치 다시 확인

# 5. 프로젝트 폴더 목록 보기
ls
💜 팁: Tab키로 자동완성!

프로젝트 폴더 구조 (CarProject2 예시)
CarProject2/                      ← 프로젝트 루트
├── src/main/java/               ← ✅ Java 소스 (Controller, DAO, VO)
│   └── com/smrental/
│       ├── controller/CarController.java
│       ├── dao/CarDAO.java
│       └── vo/CarVO.java
├── src/main/webapp/             ← ✅ 웹 파일 (JSP, CSS, JS, 이미지)
│   ├── WEB-INF/web.xml
│   ├── css/style.css
│   ├── js/script.js
│   ├── Top.jsp, Main.jsp, CarList.jsp ...
├── .settings/                    ← ❌ 제외! (Eclipse 설정)
├── .classpath                    ← ❌ 제외! (Eclipse 설정)
├── .project                      ← ❌ 제외! (Eclipse 설정)
├── build/ 또는 bin/              ← ❌ 제외! (컴파일 결과물)
└── .gitignore                    ← ✅ Git 제외 목록 파일
✅ Git으로 관리 = 팀원이 직접 작성한 코드

src/main/java/ (Java), src/main/webapp/ (JSP, CSS, JS)

❌ Git에서 제외 = Eclipse가 자동 생성하는 설정

.settings/, .classpath, .project, build/ — 각 PC마다 달라서 공유하면 오류!

④ .gitignore 파일 만들기 [🟢 팀장만 실행]

❓ .gitignore란?

"이 파일은 Git에 올리지 마!"라고 적는 목록 파일입니다. Eclipse 설정 파일, 컴파일 결과물 등 팀원과 공유할 필요 없는 파일을 여기에 적습니다.

🚫 비유: 택배 보낼 때 "이건 포장하지 마" 목록과 같습니다. 불필요한 것은 빼고 필요한 것만 보냅니다.
❌ .gitignore가 없으면 이런 문제 발생!

① Eclipse 설정 파일(.settings/)이 올라가서 → 팀원 PC에서 프로젝트 오류 발생
② .class 파일(bin/)이 올라가서 → 저장소 용량만 쓸데없이 증가
③ 각자 PC별 설정이 섞여서 → 매번 충돌 발생

Git Bash — .gitignore 파일 생성 (아래 전체를 복사 → 붙여넣기 → Enter!)
cat > .gitignore <<'EOF'
# ========================================
# Eclipse Dynamic Web Project (JSP MVC)
# Git 제외 파일 목록
# ========================================

# --- Eclipse 설정 파일 (각 PC마다 달라서 공유하면 오류!) ---
.settings/
.project
.classpath

# --- 컴파일 결과물 (빌드하면 자동 생성됨) ---
bin/
build/
target/
*.class
*.war
*.ear

# --- Tomcat 서버 관련 ---
.tomcat/
work/
Servers/

# --- OS가 자동 생성하는 파일 ---
Thumbs.db
Desktop.ini
.DS_Store

# --- 기타 IDE 설정 (IntelliJ, VS Code 등) ---
*.iml
.idea/
.vscode/

# --- 로그 파일 ---
*.log
EOF

부분의미왜 필요한가?

<<'EOF' ~ EOF여러 줄을 한 번에 입력하는 방법EOF를 만나면 입력이 끝남
# 주석#으로 시작하는 줄은 설명(주석)Git이 무시하는 줄, 사람이 읽기 위한 메모
.settings/Eclipse 프로젝트별 설정 폴더각자 PC마다 달라서 공유하면 Eclipse 오류!
.projectEclipse 프로젝트 파일Eclipse가 자동 생성, 공유 불필요
.classpathEclipse의 Java 빌드 경로 설정각자 PC의 JDK/라이브러리 경로가 다름
bin/컴파일된 .class 파일 폴더빌드하면 자동 생성 → 올릴 필요 없음
*.classJava 컴파일 결과 파일*은 "모든"이라는 뜻 → 모든 .class 파일 제외
*.war웹 애플리케이션 배포 파일용량이 크고, 빌드하면 자동 생성됨
Thumbs.dbWindows 썸네일 캐시Windows가 자동 생성, 코드와 무관
.DS_StoreMac 폴더 설정 파일Mac이 자동 생성, 코드와 무관
