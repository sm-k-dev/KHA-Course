# NEXORA AI Gateway: 한 페이지 스펙

> 상태: 설계 기준선 (확정) / 팀·기간: 미정

## 1. 주제
정책 기반 AI 요청 보안 게이트웨이.
API 키로 요청을 인증하고, 규칙 기반 검사로 허용·마스킹·차단한 뒤 결과를 감사 로그로 남기는 Spring Boot 서비스.

- 세미 NEXORA의 "탐지·기록"을 "요청 경로에서의 판정·통제"로 확장
- 발표 시 "공격을 확실히 판별한다"가 아니라 "정책에 따라 위험 요청을 검사하고 조치한다"로 설명

## 2. 요청 흐름
1. 클라이언트가 `/v1/chat`에 API 키와 프롬프트를 보냄
2. API 키 인증 (실패 시 401, 인증 실패 이벤트 기록)
3. 규칙 엔진이 프롬프트를 검사 (원문은 메모리에서만 사용)
4. 판정: 허용 / 마스킹 / 차단
5. 판정 결과를 로그에 먼저 기록
6. 허용·마스킹은 모델 호출(Mock) → 결과 갱신, 차단은 모델 호출 없이 거부
7. 응답 반환

## 3. 판정과 로그 상태

| 판정 | 모델 호출 | 로그 상태 흐름 |
|---|---|---|
| 허용 | 호출 | `PENDING` → `SUCCESS` 또는 `MODEL_ERROR` |
| 마스킹 | 마스킹된 내용으로 호출 | `PENDING` → `SUCCESS` 또는 `MODEL_ERROR` |
| 차단 | 호출 안 함 | `BLOCKED` (한 번에 기록) |

- `PENDING`이 오래 남아 있으면 미완료 요청으로 조회 가능 (타임아웃·프로세스 종료 발견용)

## 4. 실패 정책

| 상황 | 동작 |
|---|---|
| 허용·마스킹 요청의 최초 기록(`PENDING`) 실패 | 모델 호출 안 함, 서버 오류 반환 |
| 모델 응답 후 최종 상태 갱신 실패 | 성공 응답 반환하지 않음, 오류 반환 (트레이드오프: 모델은 응답했음을 문서에 명시) |
| 차단 로그 저장 실패 | 차단 유지, 외부 모델 호출 없음, 서버 운영 로그에 기록 실패 남김 |
| 인증 실패 | 요청 감사 로그와 분리된 보안 이벤트로 기록, 같은 시간 버킷 내 횟수 집계 |
| 정책 파일 로드 실패 | 서버 기동 중단 (잘못된 정책으로 판정하지 않음) |

## 5. 보안 원칙
- 원문 프롬프트는 로그·DB·응답 어디에도 저장하지 않음
- 로그에는 판정 결과, 규칙 코드, 정책 버전, 마스킹된 발췌만 기록
- 정책 버전은 사람이 읽는 버전 문자열과 설정 파일 해시를 함께 기록
- 원본 API 키는 저장하지 않음 (식별용 앞자리 또는 해시만)
- 차단 응답에는 규칙 상세를 노출하지 않고 일반 차단 코드만 반환 (규칙 상세는 관리자 로그에만)
- 관리자 로그인과 API 키 인증은 Spring Security 필터 체인을 분리

## 6. 범위

**MVP (필수)**
- API 키 인증 (발급은 초기 데이터 또는 간단한 등록 방식)
- `/v1/chat` 요청 처리 흐름 전체 (Mock 응답)
- 규칙 엔진 3~5개, 허용·마스킹·차단 판정
- 판정·상태·정책 버전을 포함한 감사 로그 저장
- 정책은 설정 파일로 분리, 읽기 전용
- 관리자 로그 목록·상세 조회 (읽기 전용)
- Swagger 문서, 핵심 테스트

**여력 있으면**
- 키별 요청 한도 (DB 카운트 기반으로 시작)
- Actuator·Micrometer 메트릭
- 실제 LLM 연동 (설정으로 Mock과 전환, 사용자 입력이 외부로 전송된다는 점을 문서에 명시)
- Slack 알림

**제외**
- 멀티테넌트 완전 분리, Redis 한도, Kafka, 결제, 게시판·문의 재구현
- 정책 편집 화면 (정책 변경은 설정 파일과 재시작으로)

## 7. 완료 기준 (통합 테스트)
1. 키 없음·잘못된 키 → 401, 인증 실패 이벤트 기록
2. 정상 요청 → 허용, Mock 응답 반환, 로그 `SUCCESS`
3. 개인정보 포함 요청 → 마스킹된 내용이 모델 호출에 전달, 응답에 `MASK` 표시
4. 공격 패턴 요청 → 차단, 외부 모델 호출 0회, 로그 `BLOCKED`
5. 인증된 요청 → 감사 로그 1건 이상 기록, 인증 실패 → 보안 이벤트에 기록 (두 기록은 분리). 어떤 기록에도 원문 프롬프트 없음
6. 로그 기록 실패 → 허용·마스킹 요청은 모델 미호출, 차단 요청은 차단 유지
7. 카나리 개인정보 값(예: `010-9999-8888`)이 모델 전달 내용, DB 로그, 로그 파일, 예외 메시지 어디에도 없음 (테스트 환경 안에서 확인)
8. `PENDING`으로 남은 요청을 조회할 수 있음

## 8. 구현 순서
1. API 키 인증 + `/v1/chat` 골격
2. 규칙 엔진과 판정 적용
3. 감사 로그 (`PENDING`/`SUCCESS`/`MODEL_ERROR`/`BLOCKED`)
4. 관리자 로그 조회 (읽기 전용)
5. 실패 정책과 카나리 테스트
6. 여력 항목
