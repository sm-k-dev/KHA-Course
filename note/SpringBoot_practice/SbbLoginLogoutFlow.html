▶ 호출하는 곳
프로그램을 시작하면 Spring이 filterChain() 메서드를 호출합니다.
↩ 리턴하는 곳
return http.build()로 만든 SecurityFilterChain 객체를 Spring에 리턴하고, Spring이 보관합니다.
  1. 이 단계는 사용자가 요청을 보내기 전, 서버가 켜질 때 한 번 실행됩니다.
  2. formLogin은 로그인 화면 주소와 로그인 성공 후 이동 주소를 등록합니다.
  3. logout은 로그아웃 주소, 로그아웃 후 이동 주소, 세션 삭제 여부를 등록합니다.
  4. 같은 시점에 passwordEncoder(), authenticationManager() 메서드도 호출되어 객체가 등록됩니다.
  5. @Service가 붙은 UserSecurityService 객체도 이때 만들어집니다.

🧠 확인 퀴즈

1. 로그인 버튼을 눌렀을 때 오는 POST /user/login 요청은 어디서 처리하나요?
💡 loginPage("/user/login")로 정한 주소의 POST 요청은 Security 필터가 가로채 처리합니다. 그래서 Controller에 POST 메서드를 만들지 않습니다.
2. loadUserByUsername() 메서드를 호출하는 곳은 어디인가요?
💡 AuthenticationManager는 UserDetailsService를 구현한 UserSecurityService 객체를 자동으로 연결해 두고, 로그인 검사 때 이 메서드를 호출합니다.
3. 로그인 후 navbar에 [로그아웃] 링크가 보이는 이유는 무엇인가요?
💡 인증 성공 시 세션에 저장된 정보 때문에 sec:authorize="isAuthenticated()"가 true가 됩니다.
4. 로그아웃 때 로그인 정보를 지우는 설정은 무엇인가요?
💡 invalidateHttpSession(true)가 세션을 삭제합니다. 세션 안의 로그인 정보도 함께 사라집니다.
