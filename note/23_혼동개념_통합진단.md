# 혼동 개념 통합 진단 — 한 개의 코드에서 층위를 분리하기

이 문서는 전 과목 공통 실습이다. 정답을 먼저 외우지 말고 **표현의 정체 → 반환값 → 책임 주체 → 실행 시점** 순서로 해석한다.

## 실습 1. List, ArrayList, 객체, 참조

```java
List<String> a = new ArrayList<>();
List<String> b = a;
a.add("one");
System.out.println(b.size()); // 1
```

- `List`는 인터페이스다. `ArrayList`는 구현 클래스다. `new ArrayList<>()`는 인스턴스를 생성한다.
- `a`와 `b`는 참조 변수다. 두 변수가 같은 객체를 가리키므로 `b.size()`는 1이다.
- **변형:** `b = new ArrayList<>();` 뒤에 `a.size()`와 `b.size()`를 각각 확인하라. 변수의 재대입이 기존 객체를 변경하는 것은 아니다.

## 실습 2. SQL 결과와 Java 반환 계약

```sql
SELECT * FROM users WHERE id = 999;
SELECT COUNT(*) FROM users WHERE id = 999;
SELECT NULL AS result;
```

- 첫 번째는 0행, 두 번째는 값 0을 가진 1행, 세 번째는 NULL을 가진 1행이다(테이블이 존재하고 id=999가 없다는 전제).
- JDBC `ResultSet.next()`가 false인 것은 다음 행이 없다는 뜻이다. `EntityManager.find`는 없으면 null, Spring Data JPA `findById`는 없으면 `Optional.empty()`라는 각각의 API 계약을 가진다.
- **변형:** 목록 조회 `findAll()`은 0건일 때 보통 빈 목록을 반환한다. 0행·null·빈 목록·Optional.empty를 섞어 설명하지 말자.

## 실습 3. 계층별 부재의 의미

```java
@GetMapping("/users/{id}")
UserResponse get(@PathVariable Long id) {
    User user = repository.findById(id)
        .orElseThrow(() -> new ResponseStatusException(HttpStatus.NOT_FOUND));
    return new UserResponse(user.getId(), user.getName());
}
```

- `findById`: Repository 반환 계약. `orElseThrow`: 애플리케이션의 부재 처리. `NOT_FOUND`: HTTP 응답 정책.
- `UserResponse`는 API DTO이고 `User`는 영속성 Entity일 수 있다. 둘은 동일한 역할이 아니다.
- **변형:** `GET /users` 목록 조회에서는 데이터가 없을 때 `200 []`를 선택할 수 있다. 단건 조회의 `404`와 구분하라.
