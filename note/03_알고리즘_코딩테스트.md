## 1. 시간 복잡도 (Big-O)

**정의** — 입력 크기 N이 커질 때 실행 시간이 얼마나 빠르게 늘어나는지를 나타내는 표기법이다. 정확한 초 단위가 아니라 증가하는 추세를 본다.

**목적과 책임** — 같은 문제를 푸는 여러 방법 중 어느 쪽이 큰 입력에서 버티는지 미리 판단한다.

**구별해야 할 개념 / 흔한 오해** — Big-O는 최악의 경우 또는 상한을 나타내는 경우가 많다. "빠른 컴퓨터에서 0.1초"는 복잡도가 아니다. N이 작으면 O(N²)도 빠를 수 있다.

**자주 쓰는 등급**

| 표기 | 예 | N = 10^5일 때 |
|---|---|---|
| O(1) | 배열에서 인덱스로 꺼내기, HashMap 조회(평균) | 바로 끝남 |
| O(log N) | 이진 탐색 | 약 17번 |
| O(N) | 전체를 한 번 훑기 | 10^5번 |
| O(N log N) | 병합 정렬, 힙 정렬 | 약 1.7×10^6번 |
| O(N²) | 이중 반복문 | 10^10번 (보통 시간 초과) |

**확인 방법:** 반복문이 중첩되면 곱한다. 입력을 반으로 나눠 가면 log N이다.

**면접 기준:** "입력 크기 N에 대해 연산 횟수가 어떻게 늘어나는지를 나타냅니다. 이중 반복문은 N²이라 N이 10^5 정도면 보통 제한 시간을 넘습니다."

## 2. 탐색: 순차 탐색과 이진 탐색

**정의** — 순차 탐색은 처음부터 끝까지 하나씩 확인한다(O(N)). 이진 탐색은 **정렬된 배열**에서 가운데 값과 비교해 범위를 절반씩 줄인다(O(log N)).

**구별해야 할 개념** — 이진 탐색은 정렬되어 있지 않으면 쓸 수 없다. 정렬 비용(O(N log N))을 고려해야 한다.

**구현 (검증 완료):**

```java
// 정렬된 배열에서 target의 인덱스를 찾는다. 없으면 -1.
static int binarySearch(int[] a, int target) {
    int lo = 0, hi = a.length - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;   // (lo + hi) / 2 는 값이 아주 클 때 int가 넘칠 수 있다
        if (a[mid] == target) return mid;
        if (a[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;
}
```

- **확인:** `{1, 3, 5, 7, 9, 11}`에서 7은 인덱스 3, 4는 -1.
- **흔한 실수:** `mid = (lo + hi) / 2`는 간단하지만 큰 값에서 오버플로가 날 수 있다. `lo + (hi - lo) / 2`를 쓴다.
- **Java 표준 라이브러리:** `Arrays.binarySearch(sortedArray, target)`도 같은 원리다.

**면접 기준:** "정렬된 배열에서 중간값과 비교해 탐색 범위를 절반씩 줄이므로 O(log N)입니다."

## 3. 정렬: 병합 정렬

**정의** — 병합 정렬은 배열을 절반으로 나누어 각각 정렬한 뒤 합치는 분할 정복 정렬이다. 시간은 항상 O(N log N)이고, 같은 값의 순서를 유지하는 안정 정렬이다.

**목적과 책임** — 큰 입력에서도 시간이 예측 가능하다. 버블 정렬처럼 O(N²)로 느리게 늘어나지 않는다.

**구별해야 할 개념 / 흔한 오해** — 퀵 정렬의 평균은 O(N log N)이지만 최악은 O(N²)이다. 병합 정렬은 추가 배열 공간(O(N))이 필요하다.

**구현 (검증 완료):**

```java
static int[] mergeSort(int[] a) {
    if (a.length <= 1) return a;
    int mid = a.length / 2;
    int[] left = mergeSort(Arrays.copyOfRange(a, 0, mid));
    int[] right = mergeSort(Arrays.copyOfRange(a, mid, a.length));
    int[] out = new int[a.length];
    int i = 0, j = 0, k = 0;
    while (i < left.length && j < right.length)
        out[k++] = (left[i] <= right[j]) ? left[i++] : right[j++];   // <= 로 같은 값의 순서를 지킨다
    while (i < left.length) out[k++] = left[i++];
    while (j < right.length) out[k++] = right[j++];
    return out;
}
```

- **확인:** `{5, 2, 9, 1, 5, 6}`을 정렬하면 `{1, 2, 5, 5, 6, 9}`이고, `Arrays.sort`와 결과가 같다.
- **실무 참고:** `Arrays.sort`는 기본형 배열에는 듀얼 피벗 퀵 정렬을, 객체 배열에는 안정 정렬인 TimSort를 쓴다.

**면접 기준:** "분할 정복으로 나눈 뒤 합치며 정렬하므로 항상 O(N log N)이고 안정 정렬입니다. 추가 공간이 필요합니다."

## 4. 그래프: BFS와 DFS

**정의** — 그래프는 정점(노드)과 간선으로 이루어진 구조다. BFS(너비 우선 탐색)는 큐로 가까운 정점부터 방문하고, DFS(깊이 우선 탐색)는 한 방향으로 끝까지 들어간 뒤 돌아온다.

**목적과 책임** — BFS는 가중치가 없을 때 최단 거리를 준다. DFS는 연결 여부, 경로 존재, 순서 탐색에 쓴다.

**구별해야 할 개념 / 흔한 오해** — BFS는 큐, DFS는 스택(또는 재귀)을 쓴다. DFS가 항상 최단 경로를 주는 것은 아니다.

**구현 (검증 완료):**

```java
// BFS: 인접 리스트로 표현한 그래프에서 시작점부터 각 정점까지 최소 간선 수
static int[] bfs(List<List<Integer>> graph, int start) {
    int[] dist = new int[graph.size()];
    Arrays.fill(dist, -1);
    Deque<Integer> queue = new ArrayDeque<>();
    dist[start] = 0;
    queue.add(start);
    while (!queue.isEmpty()) {
        int cur = queue.poll();
        for (int next : graph.get(cur)) {
            if (dist[next] == -1) {
                dist[next] = dist[cur] + 1;
                queue.add(next);
            }
        }
    }
    return dist;
}

// DFS (재귀): 방문 순서를 기록
static void dfs(List<List<Integer>> graph, int cur, boolean[] visited, List<Integer> order) {
    visited[cur] = true;
    order.add(cur);
    for (int next : graph.get(cur)) if (!visited[next]) dfs(graph, next, visited, order);
}
```

- **확인:** 간선 0-1, 0-2, 1-3, 2-3, 3-4에서 BFS로 0에서 4까지 거리는 3, 0에서 3까지 거리는 2다.
- **시간:** 정점 V, 간선 E일 때 O(V + E).

**면접 기준:** "BFS는 큐로 가까운 정점부터 방문해 가중치 없는 그래프의 최단 거리를 구하고, DFS는 스택이나 재귀로 깊이 들어갑니다. 둘 다 O(V + E)입니다."

## 5. 최단 경로: 다익스트라

**정의** — 간선마다 가중치가 있을 때, 시작점에서 각 정점까지의 최단 거리를 구한다. 아직 확정되지 않은 정점 중 거리가 가장 짧은 것을 우선순위 큐에서 꺼내 확정한다.

**구별해야 할 개념 / 흔한 오해** — 다익스트라는 **가중치가 0 이상**일 때만 정확하다. 음수 간선이 있으면 벨만-포드 같은 다른 알고리즘을 쓴다.

**구현 (검증 완료):**

```java
// edges[i] = {from, to, weight}, 가중치는 0 이상
static long[] dijkstra(int n, int[][] edges, int start) {
    List<List<int[]>> g = new ArrayList<>();
    for (int i = 0; i < n; i++) g.add(new ArrayList<>());
    for (int[] e : edges) g.get(e[0]).add(new int[]{e[1], e[2]});
    long[] dist = new long[n];
    Arrays.fill(dist, Long.MAX_VALUE);
    dist[start] = 0;
    PriorityQueue<long[]> pq = new PriorityQueue<>(Comparator.comparingLong(x -> x[0]));
    pq.add(new long[]{0, start});
    while (!pq.isEmpty()) {
        long[] top = pq.poll();
        long d = top[0];
        int u = (int) top[1];
        if (d > dist[u]) continue;          // 이미 더 짧은 거리로 처리된 정점은 건너뛴다
        for (int[] e : g.get(u)) {
            long nd = d + e[1];
            if (nd < dist[e[0]]) { dist[e[0]] = nd; pq.add(new long[]{nd, e[0]}); }
        }
    }
    return dist;
}
```

- **확인:** 0→1 (4), 0→2 (1), 2→1 (2), 1→3 (1), 2→3 (5)에서 0에서 1까지 최단 거리는 3(0→2→1), 0에서 3까지는 4(0→2→1→3)다.
- **시간:** O((V + E) log V) (우선순위 큐 사용).

**면접 기준:** "가장 가까운 미확정 정점을 우선순위 큐에서 꺼내 확정하는 방식입니다. 음수 간선은 처리하지 못합니다."

## 6. 동적 계획법 (DP): 메모이제이션

**정의** — 큰 문제를 작은 문제로 나누고, 작은 문제의 답을 저장해 두었다가 재사용하는 방법이다. 같은 계산을 반복하지 않게 한다.

**구별해야 할 개념 / 흔한 오해** — DP는 재귀와 같지 않다. 재귀에 저장(메모)을 더해야 DP가 된다. 저장하지 않은 재귀는 같은 계산을 지수 번 반복할 수 있다.

**구현 (검증 완료): 계단 오르기 (1칸 또는 2칸씩)**

```java
// n계단을 오르는 방법의 수. memo[i]는 i계단의 답을 저장한다.
static long climb(int n, long[] memo) {
    if (n <= 1) return 1;
    if (memo[n] != 0) return memo[n];
    return memo[n] = climb(n - 1, memo) + climb(n - 2, memo);
}
```

- **확인:** 5계단은 8가지, 50계단은 20365011074가지다. 저장하지 않으면 50계단은 사실상 끝나지 않는다.
- **점화식:** `dp[n] = dp[n-1] + dp[n-2]`. 이것은 피보나치 수열과 같다.

**면접 기준:** "작은 문제의 답을 저장해 재사용하는 방법입니다. 점화식을 세우고 저장하면 중복 계산이 사라집니다."

## 7. 자료구조와의 연결

- **HashMap:** 조회·삽입·삭제 평균 O(1). 중복 검사와 빈도 세기에 쓴다.
- **ArrayDeque:** 큐와 스택으로 쓴다. BFS의 큐가 여기에 해당한다.
- **PriorityQueue:** 가장 작은 값을 빠르게 꺼낸다. 다익스트라에서 쓴다.
- **연결:** 자료구조는 데이터를 담는 그릇이고, 알고리즘은 그 그릇으로 문제를 푸는 절차다.

---

## 8. 코딩테스트에서 자주 하는 실수

- 입력 범위를 확인하지 않고 O(N²)로 짠다. N이 10^5인지 먼저 본다.
- 이진 탐색의 경계(lo, hi)를 잘못 바꿔서 무한 루프에 빠진다.
- BFS에서 방문 표시를 큐에서 꺼낼 때 하면 같은 정점이 여러 번 들어간다. **넣을 때** 표시한다.
- 다익스트라에 음수 간선을 넣는다.
- 재귀가 깊어지면 StackOverflowError가 난다. 깊이가 크면 반복문으로 바꾼다.

## 8. 이산수학 기초 (논리, 집합, 그래프)

- **논리:** 참과 거짓으로 조건을 다룬다. `AND`, `OR`, `NOT`. 조건문과 검색 조건이 모두 논리다. 드 모르간 법칙: `!(A && B) = !A || !B`.
- **집합:** 원소의 모임. 합집합, 교집합, 차집합. 자바의 `Set`과 `retainAll` 같은 연산이 집합 연산이다.
- **그래프:** 정점과 간선. 방향이 있거나 없고, 가중치가 있거나 없다. 이 장의 BFS, DFS, 다익스트라가 그래프 알고리즘이다.
- **왜 필요한가:** 조건을 정확히 쓰면 코딩테스트에서 경계 실수가 줄고, 그래프 문제를 정점과 간선으로 바꿔 생각할 수 있다.
- **확인 과제:** 두 집합 `{1,2,3}`과 `{2,3,4}`의 교집합과 합집합을 `Set`으로 구한다.
