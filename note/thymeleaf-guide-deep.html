1. 타임리프란 무엇인가

타임리프(Thymeleaf)는 Java 웹 프로젝트에서 HTML을 만들 때 쓰는 서버 사이드 템플릿 엔진입니다.

1-1. 핵심 특징

특징설명
내추럴 템플릿HTML 파일 그대로 브라우저에서 열어도 화면이 깨지지 않습니다. 디자이너와 개발자가 같은 파일로 작업할 수 있습니다.
속성 기반 문법태그 안에 th: 속성을 붙이는 방식이라 HTML 구조를 해치지 않습니다.
Spring과 결합Spring MVC의 Model에 담긴 데이터를 그대로 꺼내 씁니다.
자동 이스케이프th:text는 HTML 기호를 자동으로 바꿔 XSS 공격을 막습니다.

1-2. JSP와 비교

구분JSP타임리프
문법 형태<% %>, <c:forEach> 같은 태그HTML 속성 th:each
파일만 열면화면이 깨지거나 코드가 그대로 보임샘플 글자가 보여 디자인 확인 가능
실행 환경서블릿 컨테이너 (Tomcat)Spring Boot 내장 엔진으로 실행

2. 동작 원리 (서버 렌더링 흐름)

브라우저 요청부터 화면이 나오기까지의 순서를 이해하면 오류 원인을 빨리 찾을 수 있습니다.

  1. 브라우저가 /question/list 주소를 요청합니다.
  2. Spring이 QuestionController의 list() 메서드를 호출합니다.
  3. 메서드 안에서 DB 데이터를 조회해 List<Question>을 만듭니다.
  4. model.addAttribute("questionList", questionList)로 이름표를 붙여 Model에 담습니다.
  5. 메서드가 "question/list"라는 뷰 이름을 반환합니다.
  6. 타임리프가 templates/question/list.html을 읽고 th: 속성을 처리합니다.
  7. 처리가 끝난 순수 HTML이 브라우저에 전달됩니다.

2-1. 컨트롤러 예제

@Controller
@RequiredArgsConstructor
@RequestMapping("/question")
public class QuestionController {

    private final QuestionService questionService;

    @GetMapping("/list")
    public String list(Model model) {
        // 1) DB에서 질문 목록 조회
        List<Question> questionList = questionService.getList();

        // 2) Model에 "questionList"라는 이름으로 저장
        //    → 타임리프에서는 ${questionList}로 읽습니다.
        model.addAttribute("questionList", questionList);

        // 3) 뷰 이름 반환 → templates/question/list.html 을 렌더링
        return "question/list";
    }
}
💡 Model 이름과 템플릿의 ${이름}은 글자 하나까지 같아야 합니다. 대소문자가 다르면 값이 비어서 화면에 아무것도 나오지 않습니다.

3. 프로젝트 준비와 기본 설정

Spring Boot에서 타임리프를 쓰려면 의존성과 파일 위치만 맞으면 됩니다.

3-1. Gradle 의존성

dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-web'
    implementation 'org.springframework.boot:spring-boot-starter-thymeleaf'
}

3-2. Maven 의존성

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-thymeleaf</artifactId>
</dependency>

3-3. 폴더 구조

src/main/resources/
 ├─ templates/            ← 타임리프 HTML 파일 위치
 │   ├─ question/
 │   │   ├─ list.html
 │   │   └─ detail.html
 │   └─ fragments/
 │       └─ header.html   ← 공통 조각
 └─ static/               ← css, js, 이미지 (정적 파일)
     ├─ css/
     └─ js/

3-4. 뷰 이름 규칙

컨트롤러 반환값실제 파일 경로

"index"templates/index.html
⚠️ 반환값 앞에 /를 붙이거나 .html 확장자를 붙이지 마세요. 접두사와 접미사는 자동으로 붙습니다.

4. 표준 표현식

타임리프 표현식은 다섯 종류이며, 각각 꺼내 오는 대상이 다릅니다.

표현식형식꺼내 오는 대상예시
변수${...}Model에 담긴 값, 객체, 컬렉션${questionList}
선택 변수*{...}th:object로 지정한 객체의 필드*{subject}
메시지#{...}messages.properties의 다국어 글자#{main.title}
링크@{...}URL 경로 (컨텍스트 경로 자동 포함)@{/css/style.css}
조각~{...}다른 파일의 fragment~{fragments/header :: header}

4-1. ${} 변수 표현식 심화

객체의 필드에 접근하면 타임리프는 getter 메서드를 호출합니다.

템플릿 표기실제 Java 호출
${question.subject}question.getSubject()
${question.createDate}question.getCreateDate()
${questionList.size()}questionList.size()
${questionList[0]}questionList.get(0)
${map['key']}map.get("key")
💡 Lombok의 @Getter가 없으면 subject를 읽지 못해 오류가 납니다. 엔티티에는 반드시 getter가 있어야 합니다.

4-2. *{} 선택 변수 표현식

th:object로 객체를 한 번 지정하면, 그 안에서는 *{필드}만 쓸 수 있습니다.

❌ ${} 로 반복 작성

<form th:object="${question}">
  <input th:field="${question.subject}">
  <textarea th:field="${question.content}"></textarea>
</form>

✅ *{} 로 간결하게

<form th:object="${question}">
  <input th:field="*{subject}">
  <textarea th:field="*{content}"></textarea>
</form>

4-3. #{} 메시지 표현식

// src/main/resources/messages.properties
main.title=질문 게시판
main.empty=등록된 질문이 없습니다.

<!-- 템플릿 -->
<h1 th:text="#{main.title}">샘플 제목</h1>
<p th:text="#{main.empty}">샘플 문구</p>
💡 다국어 지원을 하려면 messages_en.properties, messages_ko.properties처럼 파일을 나눠 두면 됩니다.

4-4. ~{} 조각 표현식

<!-- templates/fragments/header.html 의 th:fragment="header" 를 가져옴 -->
<div th:replace="~{fragments/header :: header}"></div>

자세한 사용법은 13번 섹션에서 다룹니다.

5. 리터럴·연산자·문자열 연결

표현식 안에서 쓰는 값과 계산 방법입니다.

5-1. 리터럴 종류

종류예시주의점
문자열'안녕'작은따옴표를 씁니다. 큰따옴표는 HTML 속성 값과 충돌할 수 있습니다.
숫자10, 3.14그대로 씁니다.
불리언true, false소문자로 씁니다.
nullnull비교할 때 ${x == null}을 씁니다.
토큰on, off, any특정 기능에서만 쓰는 예약어입니다.

5-2. 문자열 연결 두 가지

방법 1: + 기호

<p th:text="'안녕하세요, ' + ${user.name} + '님'"></p>

따옴표 짝을 맞춰야 해서 실수하기 쉽습니다.

방법 2: | | 리터럴 치환 (권장)

<p th:text="|안녕하세요, ${user.name}님|"></p>

문장 안에 바로 ${}를 넣을 수 있어 가독성이 좋습니다.

5-3. 연산자 전체 목록

분류연산자예시설명
산술+ - * / %${price * 0.9}사칙연산과 나머지
비교> < >= <=${count > 0}속성 안에서는 아래 별칭 사용
비교 별칭gt lt ge le${count gt 0}HTML 속성 안에서 안전
같음== !=, eq ne${status == 'OK'}문자열은 equals처럼 동작
논리and or not, ! && ||${a and b}둘 다 쓸 수 있으나 속성 안에서는 and, or 권장
삼항조건 ? 참 : 거짓${ok ? 'Y' : 'N'}한 줄 분기
기본값?:${nick ?: '익명'}값이 null이면 오른쪽 값
안전 탐색?.${user?.address?.city}중간에 null이 있어도 오류 없음
무(無) 연산_th:text="${x} ?: _"값이 없을 때 원래 샘플 글자 유지
⚠️ <는 HTML 태그 시작 기호와 겹칩니다. 속성 안에서 <를 쓰면 파싱 오류가 날 수 있으니 lt로 바꿔 쓰세요.

6. 텍스트 출력 th:text / th:utext

태그 안의 글자를 값으로 바꿉니다. 보안과 직결되는 중요한 속성입니다.

6-1. 차이점 비교

속성처리 방식예: 값이 <b>굵게</b>일 때보안
th:textHTML 기호를 이스케이프합니다.화면에 <b>굵게</b> 글자 그대로 보임✅ 안전
th:utextHTML로 해석합니다.화면에 굵게 보임⚠️ XSS 위험

6-2. 이스케이프 원리

원본 값          출력 시 바뀌는 형태
<        →   &lt;
>        →   &gt;
"       →   &quot;
&        →   &amp;

6-3. 악성 스크립트 예시

// 사용자가 제목에 이렇게 입력했다고 가정
// <script>alert('해킹!')</script>

<!-- th:text 사용: 스크립트가 글자로만 출력됨 (안전) -->
<p th:text="${question.subject}"></p>

<!-- th:utext 사용: 스크립트가 실제로 실행됨 (위험) -->
<p th:utext="${question.subject}"></p>
✅ 사용자가 입력한 값은 항상 th:text로 출력하세요. th:utext는 관리자가 직접 작성한 신뢰된 HTML 조각에만 씁니다.

7. 속성 설정 th:href, th:class, th:attr

HTML 속성 값을 데이터에 따라 바꿉니다. 원래 속성 이름 앞에 th:를 붙이는 방식입니다.

7-1. 전용 속성 표

타임리프 속성바뀌는 HTML 속성예시
th:hrefhrefth:href="@{/home}"
th:srcsrcth:src="@{/img/logo.png}"
th:actionactionth:action="@{/question/create}"
th:valuevalueth:value="${name}"
th:id, th:nameid, nameth:id="|q-${q.id}|"
th:classclass (덮어씀)th:class="${on} ? 'a' : 'b'"
th:classappendclass (추가)th:classappend="${urgent} ? 'red'"
th:stylestyleth:style="|color:${color}|"
th:checked, th:selected, th:disabled체크, 선택, 비활성th:checked="${agree}"

7-2. th:class와 th:classappend의 차이

th:class (덮어쓰기)

<button class="btn" th:class="${main} ? 'primary'">
결과: class="primary"   ← btn이 사라짐

th:classappend (추가)

<button class="btn" th:classappend="${main} ? 'primary'">
결과: class="btn primary"   ← btn 유지
💡 기존 클래스를 유지하고 싶을 때는 거의 항상 th:classappend를 쓰세요.

7-3. th:attr로 여러 속성 한 번에 설정

<!-- 쉼표로 구분 -->
<img th:attr="src=@{/img/a.png}, alt=${title}, width=200" />

<!-- data-* 속성 -->
<li th:attr="data-id=${item.id}, data-kind='notice'"></li>

7-4. 불리언 속성 주의

<!-- 값이 true면 checked="checked", false면 속성 자체가 사라짐 -->
<input type="checkbox" th:checked="${question.secret}">

8. 반복문 th:each와 상태 변수

리스트를 하나씩 꺼내 태그를 여러 번 만듭니다. 질문 목록 화면의 핵심 문법입니다.

8-1. 기본 형식

<tr th:each="question : ${questionList}">
    <td th:text="${question.subject}">질문제목</td>
    <td th:text="${question.createDate}">작성일</td>
</tr>
실행 과정 (질문이 3개인 경우)
  1. 1번째: question에 첫 번째 객체를 넣고 <tr> 하나를 만듭니다.
  2. 2번째: question에 두 번째 객체를 넣고 <tr>을 또 만듭니다.
  3. 3번째: 같은 방식으로 세 번째 <tr>을 만듭니다.
  4. 결과: 같은 모양의 행이 3개 나옵니다.

8-2. 상태 변수 (iterStat)

두 번째 변수를 적으면 반복 상태 정보를 함께 받을 수 있습니다. 변수 이름은 자유롭게 정합니다.

<tr th:each="q, stat : ${questionList}">
    <td th:text="${stat.count}">1</td>
    <td th:text="${q.subject}"></td>
</tr>
속성값예시 (3개 중)
index0부터 시작0, 1, 2
count1부터 시작1, 2, 3
size전체 개수3, 3, 3
current현재 객체question과 같음
even / odd짝수·홀수 행 여부odd: true, false, true
first / last첫 번째·마지막 여부first: true (1번째만)

8-3. 줄무늬 표 만들기 (실전 예)

<style>
  .striped { background: #f3f4f6; }
</style>
<tr th:each="q, stat : ${questionList}"
    th:classappend="${stat.odd} ? 'striped'">
    <td th:text="${stat.count}"></td>
    <td th:text="${q.subject}"></td>
</tr>

8-4. Map 반복

// 컨트롤러: model.addAttribute("scoreMap", map);  // Map<String, Integer>
<li th:each="entry : ${scoreMap}"
    th:text="|${entry.key} : ${entry.value}점|"></li>

8-5. 빈 리스트일 때 처리

<!-- 리스트가 비어 있으면 아래 행을 출력 -->
<tr th:if="${#lists.isEmpty(questionList)}">
    <td colspan="2">등록된 질문이 없습니다.</td>
</tr>
<tr th:each="question : ${questionList}">
    ...
</tr>
⚠️ 한 태그에 th:each와 th:if를 같이 쓰면 th:each가 먼저 실행됩니다. 그래서 각 항목마다 조건을 검사하게 됩니다. 빈 리스트 검사는 위처럼 별도 태그로 분리하는 것이 안전합니다.

9. 조건문 th:if, th:unless, th:switch

조건에 따라 태그를 보이거나 숨깁니다.

9-1. th:if와 th:unless

<p th:if="${questionList.size() gt 0}">질문이 있습니다.</p>
<p th:unless="${questionList.size() gt 0}">등록된 질문이 없습니다.</p>

9-2. 거짓으로 취급되는 값

값th:if 결과
true참
false, null거짓
0거짓
"" (빈 문자열)거짓
빈 리스트, 빈 Map거짓
그 밖의 모든 값참
💡 th:if="${question.content}"처럼 쓰면 내용이 비어 있는지 한 번에 확인할 수 있습니다.

9-3. 권한별 메뉴 예시

<!-- 로그인한 사용자만 글쓰기 버튼 표시 -->
<a th:if="${session.loginUser != null}" th:href="@{/question/create}">질문 등록</a>

<!-- 로그인하지 않은 사용자에게 로그인 버튼 표시 -->
<a th:unless="${session.loginUser != null}" th:href="@{/user/login}">로그인</a>

9-4. th:switch / th:case

<div th:switch="${question.status}">
    <span th:case="'OPEN'">답변 대기</span>
    <span th:case="'CLOSED'">답변 완료</span>
    <span th:case="*">알 수 없음</span>   <!-- 기본값 -->
</div>
⚠️ th:switch의 부모 태그에는 th:switch만 있어야 하며, 자식은 반드시 th:case로 조건을 줘야 합니다.

10. URL 표현식 @{...} 심화

링크 주소를 만들 때 쓰며, 프로젝트 경로(context path)를 자동으로 붙여 줍니다.

10-1. 기본 형태

<a th:href="@{/question/list}">목록</a>
<!-- 결과: /question/list -->

<!-- 프로젝트 경로가 /myapp 이라면 결과: /myapp/question/list -->

10-2. 경로 변수 두 가지 방법

방법 A: 파이프 결합 (권장)

<a th:href="@{|/question/detail/${q.id}|}">
결과: /question/detail/5

방법 B: 중괄호 치환

<a th:href="@{/question/detail/{id}(id=${q.id})}">
결과: /question/detail/5

10-3. 쿼리 파라미터

<a th:href="@{/question/list(page=${page}, keyword=${kw})}">검색</a>
<!-- 결과 예: /question/list?page=2&keyword=java -->

10-4. 흔한 실수

⚠️ @{/detail/${id}}처럼 파이프 없이 쓰면 ${id}가 그대로 글자로 나옵니다. 반드시 |...|로 감싸거나 방법 B를 쓰세요.

10-5. 정적 리소스

11. 지역 변수 th:with

템플릿 안에서 임시 변수를 만듭니다. 같은 계산을 여러 번 하지 않으려고 씁니다.

<div th:with="total=${price * count}, label='합계'">
    <p th:text="|${label} : ${total}원|"></p>
</div>
💡 th:with로 만든 변수는 그 태그와 안쪽 자식 태그에서만 씁니다. 범위 밖에서는 사용할 수 없습니다.

12. 폼 처리 th:object, th:field, th:errors

입력 폼과 객체를 자동으로 연결합니다. 입력값이 객체에 담기고, 실패하면 입력값이 그대로 유지됩니다.

12-1. 등록 폼 전체 예제

// 컨트롤러
@GetMapping("/create")
public String createForm(Model model) {
    model.addAttribute("questionForm", new QuestionForm());
    return "question/form";
}

@PostMapping("/create")
public String create(@Valid QuestionForm questionForm,
                     BindingResult bindingResult) {
    if (bindingResult.hasErrors()) {
        return "question/form";   // 오류가 있으면 입력 화면으로 되돌림
    }
    questionService.create(questionForm.getSubject(), questionForm.getContent());
    return "redirect:/question/list";
}
<!-- templates/question/form.html -->
<form th:action="@{/question/create}" th:object="${questionForm}" method="post">
    <label>제목</label>
    <input type="text" th:field="*{subject}">
    <span th:if="${#fields.hasErrors('subject')}"
          th:errors="*{subject}" style="color:red;">오류</span>

    <label>내용</label>
    <textarea th:field="*{content}"></textarea>
    <span th:if="${#fields.hasErrors('content')}"
          th:errors="*{content}" style="color:red;">오류</span>

    <button type="submit">등록</button>
</form>

12-2. th:field가 해 주는 일

자동으로 채워지는 것설명
id필드 이름과 같은 값이 들어갑니다.
name컨트롤러의 필드 이름과 맞춰집니다. 제출할 때 이 이름으로 값이 전달됩니다.
value객체에 들어 있던 값을 넣습니다. 수정 화면에서 기존 값이 보입니다.

12-3. 검증 어노테이션과 메시지

public class QuestionForm {
    @NotBlank(message = "제목을 입력해 주세요.")
    @Size(max = 200, message = "제목은 200자 이하로 입력해 주세요.")
    private String subject;

    @NotBlank(message = "내용을 입력해 주세요.")
    private String content;

    // getter, setter 생략
}
💡 @Valid를 쓰려면 spring-boot-starter-validation 의존성이 필요합니다.

13. 레이아웃 th:fragment, th:insert, th:replace

공통 헤더, 푸터, 메뉴를 한 번만 만들고 여러 페이지에서 가져다 씁니다.

13-1. 조각 정의

<!-- templates/fragments/header.html -->
<header th:fragment="header">
    <h1>질문 게시판</h1>
</header>

<!-- 인자를 받는 조각 -->
<nav th:fragment="menu(activeMenu)">
    <a th:classappend="${activeMenu == 'list'} ? 'on'"
       th:href="@{/question/list}">목록</a>
</nav>

13-2. insert와 replace 차이

th:insert

<div class="box" th:insert="~{fragments/header :: header}"></div>

결과:
<div class="box">
  <header>...</header>
</div>

자기 태그는 남고 안에 조각이 들어갑니다.

th:replace

<div class="box" th:replace="~{fragments/header :: header}"></div>

결과:
<header>...</header>

자기 태그가 조각으로 통째로 바뀝니다.

13-3. 레이아웃 적용 예

<!-- 페이지에서 조각 사용 -->
<body>
    <div th:replace="~{fragments/header :: header}"></div>
    <div th:replace="~{fragments/nav :: menu('list')}"></div>

    <main> 본문 </main>
</body>
💡 ~{파일경로 :: 조각이름}에서 :: 앞은 파일 경로, 뒤는 fragment 이름입니다. 같은 파일 안이면 ~{:: header}처럼 앞을 생략합니다.
⚠️ th:include는 구버전 방식이며 Thymeleaf 3.0부터 권장되지 않습니다. th:insert 또는 th:replace를 쓰세요.

14. 유틸리티 객체 #dates, #temporals 등

#으로 시작하는 내장 객체로 날짜, 문자열, 숫자, 리스트를 다룹니다.

14-1. 객체 목록

객체대상 타입예시
#datesjava.util.Date${#dates.format(d, 'yyyy-MM-dd')}
#temporalsjava.time (LocalDateTime 등)${#temporals.format(d, 'yyyy-MM-dd HH:mm')}
#strings문자열${#strings.isEmpty(s)}, ${#strings.abbreviate(s, 10)}
#numbers숫자${#numbers.formatInteger(n, 3, 'COMMA')}
#listsList${#lists.isEmpty(list)}, ${#lists.size(list)}
#arrays배열${#arrays.length(arr)}
#fields폼 검증${#fields.hasErrors('subject')}
#objects모든 객체${#objects.nullSafe(obj, '기본값')}

14-2. 날짜 포맷 실전

<!-- LocalDateTime 이면 #temporals 사용 -->
<td th:text="${#temporals.format(question.createDate, 'yyyy-MM-dd HH:mm')}"></td>

<!-- java.util.Date 이면 #dates 사용 -->
<td th:text="${#dates.format(question.createDate, 'yyyy.MM.dd')}"></td>

14-3. 긴 제목 줄이기

<a th:text="${#strings.abbreviate(question.subject, 20)}"></a>
<!-- 20자를 넘으면 뒤를 ...으로 줄임 -->
⚠️ #temporals는 Java 8 날짜 API를 쓸 때 사용합니다. 엔티티 필드가 Date 타입이면 #dates를 씁니다. 타입과 맞지 않으면 오류가 납니다.

15. 기타 th:block, th:remove, th:inline

15-1. th:block (가상 태그)

화면에 남지 않는 빈 태그입니다. 여러 태그에 한꺼번에 반복이나 조건을 걸 때 씁니다.

<table>
  <th:block th:each="q : ${questionList}">
    <tr>
      <td th:text="${q.subject}"></td>
    </tr>
    <tr class="divider">
      <td colspan="2"></td>
    </tr>
  </th:block>
</table>
💡 th:block은 반복 대상이 되는 자식 태그 여러 개를 묶을 때 편리합니다.

15-2. th:remove

<!-- 렌더링할 때 이 태그 자체를 지움 (디자인 확인용 샘플을 숨김) -->
<tr th:remove="all">
    <td>샘플 행입니다. 실제 화면에는 나오지 않습니다.</td>
</tr>
값동작
all태그와 안의 내용을 모두 지웁니다.
body안의 내용만 지우고 태그는 남깁니다.
tag태그만 지우고 안의 내용은 남깁니다.
all-but-first첫 번째 자식만 남기고 나머지를 지웁니다.

15-3. th:inline (자바스크립트 값 사용)

<script th:inline="javascript">
    const subject = [[${question.subject}]];     // 문자열: 자동으로 따옴표 처리
    const count   = [[${questionList.size()}]];  // 숫자
    const list    = [[${questionList}]];         // 객체는 JSON으로 변환
</script>
⚠️ th:inline을 쓰면 값이 JavaScript 안에서 안전하게 이스케이프됩니다. 그래도 사용자 입력을 스크립트에 바로 넣을 때는 주의하세요.

16. 흔한 오류 진단과 해결

실제로 가장 많이 만나는 오류 상황을 증상별로 정리했습니다.

증상원인해결
화면에 ${questionList} 글자가 그대로 보임 타임리프가 처리하지 않음 (HTML 파일을 직접 열었거나 xmlns:th 누락) 서버를 통해 접속하고, 정상 실행 여부를 확인
목록이 비어 있음 Model 이름 불일치 또는 DB 조회 결과가 0건 addAttribute 이름과 ${} 이름을 맞추고, 컨트롤러에서 size 출력
Property or field 'subject' cannot be found getter가 없거나 객체가 null 엔티티에 getter 추가, 객체가 Model에 들어 있는지 확인
Exception evaluating SpringEL expression null 객체의 필드에 접근 ${question?.subject}처럼 안전 탐색 사용
링크가 /detail/${id}처럼 나옴 @{}에서 파이프 누락 @{|/detail/${id}|}로 수정
부분만 보이고 뒤가 잘림 HTML 속성 안에서 <, > 사용 gt, lt 별칭 사용
화면 디자인이 깨짐 th:class로 덮어써서 기존 클래스 소실 th:classappend로 변경
날짜가 2026-10-15T12:30:00처럼 길게 나옴 포맷 없이 출력 #temporals.format 적용
폼 입력값이 제출 후 사라짐 th:field 대신 name만 씀 th:field="*{필드}"로 변경
수정 화면에서 기존 값이 안 보임 th:object 또는 th:field 누락 컨트롤러에서 기존 객체를 Model에 담고 th:object로 연결

16-1. 디버깅 팁

<!-- 임시로 Model 값을 화면에 찍어 확인 -->
<pre th:text="${questionList}"></pre>

<!-- 개수 확인 -->
<p th:text="|목록 개수: ${#lists.size(questionList)}|"></p>
