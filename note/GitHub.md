지역 저장소를 원격 저장소에 연결하기
    로컬에 깃허브 레포지토리랑 연결할 디렉토리를 생성한다.
        git init (폴더명)
        cd (폴더명)
        파일생성

        git add (파일명)
        git commit -m "message"
        git log

    원격 저장소에 연결하기
        지역 저장소와 원격 저장소를 연결하려면 원격 저장소의 HTTPS 주소를 알아야 한다.
        git remote add origin (원격 저장소 HTTPS 주소)
        git remote -v
            원격 저장소에 제대로 연결됐는지 확인
        경로가 잘못 되었다면 수정할때
            git remote set-url origin (원격 저장소 HTTPS 주소)
        아예 경로를 삭제 하고 새로 add 하려면
            git remote remove origin

    지역 저장소와 원격 저장소 동기화 하기
        처음으로 원격 저장소에 커밋 올리기
            git branch -M main
                간혹 저장소의 main 브랜치 명이 main이 아닐때 main으로 맞춰주는 명령어
            git push -u origin main
                지역 저장소의 브랜치를 origin (원격저장소)의 main 브랜치로 푸시하는 명령어
                -u 옵션은 지역 저장소의 브랜치를 원격 저장소의 브랜치에 연결하기 위한것으로 처음에만 사용
                -u나 main 브랜치 이름 없이 간단히 푸시 가능

    원격 저장소에 파일 올리기 - git push
        파일 생성
        git add 파일명
        git commit -m "커밋 메세지"
        git push

    원격 저장소에서 커밋 내려받기 - git pull
        git pull origin main

깃허브에 SSH 원격 접속하기
    SSH 원격 접속이란
        Secure Shell의 줄임말
        보안이 강화된 안전한 방법으로 정보를 교환하는 방식
        기본적으로 프라이빗 키 (private key)와 퍼블릭 키 (public key)를 한 쌍으로 묶에서 컴퓨터를 인증한다.
    
    SSH키 생성하기
        터미널 창에서 홈 디렉토리로 이동
        ssh-keygen 입력
            - SSH키가 저장되는 디렉토리 경로가 표시되면서 파일이름을 입력하라고 뜬다.
        파일 이름은 입력하지말고 enter 누른다.
        그 후에 enter를 두번 더 누르면 SSH 접속을 위한 비밀번호가 만들어진다.
            화면에 몇가지 파일 경로가 표시되는데
                id_rsa = 프라이빗 키
                id_rsa.pub = 퍼블릭 키
        
        만들어진 키가 .ssh 디렉토리에 저장되어 있는지 확인
            cd .ssh
            ls -la

            그럼 폴더안에 id_rsa / id_rsa.pub 파일이 만들어져 있다.
    
    깃허브에 퍼블릭 키 전송하기
        SSH로 접속하려면 퍼블릭키를 깃허브에 올려야 한다.
            clip < ~/.ssh/id_rsa.pub 명령어로 내용을 복사 한다.
            깃 허브에 로그인 한다
            오른쪽 위 사용자 아이콘 클릭
            settings > Access 카테고리 > SSH and GPG keys 선택 > New SSH key 버튼 클릭
            title에 알아보기 쉽게 이름을 정하고 Key 항목에 복사한 퍼블릭 키 값을 붙여 넣는다.
            Add SSH key 를 클릭
    
    SSH 주소로 원격 저장소 연결하기
        연결할 원격 저장소의 SSH 주소를 복사한다.
        연결할 지역 저장소를 git 설정을 한다 (git init)
        git remote add origin 복사한 SSH주소
        git remote -v 로 확인

서로 다른 컴퓨터에서 원격 저장소 함께 사용하기
    원격 저장소 복제하기 - git clone
        원격 저장소에 담긴 내용 전체를 지역 저장소로 가져오는걸 복제한다, clone 또는 cloning 이라고 한다.
        클로닝을 할 디렉토리로 이동한다.
        git clone (원격 저장소 주소)
            - git clone (원격 저장소 주소) (디렉토리명)
                디렉토리명으로 지역 저장소 생성함과 동시에 클로닝
    
    A 지역 저장소에서 작업하고 올리기
        작업을 마친후 git add . / git commit -m "message" 하고
        git push 한다.
    
    B 지역 저장소에서 내려받아 작업하기
        작업을 시작하기전에 git pull 로 코드를 새로 내려 받고 작업을 시작한다.

원격 브랜치 정보 가져오기
    원격 main 브랜치
        작업을 시작하기전에 git status를 확인해서 지역 저장소와 원격 저장소의 버전을 체크해주는 버릇
            git status
    
    원격 브랜치 정보 가져오기 - git fetch
        페치(fetch)는 불러오다, 가져오다 라는 뜻
        git fetch 는 원격 저장소의 정보를 가져오는 명령어
        팀 작업을 할 때 다른 사람이 원격 저장소에 커밋한 내용을 무조건 내 지역 저장소에 합치지 않고 원격 저장소에서 수정한 내용을 가져와 훑어본 후에 필요할때만 내 지역 저장소에 합친다.

        하지만 git log 로 살펴보면 HEAD -> main 만 보이고, 원격 저장소의 origin/main은 보이지 않는다. 원격 저장소의 최신 커밋 정보를 가져왔지만 아직 지역 저장소에 합치지 않아서이다.

        git status로 원격 저장소와 내 로컬 저장소의 버전의 차이를 확인한다.
        git fetch로 원격 저장소의 정보를 가져온다
        git diff HEAD origin/main 으로 최신 커밋과 원격 저장소에서 가져온 커밋의 차이를 살펴본다.

        원격 저장소의 커밋을 확인하고 저장소에 합치려면 merge 명령어
        git merge origin/main

        다시 git log --oneline 살펴보면 새 커밋이 지역 저장소에 반영된 것을 확인 할 수 있다.

협업의 기본
    협업을 위한 저장소 만들기
        - 팀장이 새 repository를 생성한다. (README file 포함)
    
    저장소에 브랜치 만들기
        - repository에서 좌측 윗부분에 main이라고 써진 드롭다운 박스를 누른다.
        - 아래의 view all branches 를 누른다
        - 오른쪽 위의 New branch를 클릭한다.
    
    공동 작업자 추가하기
        - repository에서 settings를 클릭
        - access 카테고리에 Collaborators를 클릭
        - 화면 가운데의 Add people 클릭
        - 추가할 팀원 아이디를 검색한 후 클릭

    공동 작업자 초대 받기
        - 초대받은 팀원은 깃허브 오른쪽 프로필 메뉴 옆의 inbox에 초대 메세지가 들어와 있다.
        - Accept invitation 을 누른다.
    
    원격 저장소 복제하기
        - 공동 작업자가 깃허브에 접속하면 저장소 목록 협업 저장소도 함께 나타난다.
        - 협업 저장소의 주소를 복사해둔다.
        - git bash에서 
            git clone (원격 저장소 주소) (디렉토리명)
        - 지역 저장소 디렉토리로 이동후 git log로 커밋 확인
        - git config로 user name, user email 설정
            git config user.name "사용자 이름"
            git config user.email "메일 주소"
    
    원격 저장소에 커밋 푸시하기
        저장소를 복제했다면 브랜치도 모두 복제된다.
        사용하기로 약속한 브랜치를 사용한다.

        공동 작업을 할 때는 내가 커밋을 올리기 전, 누군가 원격 저장소에 푸시했을 수도 있으므로 항상 풀(pull)을 먼저 해야 한다.
            git pull
        
        사용하기로 한 브랜치로 이동한다
            git switch (사용하기로 한 브랜치 명)
            git add . / git add (스테이징 할 파일 명)
            git commit -m "커밋 메세지"
            git push -u origin (푸시 할 브랜치 명)
                처음 푸시할때는 -u 옵션을 쓴다.
                origin - 원격 저장소를 의미한다.
        
        풀 리퀘스트 보내기 및 병합하기
            공동 작업에서 각자 커밋을 푸시한 후 꼭 해야 할 작업이 있다.
            푸시한 커밋의 메세지를 남기는 것이다. <- 이것이 풀 리퀘스트 (pull request, PR)이다.
                내가 푸시했으니까 병합하라 라고 팀장에게 메세지 보내는 것
            
            브랜치에 푸시를 했기 때문에 main 브랜치에는 커밋이 병합되지 않았다.

            원격 저장소에 들어가서, 작업하기로 한 브랜치로 들어가면 상단에 contribute 라는 드롭다운 박스가 있다.
            그 아래에 Open Pull Request 라는 버튼이 있다. 클릭
            title을 입력하고, Add a description에 상세사항을 적는다.

        풀 리퀘스트 받기
            팀장의 원격 저장소의 상단에 Pull request 알람에 뱃지가 떠 있다.
            들어가면 받은 request가 있고, 타이틀을 클릭한다.
            메세지를 확인하고 아래의
                Merge Pull request 를 누른다.
                    Creat a merge commit (기본)
                    Squash and merge
                    Rebase and merge
                    중 선택 할 수도 있다.

README 파일 작성 / 마크다운 언어
    README - 프로젝트 설명, 확장자는 .md
    
    제목 - 텍스트 앞에 #을 붙인다. #과 텍스트 사이에는 여백이 있어야 한다.
        # 을 1~6개 붙여서 제목 글자 크기 지정
            1개가 제일 크고 6개가 제일 작다
            1, 2 개는 제목 아래에 가로줄이 그어진다.
    
    가로줄 추가
        * 이나 - 3개이상
            
    줄바꿈
        텍스트 단락에서 줄을 바꿀때는 엔터 두번

    순서 목록
        1, 2, 3... 처럼 번호를 붙인다.
    
    순서 없는 목록
        +나 - 또는 *을 붙여서 나열
        tab을 눌러 항목을 들여 쓰면 단계가 여러개로 이루어진 목록
    
    텍스트 꾸미기
        굵게: ** 또는 _ _ 로 감싸기
        기울이기: * 또는 _ 로 감싸기
        굵은 기울임체: *** 또는 _ _ _ 로 감싸기
        취소선: ~~ 로 감싸기
    
    소스 코드
        한 줄 코드
            텍스트 사이에 소스 코드 삽입시 백틱(`) 기호를 사용
        여러줄 코드
            소스를 백틱 3개 (```)로 감싼다.
    
    링크
        <주소> : 링크 주소가 그대로 화면에 나타난다.
        [텍스트](주소) : 링크 텍스트만 나타난다.
        [텍스트](주소, "부가 설명") : 링크 텍스트 위로 커서를 올리면 부가 설명이 말풍선 형태로 나타난다.

IDE로 Git, GitHub 다루기
    버전 관리를 편리하게 해주는 프로그램
        - 소스트리 (SourceTree)
        - 깃허브 데스크톱 (Github Desktop)
    
    컴퓨터에 지역 저장소를 연다.
    IDE로 지역 저장소를 연다.
    소스제어 아이콘을 누른다. (VSCode 는 사이드바, Cursor는 Explorer 위쪽)
    Initialize Repository (git init과 같다) 을 누른다.
    IDE에서 처음 깃을 사용하면 사용자 이름과 메일 주소 등을 등록해야 한다.
        IDE내의 터미널에서 
            git config --global user.name "사용자 이름"
            git config --global user.email "이메일 주소"
        (저장소마다 다른 계정을 사용한다면 --global을 빼고 입력한다.)
    새 파일을 만들어 저장을 한뒤 다시 소스제어 아이콘을 누르면 commit을 할 수 있다.

    GitHub 연결하기
        소스제어 아이콘을 누른 후 CHANGES 옆의 점 세개를 누르고 Remote > Add Remote 를 누른다.
        GitHub에서 연결할 원격 저장소의 HTTPS 주소를 복사해서 붙여넣는다.
    
    branch 만들기
        소스제어 아이콘을 누른 후 CHANGES 옆의 점 세개를 누르고 Branch > Create Branch... 를 한다.
        IDE 하단 왼쪽에 보면 main 혹은 새로만든 브랜치 이름이 뜬다. 이 브랜치 이름을 잘 확인하고 작업한다.
        브랜치를 바꿀땐 IDE 하단 왼쪽 아래의 브랜치명을 클릭한다. 그러면 pallete 영역에서 브랜치를 선택 할 수 있게 뜬다.
    
    branch 병합하기
        main 브랜치에서 다른 브랜치의 푸시 내용을 합치려면 IDE에서 main 브랜치로 바꾼 후, 소스제어 아이콘을 누른 후 CHANGES 옆의 점 세개를 누르고 Branch > merge... 를 누른다.
