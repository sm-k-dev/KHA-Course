🏆 일상생활 예시로 푸는 기출문제 10선

시뮬레이터에서 배운 원리를 넷플릭스, 배달의민족, 스타벅스 상황에 적용해 보세요.
머릿속으로 코드를 떠올린 뒤 [정답 및 한글 번역 보기]를 눌러보세요!

🟡 INNER JOIN
문제 1. 넷플릭스 시청자 찾기
USER (가입자 테이블)
아이디(UID)이름
N01김토스
N02이배민
WATCH (시청 테이블)
아이디(UID)영화제목
N01오징어게임
넷플릭스 가입자 중에서 영화를 1편이라도 시청한 사람의 이름과 영화제목을 조회하세요. (가입만 하고 안 본 사람은 출력 안 함)
SELECT U.이름, W.영화제목
FROM USER U
INNER JOIN WATCH W
ON U.UID = W.UID;
💁‍♂️ 한글 해석: USER 테이블과 WATCH 테이블 양쪽 모두에 존재하는 사람(INNER JOIN)만 아이디 기준으로 엮어!
[해설] 가입(USER)도 했고 시청(WATCH)도 한 확실한 짝꿍 행(Row)만 찾아야 하므로 INNER JOIN을 사용합니다.
🟡 INNER JOIN
문제 2. 쿠팡 로켓배송 상품과 주문 합치기
PRODUCT (상품)
상품번호(PID)상품명
P1맥북
P2햇반
ORDERS (주문)
주문번호상품번호(PID)
O_99P1
고객이 주문한 상품들의 주문번호, 상품번호, 상품명을 하나의 표로 합쳐서 조회하세요. (단, INNER JOIN 이라는 단어 대신 짧은 문법 사용)
SELECT O.주문번호, P.PID, P.상품명
FROM PRODUCT P
JOIN ORDERS O
ON P.PID = O.PID;
💁‍♂️ 한글 해석: PRODUCT 테이블과 ORDERS 테이블을 공통 상품번호(PID) 기준으로 확실한 짝꿍(JOIN)만 합쳐줘!
[해설] 실무와 시험 모두 INNER JOIN에서 INNER를 생략하고 그냥 JOIN이라고 써도 똑같이 작동합니다.
🔵 LEFT JOIN
문제 3. 올리브영 전 메뉴 판매 현황 (0건 포함)
MENU (메뉴)
번호(M_ID)메뉴명
1립스틱
2수분크림
SALE (판매)
주문번호번호(M_ID)
S11
가게의 모든 메뉴명과 팔린 주문번호를 조회하세요. 단, 아직 안 팔린 '수분크림'도 메뉴 목록에서 사라지면 안 됩니다. (메뉴를 왼쪽에 둘 것)
SELECT M.메뉴명, S.주문번호
FROM MENU M
LEFT OUTER JOIN SALE S
ON M.M_ID = S.M_ID;
💁‍♂️ 한글 해석: 왼쪽 MENU 테이블은 무조건 100% 살리고(LEFT JOIN), 오른쪽 SALE 테이블에서 짝을 찾아서 붙여! 없으면 빈칸(NULL) 줘!
[해설] 모든 메뉴(왼쪽)의 행(Row)이 100% 살아남아야 하므로 LEFT OUTER JOIN을 실행합니다. 안 팔린 상품의 주문번호 칸에 NULL 값이 생성됩니다.
🔵 LEFT JOIN
문제 4. 쿠팡 '휴면 계정' 찾기 (IS NULL)
USER (가입자)
아이디이름
U1제니
U2지수
ORDER (주문)
아이디상품명
U1아이폰
쿠팡에 가입만 해놓고 단 한 번도 주문을 하지 않은 사람의 이름만 쏙 골라내는 코드를 작성하세요.
SELECT U.이름
FROM USER U
LEFT JOIN ORDER O ON U.아이디 = O.아이디
WHERE O.상품명 IS NULL;
💁‍♂️ 한글 해석: USER 테이블을 100% 살려서 엮은 다음(LEFT JOIN), 오른쪽 테이블의 상품명이 빈칸(NULL)인 행만 걸러내!
[해설] 실무 최고 빈출 패턴! 전체 가입자를 보존(LEFT JOIN)한 뒤, 주문 내역이 없어서 열값이 빈칸이 된 행만 WHERE ~ IS NULL 조건으로 필터링하여 지수를 찾습니다.
🟢 RIGHT JOIN
문제 5. 교보문고 영수증 100% 보존
가입자(USER) 테이블을 왼쪽에, 영수증(RECEIPT) 테이블을 오른쪽에 둡니다. 회원/비회원 상관없이 가게에서 팔린 모든 영수증 내역이 누락 없이 100% 나오게 하세요.
SELECT U.이름, R.결제금액
FROM USER U
RIGHT OUTER JOIN RECEIPT R
ON U.아이디 = R.아이디;
💁‍♂️ 한글 해석: 오른쪽에 있는 RECEIPT 테이블의 모든 행은 무조건 100% 살려라(RIGHT JOIN)!
[해설] 기준이 오른쪽(판매영수증)이므로 RIGHT OUTER JOIN을 사용합니다. 비회원 영수증은 왼쪽 회원 이름 열값이 NULL로 채워집니다.
🟢 RIGHT JOIN
문제 6. 배민 '비회원 전화주문' 찾기
가입자(USER) 테이블을 왼쪽에, 주문(ORDER) 테이블을 오른쪽에 두고 조인합니다. 주문은 들어왔는데 비회원이 시킨 주문의 결제금액만 필터링하세요. (IS NULL 사용)
SELECT O.결제금액
FROM USER U
RIGHT JOIN ORDER O ON U.아이디 = O.아이디
WHERE U.아이디 IS NULL;
💁‍♂️ 한글 해석: ORDER 장부를 100% 살려 엮고(RIGHT JOIN), 왼쪽 USER 장부의 아이디 칸이 비어있는 행만 뽑아!
[해설] 전체 주문(오른쪽)을 기준으로 조인한 뒤, 왼쪽의 회원 데이터 칸이 텅 빈(NULL) 주문 건만 WHERE IS NULL로 골라냅니다.
🟣 FULL OUTER
문제 7. 요기요와 배민 데이터 합병
요기요 가입자 테이블과 배민 가입자 테이블이 있습니다. 양쪽 회사를 합병하면서, 요기요에만 가입한 사람과 배민에만 가입한 사람을 단 한 명도 누락시키지 않고 모두 합쳐서 거대한 통합 명부를 만드세요.
SELECT Y.이름, B.이름
FROM 요기요 Y
FULL OUTER JOIN 배민 B
ON Y.전화번호 = B.전화번호;
💁‍♂️ 한글 해석: 요기요 장부와 배민 장부를 양쪽 다 하나도 버리지 말고 몽땅 합쳐(FULL OUTER JOIN)!
[해설] 양쪽 테이블의 데이터를 버림 없이 전부 살려내야 할 때는 FULL OUTER JOIN을 사용합니다.
❌ CROSS JOIN
문제 8. 배스킨라빈스 조합 (카테시안 곱)
맛 (FLAVOR)
맛_이름
엄마는외계인
민트초코
슈팅스타
컵 (CONE)
컵_종류
일반콘
와플콘
맛 테이블(3행)과 컵 테이블(2행)을 아무 조건(ON) 없이 마구잡이로 조인(CROSS JOIN)하면 모든 경우의 수가 나옵니다. 이때 생성되는 총 조합(Row) 개수를 구하고 쿼리를 작성하세요.
-- 행 개수 정답: 6개 (3개 x 2개 = 6)
SELECT *
FROM FLAVOR
CROSS JOIN CONE;
💁‍♂️ 한글 해석: 맛 장부랑 컵 장부를 조건 따지지 말고 곱하기 해서 모든 경우의 수(CROSS JOIN)를 만들어버려!
[해설] CROSS JOIN(교차 조인)은 양쪽 테이블의 모든 경우의 수(3 곱하기 2 = 6)를 강제로 만들어냅니다. 이를 카테시안 곱(Cartesian Product)이라고 부릅니다.
💖 SELF JOIN
문제 9. 알바생의 사수(매니저) 이름 찾기
직원명부 (STAFF)
직원번호(S_ID)이름사수번호(MGR)
101매니저NULL
102알바제니101
직원명부 테이블 1개만을 이용하여, 알바생의 이름과 그 알바생을 담당하는 사수(매니저)의 이름을 한 줄에 나란히 조회하는 조인을 작성하세요.
SELECT 알바.이름, 사수.이름
FROM STAFF 알바
JOIN STAFF 사수
ON 알바.MGR = 사수.S_ID;
💁‍♂️ 한글 해석: STAFF 장부를 '알바 시점'과 '사수 시점' 2개로 복사해서 펼쳐놓고(SELF JOIN), 알바 행의 '사수번호'와 사수 행의 '직원번호'를 엮어!
[해설] 테이블을 가상으로 복사하여 분리한 뒤(SELF JOIN), 알바의 사수번호 열값(MGR)과 사수의 직원번호 열값(S_ID)을 매칭시킵니다.
💖 SELF JOIN
문제 10. 카카오톡 추천인 이벤트 (심화)
카카오 회원(USER) 테이블에는 가입자 이름(NAME)과 '추천인 아이디(REF_ID)' 열이 있습니다. 모든 가입자의 이름과 추천인 이름을 함께 조회하세요. 단, 추천인 없이 나 홀로 가입한 사람도 누락 없이 출력되어야 합니다.
SELECT 가입자.NAME, 추천인.NAME
FROM USER 가입자
LEFT JOIN USER 추천인
ON 가입자.REF_ID = 추천인.UID;
💁‍♂️ 한글 해석: USER 장부를 2개로 쪼개되, 왼쪽 '가입자 장부'의 모든 행(Row)은 100% 살려서(LEFT JOIN) 빈칸(NULL)으로 남겨둬!
[해설] 자신과 자신의 테이블을 조인(SELF JOIN)하면서도, 왼쪽의 전체 가입자를 한 명도 버리지 않고 살려야 하므로 LEFT JOIN을 써야 합니다. 추천인이 없는 사람은 추천인 이름 열값이 NULL이 됩니다.
