0. 시작하기 전에

💡 왜 이 장이 필요한가요?
낯선 단어가 나오면 뇌가 멈춥니다. 자주 나올 단어 5개를 먼저 생활 비유로 정리합니다. 외우지 마세요. 막힐 때 돌아와서 다시 읽으면 됩니다.
🍽️ 웹서버 = 식당의 홀 직원. 손님(브라우저)의 주문을 받습니다. 메뉴판(정적 HTML)처럼 이미 만들어진 것만 바로 줍니다.
👨‍🍳 서블릿(Servlet) = 주방의 요리사. 주문이 들어오면 그때그때 새로 요리(동적인 결과)를 만들어 내놓는 자바 클래스입니다.
🏢 톰캣(WAS) = 주방 전체. 요리사(서블릿)를 고용하고, 부르고, 퇴근시키는 관리자입니다. WAS는 "웹 애플리케이션 서버"의 줄임말입니다.
🧾 요청(Request) = 손님의 주문서. / 응답(Response) = 완성되어 나가는 요리 접시.
🗺️ 매핑(Mapping) = 메뉴 이름표. 손님은 "김치찌개 주세요"라고 말하지, 요리사의 본명을 부르지 않습니다. URL 이름과 서블릿 클래스를 연결하는 작업입니다.

준비물 확인

  1. 이클립스(Eclipse)가 설치되어 있어야 합니다. 자바 웹 개발용 편집 프로그램입니다.
  2. 톰캣(Tomcat) 9가 설치되어 있어야 합니다. 예시 경로: C:\tomcat9
  3. 자바(JDK)가 설치되어 있어야 합니다. 아래 명령으로 확인합니다.
java -version
✅ 이렇게 나오면 성공: "java version" 또는 "openjdk version"으로 시작하는 줄이 보이면 됩니다. 뒤의 숫자(버전)는 환경마다 다를 수 있습니다.
명령 프롬프트
C:\Users\me> java -version java version "17.0.10" 2024-01-16 LTS Java(TM) SE Runtime Environment (build 17.0.10+11)

※ 화면 예시입니다. 숫자·문구는 환경마다 다를 수 있습니다.

⚠️ "java는 내부 또는 외부 명령이 아닙니다"라고 나오면 — 자바가 설치되지 않았거나 경로(PATH) 설정이 안 된 상태입니다. JDK를 먼저 설치한 뒤 명령 프롬프트를 새로 열고 다시 실행하세요.

1. 서블릿이란? (5.1)

💡 왜 배우나요?
일반 HTML 파일은 "인쇄된 메뉴판"이라 내용이 항상 똑같습니다. 그런데 쇼핑몰의 할인 가격이나 로그인한 사람 이름은 매번 달라야 하죠. 이렇게 요청마다 다른 결과를 실시간으로 만들어 주는 자바 클래스가 서블릿입니다.

1-1. 한 문장 정의

서블릿(Servlet)은 서버에서 실행되며, 클라이언트의 요청에 따라 동적인 서비스를 제공하는 자바 클래스입니다.

1-2. 동작 과정 (식당 흐름)

① 클라이언트 (손님)→ ② 웹서버 (홀 직원)→ ③ 톰캣/WAS (주방)→ ④ 서블릿 실행 (요리)→ ⑤ 응답 생성 (접시 완성)→ ⑥ 클라이언트에게 전달
  1. 클라이언트(브라우저)가 웹서버에 요청을 보냅니다. — 손님이 주문합니다.
  2. 웹서버는 요청을 톰캣(WAS)에 전달합니다. — 홀 직원이 주문서를 주방에 넘깁니다.
  3. 톰캣은 해당 요청에 맞는 서블릿을 실행합니다. — 주방장이 담당 요리사를 부릅니다.
  4. 서블릿은 요청을 처리하고 응답 데이터를 생성합니다. — 요리사가 요리를 완성합니다.
  5. 생성된 응답이 클라이언트에게 전달됩니다. — 요리가 손님 테이블에 나갑니다.

1-3. 서블릿의 특징 6가지

특징쉬운 설명
서버 측에서 실행내 컴퓨터(브라우저)가 아니라 서버 컴퓨터에서 돌아갑니다.
동적인 웹 기능요청할 때마다 다른 결과를 만들 수 있습니다.
멀티 스레드 기반요리사 한 명이 여러 주문을 동시에 처리하는 방식입니다.
자바 언어 기반객체지향 특징을 그대로 가집니다.
서블릿 컨테이너(WAS)에서 실행혼자 실행 못 하고 반드시 주방(톰캣) 안에서만 일합니다.
플랫폼 독립적 + 보안 용이다양한 컨테이너에서 실행 가능하고, 보안 기능 구현이 쉽습니다.

🛠️ 미션 1 — 동작 순서 말로 설명하기

화면을 보지 않고, 종이에 손님 → 홀 직원 → 주방 → 요리사 → 접시 → 손님 순서를 쓰고, 각 단어 옆에 실제 용어(클라이언트/웹서버/WAS/서블릿/응답)를 적어 보세요. 다 썼으면 아래 버튼을 누르세요.

🧠 퀴즈 1 — 서블릿을 직접 실행하는 것은 누구일까요?

정답: ② 톰캣(WAS). 웹서버는 주문을 전달만 하고, 실제로 요리사(서블릿)를 부르는 것은 주방(WAS)입니다.

2. 서블릿 API 계층 구조 (5.2)

💡 왜 배우나요?
우리가 만들 서블릿 클래스는 맨땅에서 만드는 게 아니라, 이미 준비된 부모 클래스(HttpServlet)를 물려받아 만듭니다. 어떤 부모를 왜 물려받는지 알면 코드 첫 줄부터 이해됩니다.

2-1. 상속 계보

클래스 계층 구조
java.lang.Object (모든 자바 클래스의 조상) └─ javax.servlet.GenericServlet (프로토콜에 독립적인 기본 서블릿) └─ javax.servlet.http.HttpServlet (HTTP 전용 서블릿 ← 우리가 상속!)
📡 프로토콜 = 통신 약속(언어). HTTP는 웹 브라우저가 쓰는 표준 언어입니다. GenericServlet은 "어떤 언어든 가능한 통역사", HttpServlet은 "웹 언어(HTTP) 전문 통역사"입니다.

2-2. 구성 요소 4가지

구성 요소역할
Servlet 인터페이스javax.servlet 패키지. init(), service(), destroy() 등 서블릿의 필수 규칙을 선언합니다.
ServletConfig 인터페이스javax.servlet 패키지. getInitParameter(), getServletContext() 등 설정 관련 규칙을 선언합니다.
GenericServlet 클래스위 두 인터페이스를 구현한 일반 서블릿. 프로토콜에 따라 service()를 오버라이딩해서 씁니다.
HttpServlet 클래스GenericServlet을 상속. 웹 브라우저(HTTP) 전용. 요청 시 service()가 호출되며, 방식에 따라 doGet()/doPost()가 차례로 호출됩니다.

2-3. 요청이 들어오면 메서드가 호출되는 순서

클라이언트 요청→ public service() 호출→ protected service() 호출→ doGet() 또는 doPost() 호출

클라이언트 요청 시 public service() 메서드가 먼저 호출된 후 protected service() 메서드가 호출되고, 요청(request) 종류에 따라 doGet()·doPost() 같은 doXXX() 메서드가 호출됩니다.

메서드언제 호출되나
doGet(req, resp)GET 요청(주소창 입력, 링크 클릭) 처리
doPost(req, resp)POST 요청(회원가입 폼 전송 등) 처리
doDelete / doHead 등각 HTTP 방식에 맞춰 service()를 통해 호출

🛠️ 미션 2 — 계보 그리기

종이에 Object → GenericServlet → HttpServlet → 내가 만들 서블릿 4칸짜리 화살표 그림을 그려 보세요. 그리면서 "나는 HttpServlet을 상속받는다"라고 소리 내어 말해 보세요.

🧠 퀴즈 2 — 웹 브라우저용 서블릿을 만들 때 상속받는 클래스는?

정답: ③ HttpServlet. HTTP 요청/응답에 특화된 클래스이며, GET·POST 요청을 doGet()·doPost()로 나눠서 처리해 줍니다.

3. 서블릿 생명주기 (5.3)

💡 왜 배우나요?
요리사(서블릿)에게도 출근 → 근무 → 퇴근이 있습니다. 어떤 메서드가 언제, 몇 번 호출되는지 알아야 4장 실습에서 콘솔에 찍히는 글자의 의미를 이해할 수 있습니다.

3-1. 생명주기 5단계

[1] 클래스 로드→ [2] 인스턴스 생성→ [3] init()→ [4] service() → doGet()/doPost()→ [5] destroy()
단계메서드호출 시점 · 횟수비유
초기화init()최초 요청 시 단 한 번만 실행됩니다. 초기화 작업을 합니다.첫 출근 날 조리복 갈아입기
작업 수행doGet() / doPost()클라이언트 요청이 있을 때마다 실행됩니다.주문 들어올 때마다 요리
종료destroy()서버 종료 또는 서블릿이 메모리에서 제거될 때 실행됩니다.폐점 정리 후 퇴근
⚠️ 중요: init()과 destroy()는 생략 가능하지만, doGet()·doPost() 같은 doXXX() 메서드는 반드시 구현해야 합니다. 요리를 못 하는 요리사는 의미가 없기 때문입니다.

🛠️ 미션 3 — 3초 안에 대답하기

스스로에게 질문하세요. "새로고침을 10번 누르면 init()은 몇 번, doGet()은 몇 번 호출될까?" 답(1번 / 10번)을 소리 내어 말했다면 완료 버튼을 누르세요.

🧠 퀴즈 3 — 최초 요청 시 딱 한 번만 실행되는 메서드는?

정답: ① init(). 첫 요청 때 한 번 초기화하고, 이후 요청은 doGet()/doPost()만 반복 호출됩니다. destroy()는 서버 종료 시 한 번입니다.

4. FirstServlet 실습 (5.4)

💡 이 장의 목표
이클립스에서 웹 프로젝트를 만들고, FirstServlet 클래스를 작성하고, 주소를 매핑해서, 브라우저로 직접 호출합니다. 아래 4단계 순서 그대로 갑니다.
① 서블릿 클래스 만들기→ ② 생명주기 메서드 구현→ ③ 서블릿 매핑 작업→ ④ 브라우저에서 매핑 이름으로 요청

4-1. 웹 프로젝트 만들기 (pro05)

  1. 이클립스 상단 New 아이콘 → Dynamic Web Project를 선택합니다.
  2. Project name에 아래 값을 입력하고 Next를 누릅니다. 
    pro05
  3. 경로 화면은 그대로 두고 Next를 누릅니다.
  4. Generate web.xml deployment descriptor 체크박스에 반드시 체크한 후 Finish를 누릅니다.
⚠️ web.xml 체크를 빼먹었다면 — 4-4단계에서 web.xml 파일이 없어서 막힙니다. 프로젝트 우클릭 → Java EE Tools → Generate Deployment Descriptor Stub을 누르면 나중에라도 만들 수 있습니다.

4-2. servlet-api.jar 등록 (클래스 패스 설정)

📦 servlet-api.jar = 서블릿 기능이 들어 있는 부품 상자. 톰캣이 제공하므로, 이클립스에게 "부품 상자 여기 있어"라고 위치를 알려줘야(클래스 패스 설정) HttpServlet을 쓸 수 있습니다.
  1. 프로젝트 이름(pro05) 우클릭 → Build Path → Configure Build Path... 선택.
  2. Libraries 탭 → Classpath 선택 → Add External JARs... 클릭.
  3. 톰캣 설치 폴더의 lib 안에 있는 servlet-api.jar를 선택합니다. 예시 경로: 
    C:\tomcat9\lib\servlet-api.jar
  4. Classpath 아래에 servlet-api.jar가 보이는지 확인 후 Apply and Close를 누릅니다.
✅ 이렇게 되면 성공: Libraries 화면의 Classpath 밑에 servlet-api.jar - C:\tomcat9\lib 한 줄이 표시됩니다.

4-3. FirstServlet 클래스 작성

  1. Java Resources 밑의 src 우클릭 → New → Package → 이름 입력 후 Finish. 
    sec01.ex01
  2. 만든 패키지 우클릭 → New → Class → Name에 FirstServlet 입력 후 Finish.
  3. 생성된 FirstServlet.java 내용을 전부 지우고 아래 코드를 붙여넣습니다. 
    package sec01.ex01;

import java.io.IOException;
import javax.servlet.ServletException;
import javax.servlet.http.HttpServlet;
import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;

// HttpServlet을 상속받아야 서블릿이 됩니다.
public class FirstServlet extends HttpServlet {

    @Override
    public void init() throws ServletException {
        // 최초 요청 시 단 한 번 실행됩니다.
        System.out.println("init 메서드 호출");
    }

    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp)
            throws ServletException, IOException {
        // 브라우저 요청이 올 때마다 실행됩니다.
        System.out.println("doGet 메서드 호출");
    }

    @Override
    public void destroy() {
        // 서버 종료 시 실행됩니다.
        System.out.println("destroy 메서드 호출");
    }
}
⚠️ 빨간 밑줄이 잔뜩 생기면 — 4-2의 servlet-api.jar 등록이 안 된 상태입니다. 4-2로 돌아가 다시 등록하세요. import 줄의 javax.servlet을 못 찾는 것이 원인입니다.

4-4. web.xml에 서블릿 매핑하기

클래스 이름 전체(sec01.ex01.FirstServlet)로 주소를 치면 길고, 클래스 구조가 노출되어 보안에도 좋지 않습니다. 그래서 짧은 매핑 이름(/first)을 붙입니다.

  1. WebContent → WEB-INF → web.xml을 엽니다.
  2. <web-app> 태그 안쪽의 기존 하위 태그를 지우고 아래를 붙여넣습니다. 
    <servlet>
    <servlet-name>aaa</servlet-name>
    <servlet-class>sec01.ex01.FirstServlet</servlet-class>
</servlet>

<servlet-mapping>
    <servlet-name>aaa</servlet-name>
    <url-pattern>/first</url-pattern>
</servlet-mapping>
태그뜻
<servlet-class>실제로 실행할 서블릿 클래스(요리사 본명)
<url-pattern>브라우저에서 부를 이름표 /first (메뉴 이름)
<servlet-name>두 태그를 이어 주는 연결 고리. 양쪽 값이 반드시 동일(aaa)해야 합니다.
⚠️ 가장 흔한 사고: 태그 철자를 <sevlet>처럼 하나만 틀려도 톰캣 시작 시 콘솔에 빨간 오류가 쏟아지고 실행되지 않습니다. 대소문자까지 정확히 입력하고, 오류가 하나라도 있으면 원인을 고친 뒤 다시 실행해야 합니다.

4-5. 톰캣에 프로젝트 등록 후 실행

  1. 하단 Servers 탭에서 톰캣 서버 우클릭 → Add and Remove... 선택.
  2. 왼쪽에서 pro05 선택 → Add > 클릭 → Finish.
  3. 톰캣 서버를 시작(▶)합니다.
  4. 브라우저 주소창에 아래 주소를 입력합니다. (포트 번호는 환경마다 다를 수 있습니다) 
    http://localhost:8090/pro05/first

✅ 이렇게 나오면 성공: 이클립스 콘솔(Console) 창에 아래 두 줄이 출력됩니다. (브라우저 화면은 비어 있어도 정상입니다. 아직 화면 출력 코드를 안 넣었기 때문입니다.)

🧠 퀴즈 4 — /first는 web.xml의 어느 태그에 적었나요?

정답: ③ <url-pattern>. 브라우저에서 부르는 이름표입니다. <servlet-class>에는 실제 클래스 이름(sec01.ex01.FirstServlet)이 들어갑니다.

5. 서블릿 동작 과정 심화 (5.5)

💡 왜 배우나요?
"왜 두 번째 손님부터는 init이 안 찍힐까?" 그 비밀이 톰캣의 메모리 체크에 있습니다. 면접에도 자주 나오는 핵심입니다.

5-1. 첫 번째 손님 (클라이언트 1)

  1. 클라이언트 1이 브라우저로 /first를 요청합니다.
  2. 톰캣은 FirstServlet이 메모리에 로드되어 있는지 체크합니다.
  3. 최초 요청이라 없으므로 → FirstServlet 객체를 메모리에 로드하고 init()을 호출합니다.
  4. 요청 방식에 따라 doGet() 또는 doPost()가 호출되어 응답 값을 생성합니다.
  5. 생성한 응답 값을 클라이언트 1의 브라우저로 전송합니다.

5-2. 두 번째 손님 (클라이언트 2)

  1. 클라이언트 2가 같은 FirstServlet을 요청합니다.
  2. 톰캣이 메모리를 체크 → 이미 있음(YES) 확인.
  3. init()을 건너뛰고 바로 doGet()·doPost()를 호출해 응답합니다. 그래서 더 빠릅니다.
톰캣 내부 판단 흐름
요청 도착 → "FirstServlet 메모리에 있나?" ├─ NO → 메모리에 로드 → init() 호출 → doGet()/doPost() → 응답 └─ YES → (init 생략) 바로 doGet()/doPost() → 응답

🛠️ 미션 5 — 30초 설명 도전

"두 번째 요청부터 init()이 호출되지 않는 이유"를 메모리라는 단어를 넣어 30초 안에 설명해 보세요. (답 예: 톰캣이 메모리에 객체가 이미 있는지 확인하고, 있으면 재사용하기 때문)

🧠 퀴즈 5 — 클라이언트 2가 같은 서블릿을 요청하면?

정답: ②. 톰캣은 메모리에 이미 로드된 객체를 재사용합니다. 그래서 서블릿이 빠르고 효율적입니다.

6. 애너테이션을 이용한 서블릿 매핑 (5.6)

💡 왜 배우나요?
서블릿이 10개, 20개가 되면 web.xml이 복잡해집니다. 클래스 파일 바로 위에 이름표를 직접 붙이는 방법이 애너테이션 매핑입니다. 가독성이 훨씬 좋아집니다.
🏷️ 애너테이션(@) = 코드에 붙이는 포스트잇. @WebServlet("/이름")을 클래스 위에 붙이면 web.xml 없이 매핑이 끝납니다.

6-1. 사용 방법

@WebServlet("/서블릿매핑이름")   // 서블릿 클래스 선언 바로 위에 붙입니다.

6-2. ThirdServlet 만들기

  1. sec01.ex01 패키지 우클릭 → New → Servlet 선택. (Class가 아니라 Servlet입니다)
  2. Class name에 ThirdServlet 입력 후 Next.
  3. URL mappings에서 기본값(/ThirdServlet) 선택 → Edit... → 아래로 수정 후 OK → Next. 
    /third
  4. Constructors from superclass 체크 해제, init · destroy · doGet에 체크하고 Finish.
  5. 생성된 파일을 아래처럼 정리합니다. (serialVersionUID 줄은 사용하지 않으므로 삭제해도 됩니다) 
    package sec01.ex01;

import java.io.IOException;
import javax.servlet.ServletConfig;
import javax.servlet.ServletException;
import javax.servlet.annotation.WebServlet;
import javax.servlet.http.HttpServlet;
import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;

@WebServlet("/third")   // 이 한 줄이 web.xml 매핑을 대신합니다.
public class ThirdServlet extends HttpServlet {

    public void init(ServletConfig config) throws ServletException {
        System.out.println("ThirdServlet init 메서드 호출");
    }

    protected void doGet(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        System.out.println("ThirdServlet doGet 메서드 호출");
    }
}
  6. 톰캣을 중지했다가 재실행한 뒤 브라우저에서 요청합니다. 
    http://localhost:8090/pro05/third
✅ 이렇게 나오면 성공: 콘솔에 "ThirdServlet init 메서드 호출" → "ThirdServlet doGet 메서드 호출" 두 줄이 출력됩니다.
⚠️ 매핑 이름 중복 금지: 애너테이션에 이미 web.xml에서 쓴 이름(/first)을 또 쓰면 톰캣 시작 자체가 실패합니다(콘솔에 LifecycleException 오류). 애너테이션 매핑명은 다른 매핑명과 중복되면 안 됩니다. 이름을 /third처럼 고유하게 바꾸고 재실행하세요.
⚠️ 기억하세요: 애너테이션으로 만드는 서블릿 클래스도 반드시 HttpServlet을 상속받아야 합니다.

6-3. 두 방식 비교 정리

구분web.xml 방식애너테이션 방식
매핑 위치WEB-INF/web.xml 파일클래스 선언 바로 위 @WebServlet
장점매핑을 한 파일에서 모아 관리가독성 좋고 코드와 매핑이 한 곳에
주의점태그 철자·대소문자 오타매핑 이름 중복 금지

🛠️ 미션 6 — 최종 실습

위 순서대로 ThirdServlet을 직접 만들고, 콘솔에서 "ThirdServlet init/doGet 메서드 호출" 두 줄을 확인하세요. 확인했으면 완료를 누르세요. 여기까지 오셨으면 5장 전체를 실습으로 완주하신 겁니다. 🎉

🧠 퀴즈 6 — 애너테이션 매핑에서 절대 하면 안 되는 것은?

정답: ①. 매핑명이 중복되면 톰캣이 시작조차 못 합니다. ②와 ③은 오히려 반드시 해야 하는 일입니다.
