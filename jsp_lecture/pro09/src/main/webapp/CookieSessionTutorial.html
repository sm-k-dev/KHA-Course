STEP 2

쿠키(Cookie) — 정보를 "브라우저"에 맡긴다

쿠키 = 서버가 응답에 실어 보내는 이름=값 텍스트 조각. 브라우저는 이를 자기 컴퓨터에 저장했다가, 같은 서버로 가는 모든 요청에 자동으로 붙입니다. 봉투 속 Set-Cookie / Cookie 헤더가 실제로 어디에 적히는지 관찰하세요.

📨 HTTP 요청

서블릿 코드로 보면 (발급 / 읽기)

// [발급] 장면 3에서 서버가 실행한 코드
Cookie cookie = new Cookie("userId", "hong"); // 이름=값으로 생성
cookie.setMaxAge(60 * 60 * 24);              // 유효 시간(초 단위) = 24시간
response.addCookie(cookie);                  // 응답 헤더에 Set-Cookie: userId=hong 추가

// [읽기] 장면 6에서 서버가 실행한 코드
Cookie[] cookies = request.getCookies();     // 요청에 실려 온 쿠키 전부를 배열로
for (Cookie c : cookies) {
    if (c.getName().equals("userId")) {   // 이름이 userId인 쿠키를 찾아
        String userId = c.getValue();        // 값 "hong"을 꺼냄
    }
}
⚠️ 쿠키의 약점 — 쿠키는 사용자 컴퓨터에 저장되고, F12 개발자도구에서 누구나 보고 고칠 수 있습니다. userId=hong 을 userId=admin 으로 바꿔 보내는 조작도 가능합니다. → 비밀번호·회원 정보를 쿠키에 담으면 절대 안 됩니다. 해결책이 STEP 3의 세션입니다.
STEP 3

세션(Session) — 정보는 "서버 금고"에, 브라우저엔 열쇠만

정보 자체는 서버 메모리의 세션 저장소에 두고, 브라우저에는 그 칸을 여는 열쇠 번호(JSESSIONID)만 쿠키로 줍니다. 봉투에 회원 정보가 한 번도 실리지 않는 것을 확인하세요.

📨 HTTP 요청

서블릿 코드로 보면 (저장 / 사용 / 종료)

// [저장] 장면 3에서 서버가 실행한 코드
HttpSession session = request.getSession(); // 세션 없으면 새로 생성, 있으면 기존 것 반환
session.setAttribute("userId", "hong");   // 서버 금고에 저장 (브라우저로 안 나감!)
session.setAttribute("grade", "VIP");
// 이때 톰캣이 자동으로 응답에 Set-Cookie: JSESSIONID=A1B2C3 을 실어 준다

// [사용] 장면 6에서 서버가 실행한 코드
HttpSession s = request.getSession();
String userId = (String) s.getAttribute("userId"); // "hong" (Object 반환 → 형변환)

// [종료] 로그아웃 시
s.invalidate(); // 금고에서 이 사용자의 칸을 통째로 삭제
💡 한 줄 요약 — 쿠키는 내용물을 통째로 들고 다니고, 세션은 열쇠 번호만 들고 다닙니다. 내용물은 전부 서버 금고 안에 있습니다.

쿠키 vs 세션 — 한눈 비교 + 분류 연습

🛠️ 분류 연습 — 이 정보는 어디에 저장해야 할까?

1) "오늘 하루 이 팝업창 열지 않기" 체크 여부

✅ 쿠키 — 민감하지 않고, 브라우저를 껐다 켜도 하루 동안 유지되어야 하므로 setMaxAge를 지정한 쿠키가 적합합니다.

2) 로그인한 회원의 아이디와 등급 (로그인 상태 유지)

✅ 세션 — 회원 정보를 사용자 손에 두면 위조될 수 있습니다. 서버가 보관하고 브라우저에는 JSESSIONID만 줍니다.

3) 쇼핑몰 장바구니에 담긴 상품 목록

✅ 세션 — 목록은 크기가 크고(쿠키는 용량 제한이 작음) 가격 조작 위험도 있어 서버 쪽 세션이 적합합니다.

🧠 이해도 점검 퀴즈

Q1. 로그인 직후의 다음 요청에서 서버가 사용자를 못 알아보는 근본 이유는?

✅ HTTP는 무상태(Stateless)입니다. 무대 1의 장면 4에서 연결이 ✕ 끊기는 순간 서버는 전부 잊었습니다.

Q2. 세션 방식에서 브라우저 쿠키 보관함에 실제로 저장되는 것은?

✅ 무대 3에서 브라우저 서랍에 들어온 것은 🔑 JSESSIONID=A1B2C3 하나뿐이었습니다. 세션도 결국 이 쿠키 하나의 도움을 받습니다.

Q3. session.setAttribute("userId","hong") 의 "hong"이 저장되는 위치는?

✅ setAttribute의 값은 서버 메모리 금고(무대 3의 🗄️)에 저장됩니다. 쿠키와는 저장 위치 자체가 다릅니다.
핵심 정리 3줄
  1. HTTP는 무상태 — 응답 후 연결을 끊고 사용자를 잊으므로, 상태 유지 장치가 필요하다.
  2. 쿠키 = 정보를 브라우저에 저장, 매 요청에 자동 첨부(Cookie 헤더) — 편하지만 노출·수정 가능해 민감 정보 금지.
  3. 세션 = 정보는 서버 금고에, 브라우저엔 열쇠 JSESSIONID만 — 로그인 유지의 표준.
